# Модуль presence — «живой ритм Боба»

Ритм-слой «человеческого группового присутствия» (BOB-066) как единая вертикаль
чистой доменной логики: насколько Боб занимает эфир (доля голоса), как быстро он
по-человечески отвечает (естественная задержка) и как экономно ставит лайки
(бюджет реакций). Это про **ритм равного участника**, а не про то, ЧТО он говорит
(вердикт — в `conversation`) и не про его фоновую тягу заговорить первым (drive —
в `proactivity`). Все политики чистые: без I/O, без часов, без rng — время и
случайность инъектятся вызывающей стороной, поэтому вердикты детерминированы и
проверяются без LLM.

Это новый **вертикальный** bounded-context (срез BOB-066.2.3): бизнес-логика
ритма собрана в `src/bob/presence/`, а не размазана по слоям. Модуль охватывает
domain + adapters **внутри** одного контекста, поэтому в графе несёт не-слойный тег
`module-vertical` (правило `architecture-layers` его рёбра пропускает), а
внутреннюю и внешнюю дисциплину держат сгенерированные path-glob
`forbid_import`-правила в `.beadloom/_graph/rules.yml`
(`python scripts/gen_boundary_rules.py`).

## 🔴 Решение по принадлежности — отдельный контекст, не в proactivity

Доля эфира / естественная задержка / бюджет реакций **сознательно вынесены в
отдельный `presence/`**, а не сложены в `proactivity/`. Проактивность — это
*тяга заговорить первым* (urge из настроения/тоски/свежести рефлексии); presence —
это *ритм живого участника* уже идущего разговора. Разные ответственности → разные
контексты (когезия). Оба, впрочем, читают одно и то же окно активности per-chat:
проактив-тик может домножать своё окно на ту же долю голоса, чтобы не заговорить
поверх только что отправленной реплики.

## 🔴 Провязка за флагом `presence.rhythm` (OFF по умолчанию)

Эпик BOB-066 — блокер owner'а: команда в группу добавляется, только когда всё
готово ЦЕЛИКОМ. Поэтому вся **поведение-меняющая** провязка ритм-слоя идёт за
фичефлагом `presence.rhythm`, выключенным по умолчанию (консистентно с
`presence.reflective` из среза 2.2). Пока флаг выключен, чистые политики инертны —
продакшн-тайминг и частота неизменны. Политики импортируемы и покрыты тестами,
готовы к включению в срезе провязки.

## Спецификация

### Раскладка модуля

```
src/bob/presence/
  __init__.py             re-export публичной поверхности (политики + VO)
  outgoing_activity.py    OutgoingActivity — rolling-окно (bob_sent, total_seen,
                          distinct_senders) per chat_id + свойство `share`
  share_of_voice.py       ShareOfVoicePolicy.damping(activity, *, focused) — мягкий
                          потолок эфира; focused=True → 1.0 (INV-1), никогда не
                          немой (INV-3)
  natural_delay.py        NaturalDelayPolicy.floor_seconds(*, char_len, complexity,
                          urgency) — человеческий пол под скоростью ответа (INV-9)
  reaction_budget.py      ReactionBudget.allows(history, *, quality, now) — отдельный
                          бюджет лайков, одна реакция на серию
  rhythm_config.py        RhythmConfig — тюнинг-пороги всех трёх политик
  ports.py                OutgoingActivityStore (Protocol) — сейм чтения окна
  adapters/
    outgoing_activity_store.py  EpisodicOutgoingActivityStore над episodic_log
```

Application-коллабораторы ритма живут под `src/bob/application/runtime/`
(оркестрация — не домен): `DelayedTurn` (порядок «заметил → typing → await
max(пол, генерация) → reply») и `ShareOfVoiceGate` (потолок на p(ambient-барджа);
фокус минует; rng-draw инъектится из `TurnScope`).

### Инварианты (структурные гарантии)

- **INV-1 (фокусная гарантия):** `ShareOfVoicePolicy.damping(..., focused=True)`
  всегда `1.0` — прямое обращение потолок НЕ трогает. `ShareOfVoiceGate` пробрасывает
  `focused` в политику.
- **INV-3 (анти-скрипт):** потолок — мягкий вероятностный множитель `> 0` (пол
  `share_min_multiplier`), а решение — случайный draw, а не жёсткий счётчик. Боб
  притормаживается, но не немеет.
- **INV-9 (живой тайминг):** `NaturalDelayPolicy` даёт только ПОЛ; `DelayedTurn`
  ждёт `max(пол, реальная генерация)` — реальная генерация всегда выигрывает, если
  дольше, поэтому Боб никогда не медленнее себя настоящего, только не мгновенный.

### Доля эфира (Q3 RFC)

Целевая доля ≈ `1 / (distinct_senders + 1)` — «как ещё один человек в комнате». Пока
доля Боба ≤ цели — множитель `1.0` (барджит свободно); выше — плавно затухает с тем,
насколько он превысил справедливую долю, с полом над нулём. Больше участников →
уже цель → раньше торможение.

### P0-упрощение адаптера (честно)

В `episodic_log` пока НЕТ колонки `chat_id` (модель данных BOB-066 её не добавляет —
в P0 у Боба один активный чат), поэтому `EpisodicOutgoingActivityStore` принимает
`chat_id` ради контракта порта и форсайта BobNet, но окно считает над всем недавним
потоком. Когда будущая миграция сегментирует эпизоды по чату, сюда без изменений
домена добавится `WHERE chat_id = ?`.

### Форсайт BobNet

Окно участник-агностично: реплика человека и реплика Боба-копии считаются одинаково.
Потолок доли эфира применяется к ЛЮБОМУ ambient-участнику, включая ботов, — тот же
субстрат работает в топике BobNet без переделки ядра.
