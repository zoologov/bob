# RFC: BOB-090 — Боб не путается в чатах + канон GUPPI

> **Status:** Approved
> **Created:** 2026-08-05

---

## Что уже есть (разведка по коду, не догадки)

- `MessageReceived` несёт `chat_id`, `message_id`, `sender_id`, `sender_name`, `is_group`.
  🔴 НЕ несёт `topic_id` (`message_thread_id`) и `sender_username`.
- `visibility` эпизода (`public` / `owner_private`) уже выводится ИЗ КАНАЛА
  (`_turn_is_shared_scope`, BOB-082.1) и пишется в `episodic_log`. То есть грубое «где
  сказано» в памяти УЖЕ есть.
- 🔴 Но `visibility` используется только для гейта разглашения — **в промпт она не
  попадает**. Боб физически не может сказать «это было в личке»: он не видит источника.
- Ростер: `first_impression(sender_id, display_name)`, `person_relationship(...)`.
  🔴 `@username` не хранится нигде.
- Двухботовая инфраструктура готова (Срез A эпика BOB-087): `stream_bot` = бот GUPPI,
  `notifier_bot` = бот Боба; флаг `coder.stream_via_guppi` пока OFF.
- Ack запроса разрешения уходит без `message_thread_id` (`permission_channels.py:101`).

## Срез C — память помнит источник (фундамент, делаем первым)

Разбивается на две независимые по цене части.

**C1 — Боб ВИДИТ источник (дёшево, закрывает большую часть US-1).**
Провенанс-директива по образцу уже работающих `recalled_self_action_directive` (BOB-079) и
`recalled_work_directive` (BOB-087.C): чистая функция строит для промпта пометку, где был
сказан припомненный эпизод («в личке» / «в общем чате»). Источник берётся из существующей
`visibility` — миграции не требуется вовсе. Это и лечит эпизод 3092 («я объяснил в
группе», хотя писал в личку): Боб перестаёт домысливать место.

**C2 — точный адрес (нужен для B и для будущих мультигрупп).**
`MessageReceived` получает `topic_id`; эпизод — `origin_chat_id` + `origin_topic_id` через
guarded ALTER (образец: `claude_session_id`, BOB-087.D1). Старые записи остаются с `NULL`
— это честно означает «источник неизвестен», а не «публично».

🔴 **Не силосить.** Источник — метаданные и сигнал для суждения, НЕ фильтр recall. Сквозная
память (BOB-082) остаётся: Боб один разум. Ось «где сказано» ортогональна оси регистра
(«про что» — работа/личное, BOB-087.C); они живут рядом и не подменяют друг друга.

## Срез B — адресация и упоминания

**B1. Инструмент отправки.** Новая capability за флагом (default OFF), owner-only:
отправить текст в указанный чат/топик. Реализация — поверх существующего
`_CodingOwnerNotifier`/`RichMarkdownSender`, новый транспорт не нужен.

**B2. Куда именно — чистое ядро.** `resolve_destination(запрос, известные адреса)` →
адрес или «переспросить». По решению owner'а: «в группу» = известная группа; при
неоднозначности — вопрос, не угадывание. Mutation-цель.

**B3. Упоминания.** Хранить `@username` (новая колонка ростера, guarded ALTER; источник —
`from_user.username` в интейке). Чистая функция «имя → @username по ростеру»; если
username нет (в Telegram он необязателен) — обращаться по имени, а не выдумывать тег.
🔴 Урок эпизода 3088: Боб написал «@Норман», хотя ник `@NormanGri` — выдуманный тег хуже
отсутствующего.

**B4. Гейт переноса приватного.** По решению owner'а перенос определяется ПО МАТЕРИАЛУ:
если в материал ответа попал эпизод с `owner_private`, а адресат — публичный чат, нужно
согласие. Переиспользуем существующий `disclosure`-контур (BOB-082), а не строим второй.
Согласие — на этот ход, не «навсегда».

**B5. Фикс ack.** `tell_requester` шлёт с `message_thread_id` топика Боба.

## Срез D — канон GUPPI

**D1. Кто говорит — чистое ядро.** `speaker_for(вид сообщения)` → Боб или GUPPI.
Механика (сырой вывод инструментов, статусы, «не найдено», технические подтверждения) →
GUPPI. Всё, адресованное людям, суждения и реакции → Боб. Mutation-цель.
🔴 Разграничение, зафиксированное заранее: **запрос разрешения — это Боб**, а не GUPPI. Это
социальный акт (Боб защищает приватность owner'а и просит решения), а не механика.

**D2. Маршрутизация.** Существующая двухботовая пара; вердикт ядра выбирает бота.
Сообщения GUPPI **не пишутся в память как реплики Боба** — иначе его голос отравится
машинным тоном через recall (класс BOB-022/074/078).

**D3. Боб не отыгрывает GUPPI.** Промпт-запрет (усиление BOB-074): не пересказывать
действия GUPPI, не приписывать ему мнения, эмоции и реплики. По канону у GUPPI нет
личности; Боб может отдать ему команду, но ответ приходит ботом GUPPI.

**D4.** Включить `coder.stream_via_guppi`.

## Срез E — голос разрешений

`PRIVILEGE_JUDGE_SYSTEM_PROMPT` переводится на язык проекта, и главное — наружу идёт **не**
`what` от классификатора, а реплика Боба своими словами: кто просит, чего именно и почему
он спрашивает. Вердикт остаётся внутренним. Упоминание owner'а — через B3.

## Риски

| Риск | Митигация |
|---|---|
| Провенанс в промпте изменит тон/поведение (recall poisoning наоборот) | Флаг + живой смоук «Боб звучит как Боб»; BDD на наблюдаемое |
| Гейт переноса сломает обычные ответы в группе | Гейт срабатывает ТОЛЬКО когда в материале есть `owner_private`; регресс-тесты на обычный групповой ход |
| Реплики GUPPI попадут в память как голос Боба | Явный тест: сообщение GUPPI не создаёт эпизод-реплику |
| Инструмент отправки = новая поверхность атаки | owner-only + DM-only вход, флаг OFF, только по явной просьбе (BOB-076) |
| `@username` отсутствует у части людей | Фолбэк на имя; никогда не выдумывать тег |

## Тестовая стратегия

- Чистые ядра (`resolve_destination`, `speaker_for`, провенанс, резолв упоминаний) —
  mutation ≥85% с ЧЕСТНОЙ оценкой силы гейта (уроки эпика BOB-087: mutmut не мутирует
  модульные константы, не заглядывает в `isinstance`, не мутирует enum-вердикты).
- BDD через границу: «owner из лички просит написать в группу» → сообщение ушло В ГРУППУ,
  тег корректный, приватное не утекло.
- 🔴 Живой смоук с участием второго человека — тот же сценарий, что породил эпик.
- Все флаги OFF по умолчанию; OFF-путь байт-в-байт (доказывать равенством, не «похоже»).
- `beadloom lint --strict` только на ЧИСТОЙ БД (инкрементальный индекс не обновляет рёбра
  импортов и уже пропускал цикл — BDL-UX #142).

## Порядок

**C1 → C2 → B → D → E.** C1 закрывает большую часть US-1 почти бесплатно и не зависит ни
от чего. B опирается на C2 (чтобы понимать, что откуда). D и E независимы от B/C, но E
использует упоминания из B3, поэтому идёт последним.
