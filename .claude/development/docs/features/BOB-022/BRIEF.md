# BRIEF: BOB-022 — Фикс: Боб повторяется дословно

> **Status:** Approved
> **Created:** 2026-06-23
> **Type:** bug

---

## Проблема

Live (`test.txt`): Боб выдал **байт-в-байт одинаковый** длинный ответ `A` на **разные** входящие
сообщения (ходы 1, 2, 4 идентичны; ход 3 — другой, корректный). Боб сам «объяснил» это как «эхо /
консолидация памяти» — **конфабуляция**, не настоящая причина.

## Находки repro (2026-06-23)

- **Эхо-петля LLM — ОПРОВЕРГНУТА.** Repro-харнесс (`/tmp/repro_bob022.py`): при наличии прошлого ответа `A`
  в истории модель даёт **новый** контекстный ответ на другой ввод (и BUG, и CONTROL — свежие, разные).
  Значит дело **не в сэмплинге/копировании моделью**.
- **В нашем коде кэша/реплея НЕТ** (grep по `lru_cache|@cache|_cache|memoiz` пуст); `retry_with_backoff`
  при исчерпании **re-raise** (не отдаёт стейл); `handle()` зовёт `compose` каждый ход заново.
- Остаются **2 механических подозреваемых** (статикой не различить): **(a)** gateway подаёт
  устаревший/дублированный `event.text` (один и тот же ход обрабатывается повторно), либо **(b)** upstream
  **Qwen MaaS** кэширует ответы (учитывая прошлые сетевые блипы MaaS).

## ПРИЧИНА ПОДТВЕРЖДЕНА (живой DIAG-лог, 2026-06-23)

DIAG: mid=143 «Боб, как ты?» → hashA; mid=145 «Расскажи, чем увлечён» → hashB; mid=147 (тот же текст) →
**hashB (идентичен 145)**; сетевых ошибок ноль. Вывод: **(a) опровергнут** (разный ввод → разные ответы,
gateway корректен), **причина — детерминированное (greedy) декодирование на стороне Qwen MaaS**: мы НЕ
задаём `temperature` → одинаковый ввод даёт байт-в-байт одинаковый вывод.

## ФИКС (по подтверждённой причине)

1. Задать **`temperature`** (+ опц. `top_p`) на LLM-запросах: tier-1 (ответы) ~0.8 для живой вариативности,
   tier-0 (классификация/сентимент) пониже ~0.3 для стабильности. Конфиг `llm.tier0_temperature` /
   `llm.tier1_temperature` (или общий) с дефолтами; провайдер кладёт в payload.
2. **Анти-повтор-страж:** если свежий ответ ≈ дословно равен ПРОШЛОМУ ответу Боба — регенерировать
   (например, повысив температуру) ИЛИ лёгкая вариация. Защита в глубину.
3. Убрать/причесать временный DIAG-лог в `handle()`.

## План

1. **Диагностика живьём (текущий шаг):** врезан DIAG-лог в `handle()` (вход: `message_id`+текст; выход:
   `replyhash`+префикс). Owner шлёт в Telegram: X → другой Y → снова Y. По логу определяем:
   - разные сообщения приходят как **разный** `event.text`? (если нет → баг gateway/дедупа)
   - distinct ввод → **одинаковый** `replyhash`? (если да при разном тексте → upstream MaaS-кэш)
2. **Фикс по найденной причине:**
   - если gateway/дедуп — починить доставку/ключ события;
   - если MaaS-кэш — отключить кэш на нашей стороне (вариативность: `temperature`/`seed`/заголовок
     no-cache) + анти-повтор-страж (регенерация при дословном дубле прошлого ответа).
3. Тесты на фейках + регрессии (anti-bait/язык/выражение/память не сломать).
