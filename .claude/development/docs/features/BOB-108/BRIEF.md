# BRIEF — BOB-108: beadloom-гейт в CI не работал

> **Тип:** bug · **Приоритет:** P1 · **Беада:** `bob-j3x` · **Заведено:** 2026-08-18
> **Ветка:** `features/BOB-108`

---

## Проблема

CI по PR (BOB-095) показывал **зелёное**, при том что арх-границы и свежесть доков в нём
**не проверялись вовсе**. Шаг `Beadloom CI (clean index)` стоял под `continue-on-error: true`,
и внутри «зелёного» прогона висела аннотация `Process completed with exit code 139`.

Ровно класс §0.3: гейт умеет показывать зелёное, ничего не проверив. Хуже обычного — здесь
дыра была *задокументирована* в комментарии workflow как «окруженческая проблема, не логическая»,
то есть выглядела осознанным решением, а не долгом.

### Корень №1 — сегфолт (устраняется)

Падал **`beadloom reindex`**, а не `beadloom ci`: крах через ~1 с, ноль вывода.

Причина — рассогласование нативного ABI tree-sitter:

| Где | `tree-sitter` (ядро) | `tree-sitter-python` (грамматика) | Итог |
|---|---|---|---|
| локально (июньская установка) | 0.25.2 | 0.25.0 | exit 0 |
| раннер (свежий `uv tool install`) | **0.26.0** | 0.25.0 | **крах** |

`beadloom` требует `tree-sitter>=0.23` **без верхней границы**, поэтому свежая установка тянет
ядро 0.26 к граммати́кам, собранным под ABI 0.25. Отсюда и «локально работает, на раннере падает»:
дело не в раннере, а в дате установки.

Воспроизведено на **macOS** двумя изолированными venv на Python 3.12, один изменённый фактор:
- `tree-sitter==0.26.0` + грамматика 0.25.0 → **exit 138** (SIGBUS), ноль вывода;
- `tree-sitter==0.25.2` + грамматика 0.25.0 → **exit 0**, `Symbols: 1620`, `Imports: 1477`.

138 против 139 — это macOS SIGBUS против Linux SIGSEGV, тот же нативный крах на загрузке грамматики.
Платформа тут ни при чём, и докер для доказательства не потребовался.

### Корень №2 — под дырой лежало настоящее красное (НЕ устраняется, легализуется)

С рабочим `reindex` полный `beadloom ci` даёт **exit 1**:

```
lint PASS: 269 rules, 0 violations
sync-check PASS: 660 pair(s) fresh
docs-audit PASS: 2 mention(s) fresh
config-check FAIL: 3 drifted artifact(s)
doctor PASS: 13 check(s) clean
```

Дрейфуют `.claude/agents/dev.md`, `.claude/agents/review.md`, `.claude/commands/coordinator.md`.

🔴 **`config-check --fix` — не фикс.** В песочнице он даёт **42 удаления и 0 добавлений**:
- из `dev.md` и `review.md` сносится параграф **Cohesion-driven design** — ровно та стоячая
  методология, что зафиксирована в CLAUDE.md §0.2 («Cohesion (name the one responsibility)»);
- из `coordinator.md` — 32 строки про автономию и гигиену команд.

### 🔴 Первый диагноз этого красного был неверен — исправлено по факту

Сначала записалось: «это наши сознательные добавления, а проектного оверлея у beadloom нет».
Поймано **расхождением сред**: в песочнице `config-check` давал exit 1, а в рабочем дереве —
exit **0**, при побайтово одинаковых файлах (`cmp` по всем трём) и одной версии `2.1.0`.

Настоящая причина — **рассинхрон релиза beadloom**:

| Среда | Откуда beadloom | Cohesion в шаблоне | `config-check` |
|---|---|---|---|
| локально | из ИСХОДНИКА `/…/beadloom/src/beadloom` | есть | **0** |
| CI | `uv tool install beadloom` → PyPI 2.1.0 | нет | **1** (3 drifted) |

Cohesion-параграф и раздел автономии координатора вкодифицированы **в сами шаблоны ролей
beadloom** (BDL-059, коммиты `68e53ff` / `faa83bc` — есть в `main` beadloom). Опубликованный на
PyPI 2.1.0 их не содержит: версию после BDL-059 не бампили. То есть наши файлы не «дрейфовали от
композиции» — они соответствуют **новой** композиции, а CI сверяет их со **старой**.

🔴 Отсюда `--fix` не просто нежелателен, а **разрушителен**: он привёл бы файлы к устаревшим
шаблонам, снеся стоячую методологию §0.2.

Отдельный факт, тоже проверенный и тоже верный: проектного оверлея у beadloom **нет вовсе** —
`roles_templates_root()` возвращает каталог **внутри установленного пакета** (`CORE` +
`architecture/` + `stack/`), проектных фрагментов композиция не знает. Это не причина текущего
красного, но именно она объясняет, **почему методологию пришлось нести в сам beadloom**, а не
держать оверлеем у себя — и почему теперь гейт downstream-проекта зависит от неопубликованного
апстрим-изменения. Заведено отдельно (BDL-UX #152).

🔴 **Побочный урок:** локальная и CI-шная сборки beadloom — **разные**. «У меня зелено» про
beadloom-гейт ничего не доказывает про CI. Тот же силуэт, что и сегфолт: там расходилась **дата**
установки, здесь — **источник** установки.

## Решение

**1. Пин tree-sitter при установке beadloom в CI.** Не трогаем сам beadloom (upstream), а
закрываем верхнюю границу на нашей стороне: `uv tool install beadloom --with "tree-sitter<0.26"`.

**2. Гейт = `beadloom ci` минус `config-check`, пять проверок БЛОКИРУЮЩИЕ.** `continue-on-error`
снимается. Проверено на чистом индексе поимённо:

| Проверка | Exit |
|---|---|
| `reindex` (после `rm -f .beadloom/beadloom.db`) | 0 |
| `lint --strict` | 0 |
| `sync-check` | 0 |
| `docs audit` | 0 |
| `doctor` | 0 |
| `config-check` | **1** — по названной причине выше |

**3. `config-check` — отдельным информативным шагом** с причиной прямо в workflow, и оно не гасит
пять настоящих проверок.

🔴 **Первая редакция этого шага была нечестной, поймано живым прогоном PR #138.** Стояло
`continue-on-error: true`, и я записал «красное видно». Замер показал обратное: шаг получает
conclusion **`success`**, а его ошибки **нет в списке ANNOTATIONS** прогона — красное лежит только
внутри лога шага. То есть «информативный красный» был информативным лишь на бумаге; тот самый
класс §0.3, который чинит этот PR, пролез в саму починку. Исправлено: `continue-on-error` убран
совсем, шаг сам решает исход и печатает `::warning` — та попадает и в ANNOTATIONS, и в PR.

🔴 **Условие окончания сделано самообъявляющимся.** Оно не должно зависеть от того, вспомнит ли
кто-то про него через месяц. Когда `config-check` начнёт проходить (то есть выйдет релиз beadloom
с BDL-059), шаг напечатает аннотацию «условие окончания НАСТУПИЛО — верни шаг в блокирующий гейт».
Ветка `else` печатает ожидаемое красное вместе с запретом на `--fix`. Это НЕ «выключили неудобное»: причина названа, она
воспроизводима, заведена дефектом апстриму — и у исключения есть **условие окончания**: выйдет
релиз beadloom с BDL-059 → шаг возвращается в блокирующую часть. Проверяется одной командой
(`beadloom config-check` в CI даёт exit 0). Ровно урок #59: у отключённой проверки без срока
нет причин когда-либо включиться обратно.

**4. Находки записаны:** BOB-Issues (#59 — эта дыра, закрыта фиксом; #60 — обход границы формой
импорта, открыт) + два dogfood-пункта в `beadloom/.claude/development/BDL-UX-Issues.md`.

### Чего решение НЕ даёт (честная граница)

- CI по-прежнему **информативный**, а не required: branch protection на этом плане недоступна
  (403 Upgrade to Pro). Блокирующий здесь означает «валит прогон», а не «не даёт смёржить».
- `config-check` в CI не проверяется. Дрейф вендоренных файлов ловится глазами и pre-push хуком
  в основном репозитории — до релиза beadloom, содержащего BDL-059.
- Пункт §0.3 №2 в силе: `sync-check` не строит пар для `component`-узлов, и его `PASS: 660 pairs`
  не означает, что доки таких узлов свежие.

## Проверка кусачести (§0.3 п.5 + п.12)

Зелёный гейт бесполезен, если не краснеет на сломанном. Саботаж границы в песочнице-клоне:

**Прогон 1 (харнесс оказался кривой — записан честно).** Добавил
`from bob.capabilities.adapters import web_search_qwen` в `capabilities/usecases/code_rationale.py`.
`lint --strict` → **0 violations, exit 0**. Две причины разбирались по очереди:
1. `beadloom reindex` собирает индекс **из git-источников** — незакоммиченная правка ему не видна;
2. после коммита `Imports` вырос 1477→1478, то есть ребро проиндексировано, а правило всё равно
   молчало: глоб `to: "bob/capabilities/adapters/*"` требует хвостовой сегмент, а импорт **пакета**
   пишется ребром на `bob/capabilities/adapters` без него.

**Прогон 2 (каноничная форма).** `from bob.capabilities.adapters.web_search_qwen import QwenWebSearch`,
коммит, чистый индекс:

```
capabilities-usecases-no-adapters:forbid_import:error:src/bob/capabilities/usecases/code_rationale.py:197
lint --strict EXIT=1
```

Правило **названо**, файл и строка есть, exit 1. Отличие «покраснело» от «сломанный вызов»
(ERROR / no tests ran) доказано числами: 269 правил оценены в обоих прогонах.

🔴 Прогон 1 — не мусор, а **находка**: границу можно обойти пакетной формой импорта, и это
касается всех 269 сгенерированных правил, а не одного. Заведено BOB-Issues #60; фикс генератора
`scripts/gen_boundary_rules.py` — отдельная работа, в этот багфикс не входит.
