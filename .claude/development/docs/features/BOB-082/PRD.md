# PRD — Dev-канал в личке: лайв-стрим Claude Code + сквозная память

## Проблема / цель

Владелец хочет **полноценный dev-режим**: выделенный канал в **личке** (1:1 DM с Бобом), где идёт
**живой односторонний стрим** активности Claude Code CLI (tool-calls / вывод / прогресс), пока приватная
**супергруппа остаётся для companion-общения**. Сегодня поток кодера **сжат в ~12 нарратив-строк** (кап
BOB-076, чтобы не флудить группу) и льётся в групповой топик — полноценного лайв-стрима и приватного
dev-канала нет.

🔴 **Критично (north star): Боб — ОДИН разум, не два бота.** Память **сквозная** между личкой и группой;
никакой амнезии. При этом Боб ведёт себя **по-человечески с приватностью**: как человек, работающий в
нескольких чатах — публично в одном, тет-а-тет в другом; приватное по умолчанию держит при себе, **но
если собеседник привата (owner) попросит или согласится вынести приватное в публику — это нормально**.
Приватность по умолчанию, не тюрьма; раскрытие — **по согласию owner'а**.

## Цель среза

Выделенный **dev-канал в личке owner'а** с полным лайв-стримом Claude Code CLI (односторонним), при
сохранении: (1) сквозной памяти across личка+группа, (2) человечного scope раскрытия (приватность по
умолчанию + раскрытие по согласию owner'а), (3) существующих гейтов безопасности кодера.

## Сценарии (acceptance)

**S1 — Лайв-стрим в личку (главный таргет).**
- Owner в личке: `/code <задача>` (или dev-режим) → Боб в **личке** прогрессивно показывает живой поток
  CLI (что claude делает: правит файл X, гоняет тесты, открывает PR) — не сжатый нарратив, а живой
  «терминал» (катящееся сообщение + шаги).

**S2 — Группа остаётся чистой (companion).**
- Пока идёт dev-сессия в личке — групповой топик НЕ заливается стримом (максимум короткий указатель
  «работаю над кодом, детали в личке» или ничего). Companion-общение в группе не страдает.

**S3 — Сквозная память (нет амнезии).**
- В личке Боб помнит и обсуждения группы; в группе помнит и вашу личку. «Помнишь, Лиля вчера просила X?»
  (спрошено в личке) → Боб помнит. «Что мы с тобой в личке решили про Y?» (спрошено... в личке) → помнит.
  Один архив, recall сквозной в обе стороны.

**S4 — Приватность по умолчанию (человечно).**
- Боб НЕ выбалтывает owner-private из лички в группу **по своей инициативе** (там Лиля/Паша). В группе он
  это помнит, но сам не поднимает.

**S5 — Раскрытие по согласию owner'а (ключевой нюанс).**
- Owner (в группе или в личке): «Боб, расскажи ребятам, что мы в личке решили про ростер» → Боб
  **раскрывает** приватное в группе (owner — хозяин своего приватного контента, попросил/согласился).
- Owner соглашается на встречный вопрос («да, можешь рассказать») → тоже раскрывает.
- Но БЕЗ просьбы/согласия owner'а — не раскрывает (S4).

**S6 — Безопасность.**
- Dev-канал/стрим — **owner-only** (личка авторизована как owner-DM). Стрим **односторонний** (без stdin —
  двойной гейт мержа НЕ ослабляется, это T3.C⁺ следующим срезом). worktree-изоляция и PR-гейт не тронуты.

## Инварианты

- **INV-1 (Сквозная память).** Личка и группа — один разум; DM НЕ создаёт memory-сило (тот же
  `episodic_log`, без chat_id-фильтра recall); recall сквозной в обе стороны.
- **INV-2 (Scope + согласие).** Ходы в личке — `owner_private`; такт разглашения (BOB-066.2.6) не даёт им
  течь в группу **по инициативе Боба**; НО явная просьба/согласие owner'а раскрыть приватное публично —
  **разрешает** раскрытие (owner-consent override). Группа доступна Бобу в личке (owner видит всё).
- **INV-3 (Односторонность / гейты целы).** Стрим только показывает (без stdin-управления); двойной гейт
  (апрув плана + мерж) и worktree-изоляция сохранены; main неприкосновенен.
- **INV-4 (Owner-only канал).** Dev-канал/стрим доступен только owner'у; не расширяет authz для чужих.
- **INV-5 (Группа не флудится).** Полный firehose — только в личку; группа companion остаётся чистой.

## Не входит в scope (границы среза)

- **Двусторонний интерактив / stdin-мост** (steer claude из Telegram) — это **T3.C⁺**, следующий срез
  (ослабляет гейт → отдельный `coder.interactive`).
- **Мульти-репо / реплики / хаб** (T3.D–H) — не трогаем.
- **Self-proposed задачи** (Боб сам предлагает из Goal Engine / `bd ready`) — позже.
- **Переработка companion-поведения группы** — группа работает как сейчас.
