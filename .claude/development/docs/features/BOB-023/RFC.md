# RFC: BOB-023 — «Адресность» (кому адресовано + стоит ли отвечать)

> **Status:** Approved
> **Created:** 2026-06-23

---

## Обзор

Боб получает **адресность**: понимает, обращено ли сообщение к нему, к другому участнику или ни к кому, и
выбирает **ответить / молча лайкнуть / промолчать**. Чистый детектор `Addressivity` поверх сигналов
Telegram (reply-to, @mention, имя-обращение) + `Interlocutor` (BOB-019); политика отклика композится с
аппетитом (BOB-014 .2a) и REACT_ONLY (BOB-018). Новый исход `SILENT`. Всё «как характер»; фундамент BobNet
turn-taking; маркер theory-of-mind (линза §4.2).

## Технический контекст

### Ограничения
- Python 3.12+, DDD/Clean (детектор — чистый домен), инъекция Clock/seeded-RNG/портов, **TDD на фейках
  через `.venv/bin/pytest`** (uv run висит), `mypy --strict`, `ruff`, cov ≥80%.
- Не ломать: реактив/проактив, perception+гость-инвариант (BOB-019), аппетит (.2a), REACT_ONLY (BOB-018),
  тиринг, authz. Гостевой инвариант не трогаем.

### Затрагиваемые области
`application/runtime/events.py` (+reply-to/mention поля), `infrastructure/telegram/multibot.py` (извлечь из
aiogram Message reply_to/entities + id/username бота Боба), `domain/personality/addressivity.py` (new),
`application/usecases/handle_message.py` (политика + `SILENT`-исход), `domain/ports.py`, `app.py`, `config`.

---

## Предлагаемое решение

### (1) Пламбинг сигналов
- `MessageReceived` += `reply_to_sender_id: int | None` (от кого сообщение, на которое реплай; None если не
  реплай) и `mentions_bob: bool` (упомянут ли бот Боба в entities). Multibot при построении события берёт
  `message.reply_to_message.from_user.id` и сканит `message.entities` (mention/text_mention) против
  **id/username бота Боба** (из `BotRegistry`/`get_me`). Текст уже есть (для имя-обращения).

### (2) Детектор адресности (чистый домен)
- `domain/personality/addressivity.py`: `Addressivity ∈ {DIRECTED_TO_BOB, DIRECTED_TO_OTHER, AMBIENT}` +
  чистая `classify_addressivity(*, text, mentions_bob, reply_to_sender_id, bob_user_id, others_present)`:
  - **DIRECTED_TO_BOB:** `mentions_bob` ИЛИ reply на сообщение Боба (`reply_to_sender_id == bob_user_id`)
    ИЛИ имя-обращение в начале («Боб, …»).
  - **DIRECTED_TO_OTHER:** reply на сообщение другого человека ИЛИ обращение по имени к другому участнику.
  - **AMBIENT:** ни reply, ни mention, ни имя — общее/риторическое.

### (3) Политика отклика (поверх аппетита .2a + perception)
- **DIRECTED_TO_BOB →** вступает (далее решает engagement/REACT_ONLY как сейчас). **Никогда не SILENT** —
  прямое обращение не игнорируется.
- **DIRECTED_TO_OTHER →** по умолчанию `SILENT` — не встревает в чужой 1:1. **НО** если тема его **сильно
  интересует** (высокий `topic_interest`/аппетит .2a) — может **изредка вклиниться**, как человек, которого
  зацепил чужой разговор: **высокий порог** (выше, чем для ambient), редко, seeded, тактично («встряну на
  секунду — это любопытно…»). Не спамит, не перехватывает разговор.
- **AMBIENT →** зависит от того, **активны ли другие люди** в треде (`others_present`, из недавних
  отправителей истории): если по сути **1:1 с owner** → вступает (по умолчанию его пространство); если есть
  другие → чаще `SILENT` или **лайк-реакция** (REACT_ONLY), изредка вклинится при высоком интересе/аппетите
  (seeded, редко).

### (4) Новый исход `SILENT`
- В `handle_message` после perceive вычисляется `Addressivity` → политика. Ветка `SILENT`: ранний return
  без reply и без реакции (прочитал, не счёл стоящим). Лайк-реакция переиспользует REACT_ONLY-путь.

### Композиция
`handle_message`: perceive(BOB-019) → addressivity → политика → {SILENT | REACT_ONLY | engage(.2a→reply)}.
Гость-инвариант (BOB-019) сохраняется (гость по-прежнему без памяти/инструментов; адресность лишь добавляет
«молчать, если не к нему»).

## Guardrails (под тестами)
- **DIRECTED_TO_BOB всегда отвечается** (никогда SILENT) — прямое обращение к Бобу не теряется.
- **1:1 owner↔Bob:** ambient → вступает (не уходит в вечное молчание в личном пространстве Боба).
- **Явный 1:1 owner↔друг → по умолчанию не лезет**, но **интересная тема может втянуть** (редко, по
  интересу/аппетиту, тактично) — как живой человек, присоединяющийся к интересному разговору. Порог выше
  ambient; никогда не перехватывает чужой диалог.
- Детектор чист/детерминирован; политика seeded; «как характер». Гостевой инвариант BOB-019 цел.

## Рассмотренные альтернативы
- **Всегда отвечать (статус-кво)** — отвергнуто: встревает в чужие разговоры, не по-человечески.
- **LLM-классификатор адресности на каждый ход** — отвергнуто для v1: цена/недетерминизм; берём сигналы
  Telegram + эвристику (порт абстрактен → можно усилить позже).
- **Молчать по умолчанию** — отвергнуто: риск игнора owner; default в 1:1 — вступать.

## Риски
| Риск | Вер. | Влияние | Митигация |
|---|---|---|---|
| Боб молчит на прямое обращение | Low | High | DIRECTED_TO_BOB → всегда ответ; тест-инвариант |
| Боб встревает в 1:1 с другом | Med | Med | reply/обращение к другому → SILENT; тесты |
| Ложный «ambient→silent» в 1:1 с owner | Med | Med | others_present-гейт: 1:1 → вступать |
| @mention/reply не извлекаются | Low | Med | Контрактные тесты на multibot-парсинг; фоллбэк — как сейчас |

## Открытые вопросы
| # | Вопрос | Предложение |
|---|--------|-------------|
| Q1 | «others_present» | Из недавних отправителей истории (был ли не-owner человек); порог конфиг |
| Q2 | id/username бота Боба | Из `BotRegistry`/`get_me` при старте; прокинуть в роутер |
| Q3 | Имя-обращение | Лёгкая эвристика («Боб,»/«Bob,» в начале); mention/reply — первичны |
| Q4 | Частота «вклиниться в ambient» | Малая, seeded, из конфига `addressivity.*` |
