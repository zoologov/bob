# BRIEF — Участник группы (гость) не получает ответа Боба

## Проблема (живая, owner)

Новый участник **Лилия** написала в топике Боба «**Привет, Боб. Тебя починили?**» — Боб промолчал,
и сообщения нет в `episodic_log`. Принцип владельца: **в группе → может общаться с Бобом; авторизация
гейтит ТОЛЬКО инструменты и приватные функции.** Молчание гостю = БАГ.

## Дефинитивная причинная цепь (разведка)

Роутинг НЕ виноват — гость в топике Боба **публикуется** и доходит до `HandleMessage`. Два дефекта
СТЕКАЮТСЯ:

1. **Молчание:** «Привет, Боб**.**» → **AMBIENT** (не прямое обращение). `_ADDRESS_TERMINATORS`
   (`conversation/addressivity.py:60`) после BOB-069 = `, : ! ?` — **точки нет**. «Боб.» с точкой →
   `_is_vocative_at` False → AMBIENT. Как AMBIENT + others_present → периферийный рефлексивный read →
   `salience < 0.35` → **IGNORE** (`room_verdict.py:94`) → молчание. Будь оно DIRECTED_TO_BOB →
   `_directed_engage`=True → детерминированный `_ReplyGate` → Боб ВСЕГДА отвечает (гость или нет).
2. **«Нет в БД»:** рефлексивный non-reply путь `_advance_silent`/`_react_turn`
   (`turn_gate.py:486`/`:473`) **НЕ персистит** входящее — в отличие от judge-пути `_act_non_reply`
   (`turn_gate.py:596/598`), который персистит и на IGNORE, и на REACT. Асимметрия → тред рвётся.

## Решение (два seam, под intent «участник группы всегда получает соц-ответ»)

### Seam A — вокатив с точкой распознаётся как обращение (чистое ядро)
`_is_name_address_to_bob`/`_is_vocative_at`/`_ADDRESS_TERMINATORS` (`conversation/addressivity.py`):
добавить «**.**» (точку) как допустимый терминатор-обращения справа, НО аккуратно против ложных
(«Это Боб.» = 3-е лицо, «Меня зовут Боб.»): требовать РЕАЛЬНЫЙ address-сепаратор СЛЕВА (запятая) для
случая точки-справа. Различает «Привет**,** Боб.» (запятая слева → вокатив) от «Это Боб.»/«зовут Боб.»
(пробел слева → сказуемое). 🔴 Не сломать матрицу BOB-069: ENGAGE «Кстати, Боб,»/«эй Боб!»/«…, Боб?»;
IGNORE «Боб молодец»/«Бобу»/«Боб-строитель»/«Это Боб.»/«зовут Боб.». Чистая функция, mutation-able.

### Seam B — персист входящего на рефлексивном non-reply пути
`turn_gate.py` `_advance_silent` (:486) + `_react_turn` (:473): персистить входящее сообщение
(как judge-`_act_non_reply` :596/598), чтобы тред участника не рвался даже при осознанном IGNORE.
Симметрия с judge-путём. (Для Лилии Seam A уже даст reply+persist; Seam B чинит тред для genuinely-
ambient сообщений участников — «читаю комнату», но помню разговор.)

## 🔴 НЕ трогать (authz-слой, ортогонален)
`Authorizer`, chat-scope/allowlist, флаг `is_guest` как **привилегия** (no tools / no owner-private /
отказ owner-команд на compose-пути `handle_message.py:1428-1437`). Гость получает соц-ответ, но без
инструментов/приватного — это остаётся. Роутинг-публикацию гостя не трогать (корректна).

## Критерии приёмки
- «Привет, Боб.» (и от гостя) → DIRECTED → Боб отвечает + сообщение в `episodic_log`.
- «Это Боб.»/«Меня зовут Боб.»/«Боб-строитель» → НЕ обращение (не регресс).
- Рефлексивный IGNORE участника → входящее персистится (тред цел).
- Гость по-прежнему без инструментов/owner-private (authz не тронут).
- pytest/mypy --strict/ruff/beadloom ci зелёные; mutation ≥85% на ядре адресности.
