# PRD: BOB-011 — Эпик «Память Боба»: помнит всё (семантика + агентный поиск + консолидация)

> **Status:** Approved
> **Created:** 2026-06-20
> **Type:** epic

---

## Контекст (что уже есть)

P0/BOB-002: SQLite (WAL) + FTS5 — `semantic_fts` (факты) + `episodic_fts` (весь архив переписки),
порт `MemoryRecall` (заложен шов keyword→vector), тонкая capability `recall_memory` (keyword-обёртка),
извлечение фактов (Tier 0). Tool-loop + capability-реестр (GUPPI-исполнитель).

## Проблема

Память Боба — **только keyword (FTS5)**: пропускает семантически близкое без совпадения слов («машина»
не найдёт «автомобиль»); `recall_memory` — тонкая обёртка, не агентная; **старое не всплывает**; нет
консолидации/долгой памяти. А книжный Боб **помнит всё** и умеет искать по всей своей истории. Это
ядро видения и фундамент под человечность (колбэки/«пока тебя не было думал о…» из BOB-010 Ф2/Ф3).

## Влияние

Боб начинает помнить как книжный — находит релевантное по смыслу даже спустя время, сам ищет по памяти
когда нужно. Усиливает все последующие фазы «живости». Приватно (эмбеддинги локальны).

## Стек (контур; детали — RFC)

Локальные эмбеддинги **`Qwen3-Embedding`** (мультиязычный SOTA, русский; через **Ollama** OpenAI-совместимо
→ позже **MLX**) + **`sqlite-vec`** (вектор-KNN в нашей же SQLite) → **гибрид FTS5(BM25)+vector+RRF** за
портом `MemoryRecall`. Всё локально/приватно (контент памяти не уходит наружу).

---

## Фаза 1 — Семантический/гибридный recall + агентный `search_memory`

**Цели:**
- [ ] **Локальные эмбеддинги** (`Qwen3-Embedding` через Ollama, OpenAI-совместимый клиент) за чистым
      портом `Embedder` — провайдер-агностично, приватно.
- [ ] **`sqlite-vec`** вектор-стор в существующей БД; эмбеддить факты + эпизоды (бэкфилл существующих + on-write).
- [ ] **Гибридный recall** за портом `MemoryRecall`: FTS5 (BM25) + sqlite-vec (KNN), слияние **RRF** →
      находит по смыслу И по словам. Drop-in замена keyword-recall (потребители не меняются).
- [ ] **`search_memory`** — **агентная capability** (через tool-loop): Боб сам решает поискать, реальным
      запросом, по всему архиву; возвращает релевантное (гибрид). Полноценная первая агентная capability
      (сверх тонкого `recall_memory`).

## Фаза 2 — Консолидация и долгая память (контур; беады на старте фазы)

Всплытие очень старого (релевантного) · суммаризация/консолидация длинной памяти (дайджесты эпизодов) ·
дедуп/слияние фактов · опц. «память-рефлексия». Зависит от Ф1 + тюнинга.

## Не-цели (вне BOB-011)

- Внешний RAG над доками/вебом (knowledge zones) — P3.
- Мультимодальная память (картинки/голос) — позже.
- Кросс-устройство/облачная синхронизация памяти.
- API-эмбеддинги (приватность: эмбеддинги локальны).

## Пользовательские истории

### US-1 (Ф1): Помнит по смыслу
**Как** owner, **я хочу**, чтобы Боб находил релевантное **по смыслу**, а не только по словам, **чтобы**
он «помнил» как человек/книжный Боб. **Приёмка:** семантически близкое находится без совпадения слов;
гибрид (вектор+keyword) лучше чистого keyword на наборе примеров.

### US-2 (Ф1): Сам ищет по памяти
**Как** owner, **я хочу**, чтобы Боб **сам** лез в память когда нужно (не только авто-recall), **чтобы**
доставал нужное из всей истории. **Приёмка:** `search_memory` вызывается моделью через tool-loop, реальным
запросом, по всему архиву; результат используется в ответе.

### US-3 (Ф1): Приватно и локально
**Как** owner, **я хочу**, чтобы эмбеддинги/память были локальными, **чтобы** контент не уходил наружу.
**Приёмка:** эмбеддинги считаются локально (Ollama/MLX); вектора в локальной SQLite; ноль внешних вызовов
с контентом памяти.

## Критерии приёмки (общие)

- [ ] Гибридный recall за портом `MemoryRecall` (drop-in); `search_memory` агентно работает; эмбеддинги локальны.
- [ ] Бэкфилл существующей памяти + on-write эмбеддинг; реактивный чат/проактив (BOB-001..010) не сломаны.
- [ ] Тесты ≥80% (эмбеддер/вектор-стор на фейках — без сети в CI), `ruff`/`mypy --strict` чисто,
      `beadloom ci` зелёный.
