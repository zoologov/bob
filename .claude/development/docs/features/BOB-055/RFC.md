# RFC: BOB-055 — «Надёжный web_search: стриминг + реплика "ищу…"»

> **Status:** Approved
> **Created:** 2026-07-01
> **PRD:** `.claude/development/docs/features/BOB-055/PRD.md`
> **Решения (под утв.):** (A) `QwenWebSearchProvider` → стриминг Responses API (SSE, парс финального
> `response.completed`) · (B) реплика «ищу…» через `ProgressAnnouncer` в tool-loop (per-turn, chat-bound,
> декоративно) · вариативность фраз seeded-RNG · инвариант BOB-053 (честный нотис, без выдумки) цел.

---

## Идея решения

Две независимые части поверх BOB-053, обе за существующими швами:

- **(A) Надёжность — стриминг.** `QwenWebSearchProvider.search()` переходит на **стриминг** Responses API
  (`stream:true`): непрерывный поток SSE-событий держит соединение живым и обходит ~30с-таймаут (доказано
  диагностикой: не-стрим рвётся на 31с, стрим живёт 90–120с). Контракт `WebSearchResult` не меняется.
- **(B) UX — реплика «ищу…».** Tool-loop, прежде чем запустить долгий навык, шлёт **сразу** короткую живую
  реплику в чат («секунду, гляну в сети…») через инъектируемый `ProgressAnnouncer`, связанный per-turn с
  chat_id + gateway. Финальный ответ приходит после (вторым сообщением). Декоративно (сбой анонса не ломает
  ход).

## Часть A — стриминг провайдера (infrastructure)

`infrastructure/llm/web_search_qwen.py` — `QwenWebSearchProvider.search()`:

- Запрос: тот же `{model, input:<query>, tools:[{type:"web_search"}]}` + **`"stream": true`**; заголовок
  `Accept: text/event-stream`.
- Чтение: итерировать тело построчно (`response.content`), парсить SSE `data: <json>` события; **накопить до
  терминального `response.completed`** (несёт полный `response.output` — тот же список items, что и сейчас).
  Игнорировать промежуточные delta-события (нам нужен финальный агрегат).
- Парсинг финала — **переиспользовать текущую логику**: `output[]` → `web_search_call.action.sources[].url`
  (dedup) + `message.content[].output_text`. Тот же `WebSearchResult{answer, sources}`.
- Ошибки/оборванный стрим/нет `response.completed`/non-200 → **raise** (как сейчас, raise-on-failure).
  Таймаут — общий с запасом (текущий `timeout_seconds`, ≥180с); ключевое, что стрим не даёт ~30с-простоя.
- Ретраи (BOB-049 `call_with_retry` в capability) остаются как есть — стриминг снимает корневую причину.

## Часть B — реплика «ищу…» (application, за швом)

**`ProgressAnnouncer` (application-порт).** `async def announce(self, capability_name: str) -> None` —
решает (по имени навыка), нужно ли и что сказать; если да — шлёт короткую живую реплику в текущий чат;
**свои ошибки глотает** (декоративно, `_safe_addon`-стиль BOB-050).

**Реализация (per-turn, chat-bound).** `GatewayProgressAnnouncer` в реализации знает: `chat_id` (текущий
ход), `gateway` (шов `reply(chat_id, markdown)`), карту `имя-навыка → тема-фразы` (пока только
`web_search → «поиск в сети»`), и **инъектируемый seeded-RNG** для выбора варианта. Набор из ~5–8 живых
разных фраз в голосе Боба («секунду, гляну в сети…», «пойду поищу, момент…», …) — не один робо-шаблон
(US-4). Seeded-RNG → детерминизм в тестах.

**Провязка в tool-loop.** `ToolLoop.__init__(..., announcer: ProgressAnnouncer | None = None)`; в `_run_tool`
ПЕРЕД `registry.dispatch(...)`: `if self._announcer: await self._announcer.announce(call.name)`. Анонсер
сам решает молчать (для быстрых навыков) или говорить (web_search). **Никаких изменений контракта
`Capability`** — решение по имени в анонсере (минимально, без ряби на все навыки).

**Сборка.** `ToolLoop` строится per-turn в `HandleMessage` (сейчас ~стр. 2763). Там же доступны chat_id и
gateway → `HandleMessage` конструирует per-turn `GatewayProgressAnnouncer(chat_id, gateway, rng, map)` и
передаёт в `ToolLoop`. Не провязано (дефолт) → анонсер `None` → поведение как сейчас. `privileged_fulfiller`
(свой ToolLoop) анонсер НЕ получает в v1 (approved-privileged путь — другой UX).

**Порядок сообщений.** Анонс = отдельное сообщение «ищу…» в минуту 0; финальный ответ — вторым сообщением
после tool-loop. `typing_indicator` продолжает оборачивать генерацию.

## 🔴 Отказоустойчивость / инварианты

- **Анонс декоративен:** сбой `announce` (или gateway) — **тихо опускается**, обычный ход не ломается,
  ответ не блокируется (принцип «полный Боб»: флейвор-addon при сбое молчит).
- **Инвариант BOB-053 цел:** реальный сбой поиска (даже со стримингом) → `call_with_retry` → честный нотис
  «не смог найти» БЕЗ конфабуляции. Стриминг лишь снижает **ложные** нотисы (таймаут), честный отказ на
  реальном сбое остаётся.
- **Один анонс на навык-вызов** (не на каждый ретрай reply-уровня) — анонс в tool-loop перед dispatch,
  идемпотентность не критична (в худшем случае две реплики «ищу…», редко).

## Слои (DDD)

- **domain:** без изменений (порт `WebSearchProvider`/`WebSearchResult` те же). `ProgressAnnouncer` — порт
  в application (это про оркестрацию/транспорт-шов, не доменная сущность), рядом с tool-loop.
- **application:** `ProgressAnnouncer` порт + `GatewayProgressAnnouncer`; `ToolLoop` +optional announcer;
  провязка в `HandleMessage` (per-turn сборка).
- **infrastructure:** `QwenWebSearchProvider` — стриминг (SSE-чтение/парсинг).

## Риски и митигации

- **Парсинг SSE** (форматы событий Responses API) → парсить терпимо: искать `response.completed`,
  игнорировать неизвестные события; на отсутствие финала — raise (честный нотис). Тесты на реалистичный
  поток.
- **Долгий поиск (1–2 мин)** → анонс «ищу…» закрывает тишину; таймаут ≥180с; если реально не успел —
  честный нотис.
- **Двойной анонс** (ретраи) → приемлемо (редко); анонс идемпотентности не требует.
- **«Программщина»** (робо-«Loading…») → набор живых вариаций в голосе Боба, seeded-выбор (US-4).
- **Связанность** → анонсер за портом, решение по имени; `Capability`-контракт и потребители не трогаем.

## Открытые решения (под утверждение)

1. **Стриминг парсинг:** копить SSE до `response.completed`, переиспользовать текущий парсер output —
   **рекомендую** (минимальная правка, тот же контракт).
2. **Механизм анонса:** `ProgressAnnouncer` в tool-loop, решение по имени навыка (без правки контракта
   `Capability`) — **рекомендую** (минимально, общо, расширяемо на read_url позже).
3. **Вариативность фразы:** набор ~5–8 живых вариантов + seeded-RNG (не Tier-0-генерация в v1) —
   **рекомендую** (дёшево, надёжно, тестируемо, не робот). Tier-0-генерация — возможный upgrade позже.
4. **Декоративность:** сбой анонса тихо опускается; инвариант BOB-053 честного нотиса цел — **рекомендую**.
5. **Объём:** анонс только в обычном reply-пути (не privileged_fulfiller) в v1 — **рекомендую**.
