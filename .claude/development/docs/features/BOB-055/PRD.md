# PRD: BOB-055 — «Надёжный web_search: стриминг + реплика "ищу…"»

> **Status:** Approved
> **Created:** 2026-07-01
> **Feature:** BOB-055 · Тир-1/2 · надёжность + UX · фикс BOB-053

---

## Контекст

BOB-053 дал Бобу `web_search` (Qwen Responses API, `qwen3.7-plus`, `tools:[web_search]`). Навык **вызывается
корректно** (Боб сам выбирает его, эндпоинт верный), но вживую часто падает. Диагностика (2026-07-01,
живые вызовы) показала:

- Обычный (не-стримовый) Responses+web_search рвётся **стабильно на ~31с** (`ServerDisconnectedError`), а
  не в случайные моменты → это **таймаут на длинный ответ** где-то в пути (шлюз/прокси), НЕ флап канала
  owner (TCP до хоста ок, быстрые вызовы 7–10с стабильны).
- **Стриминг** (`stream:true`) тот же запрос **проживает 90–120с** и завершается (HTTP 200, 800–1000+ SSE-
  событий) — непрерывный поток данных обходит ~30с-таймаут.

Причина: серверный веб-поиск + reasoning реально идут **~1–2 минуты**; не-стримовое соединение до конца не
доживает. Плюс UX-проблема: даже когда поиск завершится, owner **1–2 минуты сидит в тишине**, не понимая,
занят ли Боб.

## Проблема

1. **Надёжность:** `web_search` часто отдаёт честный нотис «не смог найти» не из-за отсутствия результата,
   а из-за ~30с-обрыва длинного не-стримового ответа. Навык де-факто нерабочий на медленных поисках.
2. **UX-тишина:** долгий поиск (1–2 мин) без обратной связи — owner не знает, ищет ли Боб или завис.

## Цель

Сделать `web_search` **надёжным** (стриминг Responses API — обходит ~30с-таймаут, поиск доживает до конца) и
**живым по ощущению**: пока Боб ищет, он **сразу говорит своим голосом**, что пошёл смотреть («секунду,
гляну в сети…»), а через 1–2 мин отвечает по существу со ссылками. Никакой мёртвой тишины и никаких ложных
«не смог найти» из-за таймаута.

## Пользовательские истории

- **US-1 (надёжный поиск).** Owner: «что нового у X?» → Боб реально ищет (стриминг доживает до конца) →
  отвечает со ссылками. Ложных «не смог найти» из-за ~30с-обрыва больше нет.
- **US-2 (реплика "ищу…").** Как только Боб решил искать → он **сразу** шлёт короткую живую реплику своим
  голосом («секунду, гляну в сети…»), потом (через 1–2 мин) — ответ по существу. Owner не сидит в тишине.
- **US-3 (🔴 честный отказ остаётся).** Если поиск реально не удался (сеть легла даже со стримингом,
  провайдер недоступен) → честный нотис «не смог найти», БЕЗ выдумки (инвариант BOB-053 цел).
- **US-4 (естественность, не «программщина»).** Реплика «ищу…» — **живая и разная** (не один робо-шаблон
  на все случаи), в голосе Боба. Не выглядит как системное «Loading…».

## Критерии успеха

- `web_search` завершается на медленных (1–2 мин) поисках (стриминг), без ложных обрывов на ~30с.
- Как только Боб инициирует поиск — owner **сразу** видит живую реплику «ищу…», затем финальный ответ.
- 🔴 Реальный сбой → честный нотис без выдумки (инвариант BOB-053 не ослаблен).
- Реплика «ищу…» звучит естественно и по-разному (не шаблон-робот).

## Объём

**В объёме:**
- **Стриминг `QwenWebSearchProvider`:** Responses API `stream:true` → читать SSE-события → парсить финальный
  `response.completed` (ответ + источники, тот же контракт `WebSearchResult`). Таймаут с запасом (≥180с).
- **Реплика «ищу…»:** когда tool-loop запускает долгий навык (web_search) → Боб **сразу** шлёт короткую
  промежуточную реплику в чат своим голосом, до финального ответа. Механизм — за швом (порт-нотификатор),
  без завязки capability на транспорт.
- **Естественность реплики:** живая, разная (набор вариаций / лёгкая генерация), в голосе Боба.
- 🔴 Инвариант BOB-053: реальный сбой → честный нотис без конфабуляции — сохранить.

**Вне объёма:**
- Стриминг финального **ответа Боба** пользователю по токенам (это про генерацию реплики, не про поиск) —
  отдельная история; здесь стримим только вызов провайдера ради надёжности.
- Промежуточный прогресс-бар/проценты поиска — достаточно одной живой реплики «ищу…».
- `read_url` interim-реплика — по желанию позже (read_url обычно быстрее); если механизм выйдет общим —
  переиспользуем, но цель здесь — web_search.
- Тюнинг числа ретраев (BOB-053) — стриминг снимает корневую причину; ретраи оставляем как есть.

## Связи и принципы

- Фикс **BOB-053** (`web_search`); тот же **capability-шов** (BOB-002), tool-loop/GUPPI; принцип **«полный
  Боб или честный GUPPI-нотис»** (BOB-049/ROADMAP #10) — стриминг снижает ложные нотисы, честный отказ на
  реальном сбое остаётся; **естественность** («никогда не выглядеть программно», север
  `bob-personality-simulation-philosophy`). Родственно `read_url` (BOB-054). Север: `bob-telegram-pivot`.
