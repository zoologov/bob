# PRD — Боб видит и навигирует весь репозиторий

## Проблема

Владелец в Telegram просит Боба выполнить реальное действие над репозиторием:
«покажи список файлов в `.beadloom/`», «найди файл `X`», «какие директории ты видишь?».
Боб в ответ **конфабулирует нарратив** («GUPPI пошёл искать, перебирает байты, ждём отчёта»)
и **не выдаёт никаких данных**. Живое подтверждение (лог + БД):

- ответы в `episodic_log` — чистый нарратив без результата;
- `tool_loop: Capability read_code failed — DeniedPathError: reading '.beadloom/rules.yml'
  is denied by the privacy guard` — модель **пыталась** вызвать инструмент, но путь заблокирован.

**Корень (двойной):**
1. У Боба **нет инструмента листинга директории / поиска файла** — только `read_code` (один
   известный путь), `inspect_architecture`, `list_work`, `code_rationale`. Класс запроса
   «покажи файлы / найди файл» не мапится ни на один tool → LLM галлюцинирует.
2. `PrivacyGuard.ALLOWED_ROOTS` — узкий белый список (`src/ tests/ docs/ .claude/dev-docs
   .claude/development/docs`). `.beadloom/`, `config/`, корневые файлы — **denied**, даже для
   владельца.

## Цель

Боб — равный участник, работающий со **всем репозиторием** так же свободно, как инженер:
**листит** директории, **ищет** файлы по имени/паттерну, **читает** любой файл — и докладывает
**факты (реальные данные)**, а не нарратив о намерении. Осознанное решение владельца: полный
доступ ко всему репо — это выбор, не проблема безопасности. Секрет-значения при этом
маскируются на выходе (backstop `sanitize`), чтобы литеральные токены не утекали во внешний LLM.

## Пользовательские сценарии

1. **Листинг директории.** «Покажи файлы в `.beadloom/`» → Боб вызывает `list_dir(".beadloom")`,
   возвращает реальные имена + тип (файл/директория) + размер; докладывает список фактами.
2. **Поиск файла.** «Найди файл `privacy_guard.py`» → Боб вызывает `find_file("privacy_guard.py")`,
   возвращает реальные совпадающие пути; если нет — честно «не найдено» (не выдумывает).
3. **Обзор структуры.** «Какие директории репозитория ты видишь?» → `list_dir(".")` в корне →
   реальный перечень верхнеуровневых директорий.
4. **Чтение вне прежнего белого списка.** «Что в `config/bob.example.yaml`?» → `read_code`
   теперь читает (полный репо), секрет-значения `[REDACTED]`.
5. **Честный отказ на выход из репо.** Попытка `../../etc/passwd` или абсолютный путь вне репо →
   отказ (полный доступ = поддерево репо, НЕ вся ФС машины).

## Инварианты (обязательные)

- **INV-N1 (действие, не нарратив):** запрос листинга/поиска приводит к РЕАЛЬНОМУ tool-call и
  фактическому результату в ответе; отсутствие — не «якобы ищу».
- **INV-N2 (полный репо):** любой путь, резолвящийся ПОД корнем репо, читаем/листится (осознанный
  выбор владельца) — включая `.beadloom/`, `config/`, `data/`, корневые файлы.
- **INV-N3 (граница репо):** путь, выходящий за корень репо (`..`-traversal, абсолютный путь вне
  репо), — **denied**. Полный доступ = поддерево репо, не файловая система машины.
- **INV-N4 (секрет-backstop сохранён):** `sanitize()` по-прежнему вымарывает секрет-образные
  значения (`sk-`-токены, `KEY=value`, api-key/token/secret/password) из ЛЮБОГО вывода до отправки.
- **INV-N5 (честный «пусто»):** несуществующий файл/пустая директория → честный пустой результат,
  Боб не выдумывает содержимое.
- **INV-N6 (read-only):** инструменты только читают; никаких мутаций файловой системы.

## Не входит в scope

- Запись/правки файлов (для этого есть `coder`/`/code` — BOB-039).
- Рекурсивный дамп всего дерева одним вызовом (find по паттерну — да; «выгрузи весь репо» — нет).
- Изменение персоны/тона отдельным эпиком (лёгкий nudge против нарратива — в RFC как опция).
