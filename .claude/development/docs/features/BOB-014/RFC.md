# RFC: BOB-014 — «Отношения (multi-party) + обида/охлаждение» (T1.5)

> **Status:** Approved
> **Created:** 2026-06-23

---

## Обзор

Два слоя поверх готового: **RelationshipTracker** (per-person качество отношений, влияет на тон и
уступчивость) и **Обида/охлаждение** (Sulk — вместо книжного Exodus hard-reset). Всё «как характер», под
guardrails в духе BOB-013/020 (границы, плавный дрейф, идемпотентность, **гарантированное** восстановление).
Память цела. Sulk — это маркер «аффект со ставками» (линза сознания VISION §4.2).

## Технический контекст

### Ограничения
- Python 3.12+, DDD/Clean (домен чист), инъекция `Clock`/seeded-RNG/портов, TDD на фейках, `mypy --strict`,
  `ruff`, cov ≥80%.
- Не ломать: реактив/проактив (BOB-010), память (BOB-011/021), личность (BOB-013/020), Свои-и-чужие
  (BOB-019), тиринг, authz. Mood остаётся ядром аффекта; relationship — поверх.
- **Память цела:** никакого reset/нового Genesis (anti-Exodus).

### Затрагиваемые области
`domain/personality/{relationship.py (new), sulk.py (new)}`, `infrastructure/persistence/relationship_store.py`
(new, per-sender, как first_impression), `application/usecases/handle_message.py` (влияние на тон/уступчивость +
апдейт отношения + холодный тон при обиде), `domain/proactivity/governance.py` (sulk-veto), `application/
usecases/heartbeat.py` (восстановление обиды на reflect-тике), `infrastructure/telegram/guppi.py` (announce
обиды), `domain/ports.py`, `app.py`, `config`.

## Предлагаемое решение

### (1) RelationshipTracker (multi-party)
- **`domain/personality/relationship.py`** (чистый): `Relationship(sender_id, trust, respect, warmth,
  compatibility)` — каждое в `[-1,1]`, старт ~0 (нейтрально). Чистая `apply_interaction(rel, *,
  stance, mood, sentiment) -> Relationship`: малые ограниченные дельты (Negotiation `Stance` — уступка
  греет/растит respect по-разному; тёплый сентимент/настроение → warmth; и т.д.) + лёгкий **дрейф к нейтрали**.
- **`RelationshipStore`** (per-sender, новая таблица `relationship`, по образцу `first_impression`).
- **Влияние** (в `handle_message`): загрузить отношение отправителя → (а) **тон** (высокий warmth → теплее
  директива, низкий → суше) — поверх mood/voice; (б) **уступчивость** — warmth/compat смещают порог
  Negotiation (с близким охотнее компромисс). Апдейт **после** хода (stance+mood+сентимент), персист.

### (2) Обида/охлаждение (Sulk)
- **`domain/personality/sulk.py`** (чистый): `SulkState(active, intensity, since, reason)` + чистые переходы:
  **вход** — когда **owner-отношение** (главное, ведёт проактив) устойчиво ниже критического порога
  (нужна устойчивость, не разовый дип); **затухание** — `intensity` падает со временем (гарантирует выход)
  и **быстрее от тепла** (тёплые сообщения owner); **выход** — ниже порога active. Границы, идемпотентность.
- **Персист** sulk-состояния (per-persona, как proactivity state).
- **Эффекты:**
  - **Проактив подавлен:** в `governance` добавляется **sulk-veto** (Боб не пишет первым, пока обижен).
  - **Реактив холодный:** `voice.sulk_directive()` — суше/минимально (но не reset; всё ещё Боб).
  - **GUPPI announce (one-shot при входе):** GUPPI постит в чат «Боб обижен и сейчас не хочет разговаривать»
    (внеличностный системный голос; один раз на вход в обиду). _Q4._
  - **Восстановление:** шаг на **reflect-тике** (как BOB-020 эволюции) затухает обиду (время + накопленное
    тепло) → выход. **Гарантированно отходит** (затухание по времени даже без тепла). Опц. лёгкий сигнал
    возвращения.
- **Anti-Exodus:** память/душа НЕ сбрасываются — Боб «отходит», не «уходит».

### Каденс / композиция
- `handle_message`: relationship-влияние на тон/уступчивость + апдейт; при `sulk.active` — холодный тон.
- `governance`: sulk-veto на проактив.
- `ReflectTick`: шаг восстановления обиды (+ апдейт дрейфа отношений по желанию).
- `GUPPI`: announce при входе в обиду.

## Guardrails (под тестами)
- Отношения: малые дельты + дрейф, всё в `[-1,1]`; персист round-trip.
- Обида: **порог + устойчивость** (не по мелочи); **гарантированный выход** (intensity затухает по времени
  до нуля независимо от тепла → нет вечной блокировки); идемпотентность (повтор тика не «застревает»);
  GUPPI-announce **один раз** на вход.
- Память цела (никаких удалений/reset). «Как характер» (тон/обида из состояния, не из правил).

## Рассмотренные альтернативы
- **Книжный Exodus (hard-reset + новый Genesis)** — отвергнуто владельцем: негуманно/теряет память; берём
  обиду с сохранением памяти.
- **Sulk на каждого** — в v1 обида завязана на **owner-отношение** (оно ведёт проактив и адресата мета-
  сообщения); per-person обида — позже. RelationshipTracker — multi-party уже сейчас.
- **Жёсткое молчание без выхода** — отвергнуто: риск вечной блокировки; гарантируем затухание.

## Риски
| Риск | Вер. | Влияние | Митигация |
|---|---|---|---|
| Боб «залип» в обиде навсегда | Low | High | Затухание intensity по времени до нуля (гарантия выхода) + тест |
| Обида по мелочи (ложный триггер) | Med | Med | Критический порог + устойчивость во времени; тесты на «не по мелочи» |
| Дрейф отношений вразнос | Low | Med | Малые дельты + границы + дрейф к нейтрали (как BOB-013/020) |
| GUPPI-announce спамит | Low | Low | One-shot на вход в обиду (флаг «announced») |

## Открытые вопросы
| # | Вопрос | Предложение |
|---|--------|-------------|
| Q1 | Дельты/дрейф отношений | Малые (≈0.05) + дрейф к 0; конфиг `relationship.*`; границы [-1,1] |
| Q2 | Sulk per-owner vs per-person | v1 — owner-отношение; per-person позже |
| Q3 | Пороги обиды + скорость затухания | Критический порог + N времени устойчивости; затухание гарантирует выход; конфиг `sulk.*` |
| Q4 | Куда GUPPI шлёт announce | В чат/топик, где owner видит; one-shot на вход |
