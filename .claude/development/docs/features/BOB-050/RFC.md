# RFC: BOB-050 — «Восприятие реакций на сообщения Боба»

> **Status:** Approved
> **Created:** 2026-06-30
> **PRD:** `.claude/development/docs/features/BOB-050/PRD.md`
> **Решения (утв.):** `bob_message_id` колонка · «вслух» = подсказка в compose · verify defensive в ходе
> разработки.

---

## Идея решения

Зеркало BOB-049. Принять Telegram `message_reaction`-апдейт (постановка/снятие реакции на сообщение Боба),
связать его с тем, что Боб **сказал** (по `message_id`), и **семантически** (Tier-0 `ReactionJudge`, как
`ResponseJudge`) понять смысл реакции → эффект на настроение/отношения/память + ощущение «меня услышали».
Восприятие реакции **декоративно/опционально** — его сбой тихо опускается (принцип «полный Боб», не essential).

## Транспорт (приём реакций)

- **allowed_updates:** добавить `message_reaction` (и `message_reaction_count`) в `get_updates`
  (`gateway.poll_once` / `app.py`). Сейчас дефолт их не доставляет.
- **Маршрутизация:** диспетчер получает `MessageReactionUpdated` → доменное событие `BobMessageReaction`
  {chat_id, message_id, эмодзи (old→new → added/removed), кто (user→sender_id→Interlocutor)}; публикуется на
  шину (как `MessageReceived`). Фильтр: только реакции на сообщения **Боба** (по записанному message_id).
- **🔴 Verify + defensive:** проверить вживую доставку для собственных сообщений бота в супергруппе. Если
  приходит только анонимный `message_reaction_count` (без «кто») — деградация: событие «кто-то отреагировал»
  (sender=None) → ощущение отклика есть, но без персоны (память/отношения per-person пропускаем).

## Связь реакции с сообщением Боба (по message_id)

- При отправке ответа Боба фиксировать `message_id` исходящего (`send_message`/`send_rich_message` его
  возвращают) и **сохранять в эпизод**: новая колонка `bob_message_id INTEGER NULL` в `episodic_log` +
  идемпотентная PRAGMA-миграция (как BOB-045 `sender_id`). Реакция на `message_id` → найти эпизод → **текст
  реплики Боба** (что именно восприняли).
- Нет эпизода для message_id (старое/не Боба) → мягко пропустить.

## Семантический шов `ReactionJudge` (Tier-0)

```python
class ReactionJudge(Protocol):
    async def interpret(self, ctx: ReactionContext) -> ReactionMeaning: ...
```

- **`ReactionContext`:** эмодзи, `added|removed`, **текст сообщения Боба**, кто отреагировал
  (Interlocutor/отношение BOB-014), мягкий контекст нити.
- **`ReactionMeaning`:** интерпретация (строка, для памяти/лога) + **mood-эффект** (знак+величина ИЗ СМЫСЛА,
  не из эмодзи) + warmth-нудж отношения + признак «стоит ли отметить вслух». Снятие → лёгкий
  негатив/неуверенность.
- **Tier-0 реализация** `LlmReactionJudge` (чистый промпт/парсер, как BOB-049). Сбой/непарсибельно → НЕ
  тихий дефолт-эффект, а **опустить восприятие** (декоративно; см. отказоустойчивость).

## Эффекты (use-case `PerceiveReaction`)

На `BobMessageReaction` (через шину):
1. найти текст сообщения Боба по `bob_message_id`; собрать `ReactionContext`; `ReactionJudge.interpret`.
2. **Настроение:** применить mood-эффект через BOB-033 соц-зарядку (`Mood.lift_toward`/дельта) — величина из
   смысла. Тёплое поднимает, снятие/холод чуть опускает (в полосе, без качелей).
3. **Отношения (BOB-014):** warmth-нудж к персоне (кто резонирует — теплее), bounded.
4. **Память (BOB-045):** записать эпизод «<кто> отреагировал <emoji> на моё „<кратко>“ — <смысл>» → для
   колбэков; per-person (sender_id).
5. **«Меня услышали»:** при стоящей реакции — пометка для **изредка-вслух** (низкочастотный опц. флейвор).

## «Изредка вслух» (опциональный флейвор)

- Не отдельное сообщение и не каждый раз: при следующем compose Боба — **низкочастотная** подсказка в
  контекст («недавно <кто> тепло отреагировал на твоё про <тема> — можешь естественно отметить»), Боб сам
  вплетает (не скриптовая фраза). Seeded-частота. Сбой подсказки — тихо опускается.

## Отказоустойчивость и authz

- 🔴 **Декоративно/опционально:** весь путь восприятия реакции — НЕ essential. Сбой `ReactionJudge`/эффекта
  → **тихо опускается** (`_safe_addon`-стиль BOB-049 .3), НИКОГДА не GUPPI-нотис, не ломает ответы Боба.
- 🔴 **Authz (BOB-019):** гость может отреагировать — Боб чувствует (соц-эффект), но реакция-восприятие не
  открывает owner-приват; память per-person (о реакции, не о приватном); гостевой ход не пишется в
  owner-факты. Реакция на сообщение Боба — низкий риск (про ЕГО сообщение), но контейнмент держим.

## Слои (DDD)

- **domain:** `BobMessageReaction` событие, `ReactionContext`/`ReactionMeaning`, `ReactionJudge` порт, чистый
  промпт/парсер.
- **application:** `PerceiveReaction` use-case (смысл → mood/отношения/память/пометка); запись
  `bob_message_id`; подписка на шину.
- **infrastructure:** allowed_updates + маршрутизация `MessageReactionUpdated`; миграция `bob_message_id`;
  `LlmReactionJudge` (Tier-0).

## Риски и митигации

- **Доставка реакций на свои сообщения** — главный риск → verify вживую + defensive (anon-деградация).
- **Снятие реакции** двусмысленно (передумал/случайно) → мягкий, слабый эффект; не драматизировать.
- **Спам реакций** (часто меняют) → throttle/дедуп события на message_id; не дёргать судью на каждый микро-тык.
- **Регрессии** mood/отношения → bounded-эффекты (BOB-030 полоса), без качелей.

## Открытые решения (под утверждение)

1. **Хранение связи:** колонка `bob_message_id` в `episodic_log` (рекомендую) vs отдельная таблица.
   Рекомендую колонку (как BOB-045).
2. **«Вслух»:** низкочастотная **подсказка в compose** (Боб сам вплетает) vs отдельное сообщение. Рекомендую
   подсказку (естественнее, не навязчиво).
3. **Verify:** строить defensive + проверить вживую в ходе разработки (а не отдельным спайком). Рекомендую.
