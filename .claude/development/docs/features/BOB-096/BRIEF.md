# BRIEF: BOB-096 — канон и тир на ВСЕХ дверях генерации + предложение правила голосом Боба

> **Status:** Approved
> **Created:** 2026-08-12

## Проблема — один класс, два симптома

**Гейт стоит на одной двери, остальные его обходят.** И обход не безобиден: дверь, которая
пишет в память, производит будущие few-shot'ы — её мусор возвращается в поведение через
припоминание (механизм BOB-074).

**Симптом 1.** Боб сказал: «GUPPI уже проверил все связи. **Он говорит**, что стрелочки идут
именно туда… **Для него** это идеальная логика». Оба запрещённых движения: речь и суждение за
исполнителя. Директива `guppi_no_roleplay_directive` при этом на месте и приклеена безусловно
— но только к разговорному ходу. А источник подражания — **его собственные рефлексии**:
«GUPPI нетерпеливо постукивает», «перестанет путать отладку с экзорцизмом». Он пишет себе
few-shot по нарушению канона, а потом добросовестно ему следует.

**Симптом 2.** «Заметил за собой: Боб замечает, что его поведение часто повторяется**..**
Предлагаю: **.** Включить? (`/rule approve rule-…`)» — пустая поправка, нулевая величина,
третье лицо о себе, двойная точка от пустого слота, идентификатор внутри фразы. Сочинил
дублёр `0.5b` в секунду отвала Tier-1.

## Что показала разведка (16 дверей)

| Факт | Следствие |
|---|---|
| Базовая персона применяется **ровно к одной** двери — разговорному ходу | Запрет отыгрыша GUPPI — не запрет, а свойство одного пути |
| 🔴 `self_improvement.detector_tier: 1` — **мёртвый ключ**: есть в конфиге и дефолтах, но сборка детектора строит его **без тира** | «Заявленного тира» не существует как механизма. §0.3 п.10, но про **ключ конфига без читателя** |
| Вердикт целостности голоса применён к **3 дверям из 16**, по условию `task_type is REPLY_TO_USER` | Детектор правил, рефлексия, дайджесты, переоценка, work_journal — вне защиты |
| Пишут в память и персоны не видят: рефлексия · переоценка · консолидация · проактивная реплика · work_journal · `extract_facts` · автобиография | Семь источников будущего few-shot без канона |
| `announce_rules`: шаблон со слотами; пометка «проговорено» — set **в памяти процесса**; при сбое `return` **до** пометки, капа нет | Шесть дней долбёжки при битой сети — наблюдалось вживую |

## Образец решения уже есть в репозитории

`social/permission/request_voice.py` (BOB-090.E) решает ту же задачу **разделением ролей, а не
генерацией**: вердикт судьи остаётся **внутри** и лишь **выбирает** одну из готовых
формулировок Боба; машинный текст никогда не становится телом фразы; «чего именно» — цитата
слов просителя. Детерминированно, без LLM. У `announce_rules` наоборот — сырой вывод детектора
вставляется дословно.

## Решение

### 🔴 Главный принцип

**Не приклеивать директиву копипастой в каждую дверь** — это ровно то, что уже сломалось
(запрет есть, но в одном месте). Нужен шов, при котором дверь **не может родиться** без канона
и без вердикта о голосе. Проверяется архитектурным тестом, который сканирует `src/` и
падает на новой двери, обошедшей шов, — по образцу единственного обёрнутого порта памяти из
BOB-090.B.

### Срез 1 — канон достаёт до всех дверей, пишущих в память

Персона (в части запретов о голосе) применяется к каждому пути, чей вывод ложится в память от
лица Боба: рефлексия, переоценка, консолидация, проактивная реплика, work_journal,
`extract_facts`, автобиография. Не через дублирование текста, а через общий шов.

### Срез 2 — вердикт о голосе по СМЫСЛУ двери, и мёртвый ключ

Сейчас «это голос Боба» = `task_type is REPLY_TO_USER`. Заменить на явное свойство двери:
служебная (дублёр допустим) против «голос Боба» (дублёр недопустим — эскалация вверх либо
молчание). Служебные по разведке: судьи, `coding_intent`, `work_talk`, `sentiment`,
`extract_facts`, `room_read`, `interim_line`. Голос Боба: разговорный ход, проактивная реплика,
детектор правил, рефлексия/дайджест/переоценка/work_journal.

🔴 `detector_tier` — **либо читается, либо удаляется**. Ключ конфига без читателя хуже
отсутствующего: он читается как обещание.

### Срез 3 — вырожденное предложение не рождается

Пустое наблюдение, пустая поправка или `magnitude <= 0` (или вне `max_magnitude`) → предложение
не создаётся и в чат не идёт. Молча, без шума. Owner не должен получать вопрос, на который
нельзя ответить осмысленно.

### Срез 4 — реплика голосом Боба + доставка, переживающая перезапуск

По образцу `request_voice`: вердикт детектора остаётся внутри и **выбирает** формулировку;
идентификатор правила — служебная сноска, а не часть фразы; Боб говорит о себе от первого лица.
Плюс: пометка «проговорено» живёт в хранилище (у `ImprovementRule` уже есть `state`), и есть кап
повторов при сбое отправки — «best-effort» означает «не роняем тик», а не «пробуем вечно».

## Границы

- Не менять смысл существующих директив — только их **досягаемость**.
- Флаги: новые механизмы за флагом, default OFF; OFF-путь байт-в-байт.
- Уже отгруженные двери не переписывать «заодно» — только подключить к шву.

## Критерии приёмки

- [ ] Запрет отыгрыша GUPPI действует на **всех** дверях, пишущих в память от лица Боба;
      перечень дверей назван и покрыт тестом
- [ ] Архитектурный тест падает на новой двери, обошедшей шов
- [ ] Вердикт о голосе выбирается по смыслу двери, а не по `task_type is REPLY_TO_USER`
- [ ] 🔴 `detector_tier` читается либо удалён — ключа-без-читателя не остаётся
- [ ] Вырожденное предложение не рождается (пусто/ноль → нет предложения)
- [ ] Пометка «проговорено» переживает перезапуск; есть кап повторов
- [ ] Реплика о правиле — голосом Боба: без слотов, без третьего лица о себе, без двойной
      пунктуации, идентификатор вне фразы
- [ ] 🔴 **Живой смоук**: Боб не приписывает GUPPI речь и мнение; пустых предложений не шлёт;
      реплику о правиле нельзя отличить от его обычной речи
