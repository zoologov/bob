# RFC: BOB-045 — «Память диалога по персоне + длинные паузы»

> **Status:** Approved
> **Created:** 2026-06-26
> **PRD:** `.claude/development/docs/features/BOB-045/PRD.md`
> **Решения (утв.):** owner replay — per-person; non-owner recall — пост-фильтр по `sender_id`; «давно
> не виделись» — лёгкий опц. маркер (~8ч).

---

## Идея решения

Единица памяти диалога — **личная нить собеседника**: недавние ходы **с этим человеком**, отобранные по
его `sender_id` (а не глобально). Реплеится нить **текущего** собеседника (owner / known / guest). Приват
вытекает **по конструкции**: каждый видит только СВОЮ нить. Длинные паузы переживаются, потому что нить —
это «последние N ходов С НИМ» (по свежести-с-ним, не по календарю), плюс recall старых колбэков (для
non-owner — **скопленный по персоне**). Реюз BOB-019 (`Interlocutor.sender_id`), BOB-044 (окно/реплей),
recall.

## Атрибуция: `sender_id` в эпизодах

Сейчас эпизод хранит автора только в тексте (`content="{sender_name}: …\nbob: …"`). Добавляем структурный
ключ.

- **Схема (`episodic_log`):** новая колонка `sender_id INTEGER NULL`. 🔴 `CREATE TABLE IF NOT EXISTS` не
  меняет существующую таблицу → **миграция**: на старте `ALTER TABLE episodic_log ADD COLUMN sender_id
  INTEGER` идемпотентно (проверка через `PRAGMA table_info`, добавить если нет). Индекс
  `idx_episodic_sender (sender_id, ts)` для быстрого per-person по свежести.
- **Запись:** `_persist` пишет `event.sender_id` (есть в `MessageReceived`). Боб-ходы остаются в том же
  эпизоде (turn = «<user>: …\nbob: …»), `sender_id` = автор хода (собеседник).
- **Бэкафилл (best-effort, разовый на старте/миграции):** для строк с `sender_id IS NULL` сопоставить
  имя-префикс из `content` → известный `sender_id` (owner-имя → `owner_id`; allowlist-имена → их id, если
  резолвятся). Несопоставленные остаются `NULL` (не реплеятся персонально — деградация мягкая). Бэкафилл
  идемпотентный, не деструктивный.

## Read-шов: нить по персоне

Новый метод репозитория (расширяет `EpisodeReader`):

```
async def recent_episodes_for(sender_id: int, k: int) -> Sequence[Mapping]:
    # последние k эпизодов, где sender_id = <персона>, по свежести, в хронологии (oldest-first)
    # — как recent_episodes, но с фильтром WHERE sender_id = ?
```

`recent_episodes` (глобальный) остаётся (для возможного owner-режима / совместимости).

## Поведение в `handle_message`

Заменяем grubo `[] if is_guest` на **персональную выборку по `interlocutor.sender_id`**:

- **История (replay):** `recent_episodes_for(interlocutor.sender_id, self._recent_turns)` для ЛЮБОГО
  собеседника с известным `sender_id` (owner / known / guest). Нет `sender_id` (нет seam идентичности) →
  деградация на текущее поведение (owner global / guest пусто). Окно — тот же `dialogue.recent_turns`.
  - Для **owner** это его личная нить (в чате, где в основном owner ↔ Боб, ≈ прежнее поведение, но чище
    при мульти-парти). Симметрично и человечно.
- **Recall (🔴 приват):**
  - **owner** — recall глобальный, как сейчас (owner доверен, видит всё своё).
  - **non-owner (known/guest)** — recall **скоплен по персоне**: результаты пост-фильтруются по
    `sender_id == interlocutor.sender_id` (recalled-проекция несёт `sender_id`), чтобы НИКОГДА не всплыло
    owner-приватное / чужая нить. Факты owner'а (приватная семантическая память) для гостя недоступны.
  - `recalled_excluding_reflections` (BOB-033) остаётся поверх.
- **Прочие гостевые ограничения СОХРАНЯЮТСЯ** (не ослабляем authz): без capabilities/tool-loop, без
  grounded owner inner-life (leak/callback/fascination), **гостевой ход не пишется в owner-факты**.
  Меняется только: гость получает СВОЮ эпизодическую нить + свой персональный recall.

## Длинные паузы

- Нить = «последние N ходов С ЭТИМ человеком» → ночь/день паузы не теряют тему (выборка по свежести-с-ним,
  не по календарю). + персональный recall старых колбэков.
- **Опц. текстура «давно не виделись»:** маркер времени с последнего хода персоны (из её последнего
  эпизода) → если разрыв > порога, в compose-контекст добавляется лёгкая подсказка («не виделись с …»),
  чтобы Боб отметил паузу по-человечески (не механически — подсказка, не скрипт фразы). Конфиг
  `dialogue.absence_hint_hours` (опц., default off или ~8ч).

## Слои (DDD)

- **domain:** чистая логика отбора персональной нити (если нужна — напр. вычисление «давно не виделись» из
  ts); инвариант приватности формулируется тестируемо.
- **application (`handle_message`):** оркестрация — выбрать per-person историю + scoped recall по
  `interlocutor`, собрать контекст. Никаких новых I/O кроме read-шва.
- **infrastructure (`sqlite_repo`):** миграция колонки + индекс, `recent_episodes_for`, бэкафилл,
  `sender_id` в recalled-проекции.

## Инвариант приватности (как обеспечивается)

🔴 **Non-owner никогда не видит чужую/owner-приватную память.** Обеспечено в ДВУХ местах (defense-in-depth):
история — фильтр `sender_id` в запросе; recall — пост-фильтр по `sender_id` для non-owner. Тест-инвариант:
при guest-собеседнике в собранном контексте нет ни одного эпизода/recall с чужим `sender_id`.

## Риски и митигации

- **Бэкафилл неточен** (тёзки/переименования) → best-effort, несопоставленные `NULL`; новые ходы точны.
  Не критично (деградация = чуть меньше старой истории у персоны).
- **Миграция на живой БД** → идемпотентный `ALTER ADD COLUMN` + `PRAGMA` проверка; бэкап перед прогоном.
- **Recalled-проекция без `sender_id`** → добавить `sender_id` в выборку recall (или пост-фильтр по
  эпизод-источнику); тест на отсутствие чужого `sender_id`.
- **Owner-поведение** — переключение на per-person не должно регрессировать owner-диалог; тест: в
  owner-доминантном чате нить эквивалентна; мульти-парти — owner видит свою нить (cross-person — вне объёма).

## Открытые решения (под утверждение)

1. **Owner-режим replay:** per-person (его нить, симметрично/чисто) — **рекомендую**; альтернатива —
   оставить owner на глобальном окне (меньше изменений, но асимметрично). Рекомендую per-person.
2. **Персональный recall для non-owner:** пост-фильтр результатов по `sender_id` — **рекомендую** (просто,
   безопасно). Глубокий персональный семантический recall (отдельный индекс) — вне v1.
3. **«Давно не виделись»:** включить опц. маркер (default ~8ч) — **рекомендую лёгкую версию**.
