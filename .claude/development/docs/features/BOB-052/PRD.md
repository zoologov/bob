# PRD: BOB-052 — «Разрешение на привилегированное»

> **Status:** Approved
> **Created:** 2026-06-30
> **Feature:** BOB-052 · Тир-1 «Личность» / безопасность · преемник BOB-051 · эпик `bob-052`

---

## Контекст

BOB-051 сделал память группы публичной, но **привилегии остаются гейтом**: инструменты/capabilities
(интроспекция репо, чтение кода, beadloom/bd, render, кодинг), **внутрянка** Боба (inner-life/приватные
рефлексии), owner-данные/команды. Сейчас не-авторизованный участник просто **молча не получает** (tool-loop
не запускается) — грубо и не по-человечески. Решено с owner: доступ к привилегированному = **«моё
разрешение ИЛИ авторизованный пользователь (allowlist)»**.

## Проблема

Норман (не-авторизованный участник) просит привилегированное («покажи задачи проекта», «запусти X», «что у
тебя в коде») → Боб либо молчит, либо отвечает общими словами — а по-человечески он должен **спросить
хозяина**: «Вова, Норман просит — показать?». Сейчас этого механизма нет.

## Цель

Когда **не-авторизованный** участник просит привилегированное (инструмент/внутрянка/owner-данные), Боб
**спрашивает owner разрешение**, а не молчит и не делает сам. Owner да/нет → Боб исполняет для этого
запроса или вежливо отказывает. **Авторизованные** (allowlist) — доступ как сейчас, без спроса. Это
по-канону: Боб — партнёр, который сверяется с хозяином перед раскрытием привилегированного.

## Пользовательские истории

- **US-1 (запрос → спросить owner).** Норман просит «покажи задачи проекта» (нужна интроспекция) → Боб:
  «Вова, Норман просит показать задачи — разрешить?» (не молчит, не делает сам).
- **US-2 (owner разрешил → исполнить).** Owner: «да» → Боб выполняет запрос для Нормана (инфо/инструмент).
- **US-3 (owner отказал → мягкий отказ).** Owner: «нет» → Боб Норману: «спросил Вову — пока не могу».
- **US-4 (авторизованный — без спроса).** Allowlisted-пользователь просит то же → Боб делает сразу (как
  сейчас), без разрешения.
- **US-5 (durable грант).** Owner может вместо разового «да» **авторизовать** Нормана («авторизуй Нормана»)
  → дальше Норман как allowlisted (через `Authorizer.authorize`).
- **US-6 (🔴 только owner; внутрянка/приват защищены).** Разрешение даёт ТОЛЬКО owner (`is_owner`).
  Внутрянка (inner-life) и owner-приват не раскрываются без явного разрешения. Сбой флоу не ломает обычные
  ответы Боба (принцип «полный Боб»).

## Критерии успеха

- Не-авторизованный запрос привилегированного → Боб спрашивает owner (не молчит/не делает сам); owner
  да→исполнить, нет→мягкий отказ; авторизованные — без спроса.
- Owner может дать разовое разрешение ИЛИ авторизовать (durable).
- **🔴 Только owner решает**; внутрянка/owner-приват не утекают без разрешения; сбой не ломает ответы.

## Объём

**В объёме:**
- **Детект привилегированного запроса** от не-авторизованного (требует инструмента/внутрянки/owner-данных)
  — семантически (судья, в духе BOB-049) и/или структурно (запрос мапится на capability).
- **Pending permission-request** состояние (как coding-сессия BOB-039): кто, что просит, статус.
- **Уведомить owner + approve/deny** (NL «да/нет» или команда `/allow`/`/deny`).
- **Грант:** per-request (разово исполнить) ИЛИ durable (`Authorizer.authorize` — в allowlist).
- **Исполнение на approve** (запрос с привилегией для этого запроса) / **мягкий отказ на deny**.
- Отказоустойчивость: сбой детекта/флоу → не ломает обычные ответы (декоративно поверх обычного пути).

**Вне объёма:**
- Личка/DM-приват Боба (будущее).
- Тонкая гранулярность прав (per-capability scopes) сверх «привилегированное да/нет».
- Авто-разрешение по правилам без owner (нет — только owner решает).

## Связи и принципы

- Преемник **BOB-051** (память публична / привилегии гейт). Реюз **Authorizer** (BOB-019),
  capability registry/tool-loop (BOB-002), паттерн **approve** (BOB-039 coding / self-improvement),
  per-person нить (BOB-045/051), принцип «полный Боб или GUPPI-нотис» (BOB-049). Канон: Боб сверяется с
  хозяином. Север: `bob-social-identity-strangers`, `bob-post-p0-plan` (authz-before-autonomy).
