# PRD: BOB-054 — «Прочитать ссылку» (`read_url`)

> **Status:** Approved
> **Created:** 2026-07-01
> **Feature:** BOB-054 · Тир-1/2 · навык за capability-швом (BOB-002) · гейт authz (BOB-052) · fast-follow BOB-053

---

## Контекст

BOB-053 дал Бобу `web_search` — искать в вебе по теме. Но это не то же, что **«кинул ссылку → Боб открыл,
прочитал, высказал мнение»**. `web_search` ищет по запросу; он НЕ читает конкретный URL, который прислал
пользователь. По-человечески компаньон, которому кидают ссылку, должен пойти, прочитать её и
отреагировать — как мы, когда нам скидывают статью «глянь, что думаешь».

Это отдельный навык `read_url`: HTTP GET конкретной страницы → извлечь читаемый текст → Боб комментирует
своим голосом. Тот же capability-шов, что и `web_search`. Фундамент и под будущий `web_research`
(многошаговое расследование дочитывает страницы этим же навыком).

## Проблема

Пользователь кидает ссылку («вот статья / пост, что скажешь?») → сейчас Боб её **не открывает**: у него нет
навыка прочитать конкретный URL. Он может лишь порассуждать по самому тексту сообщения, но не по содержимому
страницы. Нужно: Боб открывает ссылку, читает и реагирует по существу.

## Цель

Дать Бобу навык **`read_url`**: на присланную ссылку (или когда сам решает открыть URL) Боб **читает
страницу** и отвечает **своим голосом по существу содержимого**. За capability-швом (BOB-002), исполнение
GUPPI/tool-loop, **гейт authz** (owner/allowlist — сразу; не-авторизованный → BOB-052). Обычные
статьи/блоги/доки — бесплатно, без ключа. 🔴 X.com/твиты — **вне объёма v1** (официальный free-tier X API
закрыт с фев-2026, чтение платное; будет опциональным платным плагином позже).

## Пользовательские истории

- **US-1 (кинул ссылку → мнение).** Owner: «вот статья <url> — что думаешь?» → Боб открывает, читает,
  отвечает по существу своим голосом (не «не могу открыть»).
- **US-2 (Боб сам решает открыть).** В сообщении есть URL, релевантный разговору → Боб сам выбирает навык
  `read_url` (через tool-loop), чтобы прочитать, прежде чем отвечать.
- **US-3 (синтез по содержимому).** Боб отвечает **по прочитанному** (пересказ/оценка/мнение), а не сыплет
  сырой HTML/текст страницы.
- **US-4 (authz-гейт).** Не-авторизованный участник просит открыть ссылку → BOB-052 (спросить owner), как
  для любого привилегированного навыка. Owner/allowlist — без спроса.
- **US-5 (🔴 честный отказ, без выдумки).** Страница недоступна / логин-волл (в т.ч. X) / не читается →
  Боб честно говорит «не смог открыть/прочитать эту ссылку», НЕ выдумывает содержимое (принцип «полный
  Боб или честный GUPPI-нотис»).
- **US-6 (🔴 безопасность доступа).** Боб не должен по присланной ссылке лезть во внутреннюю сеть/локалхост/
  облачные метаданные (SSRF): только публичный веб (http/https), приватные/loopback/link-local адреса
  заблокированы.

## Критерии успеха

- Присланный URL (обычная страница) → Боб читает и отвечает по существу своим голосом.
- Боб **сам** выбирает навык, когда в разговоре появляется релевантная ссылка (tool-loop).
- Гейт authz: owner/allowlist — сразу; не-авторизованный → BOB-052.
- 🔴 Недоступно/не читается → честный отказ без выдумки содержимого; диалог не ломается.
- 🔴 SSRF-защита: приватные/loopback/link-local/не-http(s) — заблокированы.

## Объём

**В объёме:**
- **Навык `read_url`** за capability-швом (`make_read_url_capability`, регистрация в `CapabilityRegistry`,
  исполнение через `ToolLoop`/GUPPI).
- **Читатель страниц** (infrastructure): HTTP(S) GET → извлечь **читаемый основной текст** (без nav/скриптов/
  рекламы) + заголовок; порт в domain, реализация в infrastructure.
- **Синтез по содержимому** в голосе Боба; защита от сырого дампа.
- **🔴 SSRF-защита + лимиты:** только http/https, блок приватных/loopback/link-local IP, лимит размера,
  таймаут, ограничение редиректов, user-agent.
- **Гейт authz** (реюз Authorizer/BOB-052) — навык привилегированный.
- Отказоустойчивость: сбой/недоступно/логин-волл → честный отказ (без выдумки).

**Вне объёма:**
- **X.com/твиты** — free-tier X API закрыт (pay-per-use ~$0.005/чтение с фев-2026). Опциональный платный
  плагин-источник позже (за тем же портом); v1 на X честно отвечает «не смог прочитать».
- JS-рендеринг SPA (headless-браузер) — v1 читает статичный HTML; тяжёлый рендер позже при нужде.
- PDF/медиа/скачивание файлов — только веб-страницы (HTML/текст) в v1.
- `web_research` (многошаговое расследование поверх `read_url`+`web_search`) — отдельно, ROADMAP T2.3.
- Кэш прочитанных страниц — по нужде позже.
