## Порядок исполнения

1. Создать эпик-беады (родитель `BOB-062` [epic] + `.1..8`), связать цепочкой `bd dep add`.
2. Для среза `.1 coding`: отдельный `/task-init` (feature/CONTEXT+PLAN) → координатор (dev→test→review→
   tech-writer) → PR → owner «мержи» → рестарт `./bob` (по желанию). Это **валидирует всю схему**
   (структура модуля, layer-теги, правила границ, доки-в-срезе) до массового применения.
3. По зелёному .1 — owner утверждает старт .2, и так далее по цепочке.

## Волны внутри среза (типовые, задаются в мини-PLAN среза)

- Волна 0 (dev): `git mv` + переписать импорты + перецелить узел графа + `# beadloom:layer=` теги.
- Волна 1 (dev): наполнить SPEC/DOC модуля.
- Волна 2 (test): полный `pytest` (поведение идентично) + чек-лист инвариантов + `beadloom ci`.
- Волна 3 (review): корректность переезда, границы/слои, поведение неизменно, доки честны.
- Волна 4 (tech-writer): финализ доков + закрыть issue среза.
