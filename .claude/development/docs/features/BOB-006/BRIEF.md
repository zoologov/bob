# BRIEF: BOB-006 — Чат-производительность: флуд-контроль + гибридный тиринг модели

> **Status:** Approved
> **Created:** 2026-06-19
> **Type:** feature

---

## Проблема

Live: Боб ожил, но второй (длинный) ответ полз ~6 минут. Два узких места:

1. **Telegram Flood Control:** `WARNING gateway: rich final failed; falling back to plain: Flood control
   exceeded on method 'SendRichMessage'. Retry in 38 seconds.` — живой edit-стриминг + rich-финал + два
   ответа подряд = слишком много запросов к Telegram; троттл edit'ов недостаточно агрессивный.
2. **Tier 1 (qwen3.7-plus) медленный:** recall `17:47:05` → ответ `17:53:09` ≈ **6 минут** на длинный
   ответ. reasoning-модель тяжела для живого чата (даже с `disable_thinking`).

Живая печать (Вариант B) подтверждена рабочей — это **тюнинг скорости**, не корректность.

## Решение (согласовано с owner 2026-06-19)

1. **Флуд-контроль (gateway):** троттл edit'ов **≥ ~2.5–3с** между правками (в группе); пропускать
   no-op edit'ы; не частить rich-финалом (одна попытка, уважая `RetryAfter` через существующий backoff;
   при флуде — деградация на плейсхолдер-plain, без спама). Цель: при обычной переписке флуд-контроль
   не срабатывает.
2. **Гибридный тиринг модели ответов (router):** селектор модели ответа —
   - **casual/короткое** → `qwen3.6-flash` (быстро, секунды) — **дефолт** ради отзывчивости;
   - **сложное/длинное/нужны инструменты** → `qwen3.7-plus` (глубина).
   - Решение по **эвристике на сообщении пользователя** (длина, мульти-вопрос, сигналы «объясни/
     проанализируй/сравни/напиши код/подробно», код, явный запрос глубины). Без лишнего round-trip;
     (опц. позже — Tier 0 классификатор для неоднозначных).
