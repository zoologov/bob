# RFC: BOB-019 — «Свои и чужие» (социальная идентичность · T1.4)

> **Status:** Approved
> **Created:** 2026-06-23

---

## Обзор

Вводим **два слоя** поверх готовой инфраструктуры: **authz** (доступ к возможностям — без изменений) и
новый **социальный слой** (личность). Ключевая абстракция — **`Interlocutor`** (кто говорит: owner / known
/ guest / bot + уровень доверия), вычисляется из `Authorizer` + `sender_id`/`sender_name` (event их уже
несёт). Сейчас неавторизованный в топике Боба → GUPPI hard-reject; меняем: **гость (неавторизован, но в
разрешённом чате)** → **социальный путь Боба** (поговорить как человек) — но **без инструментов и без
приватной памяти owner**. Чужой чат → по-прежнему жёсткий дроп (chat-scope не трогаем). Всё «как характер».

## Технический контекст

### Ограничения
- Python 3.12+, DDD/Clean (домен чист), инъекция `Clock`/портов, TDD на фейках, `mypy --strict`, `ruff`,
  cov ≥80%.
- **Безопасность — инвариант:** гость НЕ вызывает capability (нет tool-loop) и НЕ видит приватную память
  owner; chat-scope и owner/allowlist-доступ к возможностям не меняются; промоушен только через `/authorize`.
- Не ломать: реактив/проактив/память/личность owner, тиринг, существующий authz-reject вне разрешённого чата.

### Затрагиваемые области
`domain/personality/interlocutor.py` (new — модель + классификация), `application/authz/authorizer.py`
(траст-уровень/хелпер), `infrastructure/telegram/multibot.py` (роут гостя → Боб-соц вместо hard-reject),
`application/usecases/handle_message.py` (guest-режим: без tools, redaction; восприятие отправителя),
`domain/personality/voice.py` (директива встречи незнакомца), `infrastructure/persistence` (лёгкий
per-sender first-impression стор), `domain/ports.py`, `app.py`, `config`.

## Предлагаемое решение

### Абстракция «собеседник»
- **`domain/personality/interlocutor.py`** (чистый): `Interlocutor(identity, kind, trust)` где
  `kind ∈ {OWNER, KNOWN, GUEST, BOT}` (бот — отдельный вид, под будущий BobNet), `trust ∈ {TRUSTED, GUEST}`.
  Чистая классификация `classify(sender_id, sender_name, *, is_owner, is_authorized, is_bot) -> Interlocutor`.
  Покрывает людей И ботов (готовность к bot-to-bot; реального транспорта нет).

### (1) Восприятие отправителя
- `sender_id`/`sender_name` (уже на `MessageReceived`) → `Interlocutor` → в compose-контекст: Боб знает,
  **кто** пишет (owner по имени; известный/незнакомец). Owner узнаётся как owner.

### (2) Гость: роут + ограниченный соц.-путь (ядро безопасности)
- **multibot:** неавторизованный отправитель **в разрешённом чате и топике Боба** → вместо GUPPI hard-reject
  идёт в **Боб-соц-путь** (guest). Вне разрешённого чата / прочее — как сейчас (дроп/reject). _Q1._
- **handle_message guest-режим:** компоновка **БЕЗ tool-loop** (нет `ToolCallingProvider`, нет манифеста
  capability), **БЕЗ recall приватной памяти owner** (redaction по аудитории — гостю не отдаём owner-память),
  обычный текст-ответ. Боб может поговорить, но «гостевой» ≠ «доверенный».
- **Директива встречи незнакомца** (`voice.stranger_directive()`, как характер): «незнакомый человек —
  решай по себе: поздороваться / держаться настороже / вежливо отшить / уточнить у владельца; не раскрывай
  личное владельца». Боб отыгрывает это в ответе.

### (3) First-impression на человека
- Лёгкий **per-sender стор** (`sender_id → {first_seen_at, impression?}`): узнан/незнаком; первая заметка.
  Минимум — основа для multi-party RelationshipTracker (BOB-014), не он сам. _Q4._

### Промоушен и редакция
- Промоушен гость→доверенный — существующий owner-команд `/authorize <user_id>` (GUPPI), без изменений.
- **Редакция по аудитории:** при не-owner отправителе/аудитории Боб не включает приватную память owner в
  контекст (guest-режим уже это обеспечивает).

## Guardrails / безопасность (под тестами)
- Гость: **ноль** вызовов capability (tool-loop не запускается), **ноль** owner-приватной памяти в контексте.
- chat-scope и доступ owner/allowlist к возможностям — без регрессий (контрактные тесты authz целы).
- Промоушен — только через `/authorize`; гость сам себя не повышает.
- Соц.-реакция — «как характер», не «программно»; не грубит без причины, но может держаться настороже.

## Рассмотренные альтернативы
- **Оставить hard-reject** — отвергнуто: негуманно (друг в группе игнорируется глухой стеной).
- **Пускать гостя в полный пайплайн** — отвергнуто: дыра (доступ к памяти owner/инструментам). Только соц.-слой.
- **Полный RelationshipTracker сейчас** — отвергнуто: это BOB-014; тут лёгкая заметка.
- **Реальный bot-to-bot транспорт** — отвергнуто: только абстракция «собеседник»; обмен ботов — Bobiverse P2.

## Риски
| Риск | Вер. | Влияние | Митигация |
|---|---|---|---|
| Гость дотянется до памяти owner/инструментов | Low | **High** | guest-режим без tools + без owner-recall; ревью+тесты на инвариант |
| Регрессия authz (свои перестали работать) | Low | High | Контрактные тесты authz; trust-классификация поверх, не вместо |
| Боб груб/наивен с незнакомцем | Med | Low | Директива «как характер» (настороже, но вежливо); first-impression |
| Спам от чужих в группе | Low | Med | Соц.-ответ по governance (как анти-тик); owner может не /authorize |

| Q1 | Кого считать «гостем» | Неавторизован + в разрешённом чате + топик Боба; вне чата — дроп как сейчас |
| Q2 | Решение «отвечать/молчать/спросить owner» | v1: соц.-ответ как характер (может уточнить у owner в тексте); жёсткого молчания-гейта не делаем |
