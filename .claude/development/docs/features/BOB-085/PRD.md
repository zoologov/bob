# PRD — UX интерактив-терминала: полный вывод + rich-форматирование

## Проблема (живые прогоны `/code -i`)

Два UX-бага интерактивного терминала в личке (оба в `coding/stream_render.py`):
1. **Огрызки (BOB-Issues #36):** ответы claude режутся до **200 символов** (`_MAX_TEXT=200`) — owner
   просил «список багов с приоритетами», получал первые 200 символов. Кэп ставили для *краткого
   одностороннего* нарратива в группу (BOB-082), но он душит двусторонний терминал.
2. **Слабое форматирование (BOB-Issues #35):** рендер выдаёт плоскую прозу; отправитель умеет rich
   (`send_rich_message`: код-блоки/списки/моно), но форматировать нечего. Вывод claude сам markdown — мы
   его расплющиваем.

Приватный чат с ботом поддерживает то же rich-форматирование, что группа (Bot API MarkdownV2/HTML);
чанкинг под лимит 4096 уже есть (`PLAIN_TEXT_LIMIT`).

## Цель (стиль owner'а: **курированный чистый**)

Интерактив-терминал в личке — удобный, читаемый:
- **полный текст ответов claude** (суть), rich-рендер его markdown;
- **вызовы инструментов** — компактными форматированными строками;
- **длинные tool-результаты** (дампы файлов/тестов) — щедро капнуты в код-блоке (не полный дамп);
- **односторонний груп-нарратив (BOB-082) сохраняет краткий кэп** — режимы различаем.

## Сценарии (acceptance)

**S1 — Полный ответ (главный, BOB-Issues #36).**
- В `/code -i` owner: «дай список багов с приоритетами» → claude отвечает списком → Боб показывает
  **весь** ответ (rich: заголовки/список/`код`), при длине >4096 — чанкинг, не 200-символьный огрызок.

**S2 — Rich-форматирование (BOB-Issues #35).**
- Команды/код/пути — в код-блоках / `моноширинном`; markdown claude рендерится как markdown (не плоский
  текст); вызовы инструментов — компактные читаемые строки (✏️ правлю `path`, `$ команда`, 🔍 ищу «…»).

**S3 — Курирование (не шум).**
- Длинный tool-результат (дамп файла/вывод тестов) — щедро капнут в код-блоке с пометкой «…обрезано»,
  а не полный дамп на пол-экрана. Суть (assistant-текст) — целиком.

**S4 — Груп-нарратив не тронут.**
- Односторонний стрим кодера в группу (BOB-082, `dev_dm` OFF-путь) остаётся **кратким** (кэп сохранён) —
  различаем интерактив-DM (полный+rich) vs груп (краткий).

## Инварианты

- **INV-1 (Полный ответ).** В интерактив-DM текст ответа claude доходит целиком (без 200-символьного
  усечения), чанкинг под лимит Telegram.
- **INV-2 (Rich).** Вывод форматируется средствами Telegram (markdown/rich): assistant-markdown как
  markdown, код/команды в код-блоках, пути в `моно`.
- **INV-3 (Курирование).** Assistant-текст целиком; tool-результаты щедро капнуты; вызовы компактны.
- **INV-4 (Режимы различены).** Груп-нарратив (BOB-082) сохраняет краткий кэп — не регресс.

## Не входит в scope

- Изменение самого интерактив-механизма (stdin-мост, kill, authz — BOB-083 не трогаем).
- Двусторонность/безопасность (owner-only/DM-only/main — как есть).
- Богатый UI Mini-App (T3.H).
- Brevity-система личности Боба (обычные ответы Боба — отдельно; здесь только рендер claude-потока).
