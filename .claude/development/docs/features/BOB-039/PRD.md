# PRD: BOB-039 — T3.B «Боб запускает Claude Code» (гейтед, user-driven v1)

> **Status:** Approved
> **Created:** 2026-06-26
> **Feature:** BOB-039 (Тир-3 «Боб-кодер», поверх T3.A/T3.A⁺) · эпик `bob-039`

---

## Контекст

T3.A отгружен: Боб **знает свой мир** (читает код/архитектуру/задачи/roadmap) и **держит историю
решений** (T3.A⁺ `code_rationale`). Следующий шаг Тир-3 — Боб **сам делает работу** над своим репо
руками headless **Claude Code CLI** (локальный `claude` v2.1.191, подписка Tier-2), а owner
валидирует. Это воплощение личности+автономности **с обязательным гейтом согласования**.

## Проблема / цель

Сейчас Боб может предложить решение, но не может его **выполнить**. Цель v1: owner даёт Бобу
dev-задачу в Telegram → Боб **через Claude Code** делает её в **изолированном worktree**, **наррирует
ход** в чат, и проводит изменения **только через ветку+PR с двойным гейтом апрува** (план до
исполнения, мерж — owner). Боб становится партнёром, который реально пишет код, оставаясь под
контролем человека.

## 🔴 Безопасность и приватность (несгибаемые требования)

- **Изоляция воркспейса.** Claude Code работает в **отдельном git worktree** (своя директория, своя
  ветка). Личные данные Боба — `data/soul/`, `data/bob.db*`, `.env*`, `config/*` — **gitignored** и в
  свежем worktree их **физически нет** (проверено). → Claude Code не видит и не может утечь SOUL/
  память/секреты.
- **Только ветка+PR, НИКОГДА main.** Боб коммитит в `bob/<task>`-ветку и открывает PR. main —
  branch-protected; прямого пуша нет.
- **Двойной гейт апрува (человек-в-петле, не опция).** (1) **План** — Боб показывает план Claude Code
  и ждёт явного апрува owner ДО исполнения; (2) **Мерж** — Боб открывает PR, мержит **owner**
  (авто-мержа нет). Между гейтами — пауза, ждёт команды.
- **Owner-only (authz).** Навык запускает ТОЛЬКО owner; гость/чужой — отказ (как везде). Боб **не**
  кладёт навык в автономный `goals.safe_capabilities` (не самонаправленный в v1).
- **«Не API» = локальный `claude` на подписке** (Pro/Max), не платный Anthropic API.

## Пользовательские истории

- **US-1 (постановка).** Owner: «Боб, добавь health-эндпоинт» → Боб подтверждает задачу, создаёт
  изолированный worktree+ветку, формирует план через Claude Code.
- **US-2 (гейт плана).** Боб присылает **план** (что Claude Code собирается сделать) → ждёт «апрув»/
  «правь так-то». Без апрува — НЕ исполняет.
- **US-3 (исполнение + нарратив).** После апрува Claude Code работает в worktree; Боб **наррирует
  ключевые события** (правит файл X, гоняет тесты, тесты зелёные, готово) — не сырой stream-json.
- **US-4 (гейт мержа).** Боб коммитит в ветку, открывает PR, показывает diff/итог → owner ревьюит и
  **сам мержит**. Боб никогда не мержит и не пушит в main.
- **US-5 (приватность).** Claude Code в worktree не имеет доступа к SOUL/`bob.db`/`.env`/`config` —
  их там нет; ничего личного не уходит в облако сверх кода задачи.
- **US-6 (контроль/стоп).** Owner может **остановить** прогон (kill-switch) в любой момент; гость не
  управляет; ошибка/таймаут — честный отчёт, без зависания.

## Критерии успеха

- Owner ставит задачу → Боб через Claude Code делает её в изолированном worktree, наррирует, открывает
  **PR в ветку** (US-1..4); **никогда** не трогает main и не мержит сам.
- **Двойной гейт** соблюдён: без апрува плана нет исполнения; без owner нет мержа.
- **Приват-инвариант:** Claude Code не видит личные данные Боба (их нет в worktree); owner-only;
  навык не в автономном safe-allowlist (US-5/owner-only).
- Стоп/таймаут/ошибка — корректны (US-6); без регрессий T3.A/диалога/authz; зелёный CI.

## Объём

**В объёме (v1, user-driven):** навык `claude_code` за GUPPI (owner-only); создание/уборка
изолированного worktree+ветки; запуск headless `claude -p … stream-json` в worktree; парсинг
stream-json → **нарратив** в Telegram; **гейт плана** (план → апрув owner → исполнение); коммит в
ветку + **открытие PR** (gh) + **гейт мержа** (owner мержит); owner-команды (старт/апрув/стоп);
конфиг (`coder.*`); таймаут/обрезка/честные ошибки.

**Вне объёма:** **self-proposed** задачи из Goal Engine (T3.C — Боб сам предлагает работу);
авто-мерж/мерж Ботом; работа вне worktree/в main; многоволновая live-оркестрация (T3.C); правки
вне репо. Эти — следующие фазы.

## Связи и принципы
