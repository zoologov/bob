# RFC: BOB-003 — GUPPI-бот (мульти-бот gateway) + topic-scope

> **Status:** Approved
> **Created:** 2026-06-19

---

## Обзор

Один процесс держит **два aiogram-бота** (Боб + GUPPI) за общим Dispatcher; центральный роутер
диспатчит апдейты по **identity + scope**: GUPPI (в General) — authz-привратник + owner-команды; Боб
(в своём топике) — персона. Авторизация переносится из gateway BOB-002 под идентичность GUPPI; отказ
неавторизованным теперь **видимый** («не авторизован» от GUPPI), Боб при этом не вызывается. Шов
forward-compatible под будущих ботов-реплик (Bobiverse).

## Мотивация

См. PRD. Технически: дать GUPPI идентичность (системный/админ-бот), Боба запереть в его топике, и
заложить **мульти-бот шов** — добавление реплики = регистрация бота, без переписывания композиции.

## Технический контекст

### Ограничения
- Python 3.12+, asyncio, DDD (`infrastructure → application → domain`), `uv`, `mypy --strict`, `ruff`,
  покрытие ≥80%, TDD. Секреты только из env. Тесты на фейк-ботах (без сети).
- **aiogram** один Dispatcher умеет поллить **несколько Bot-инстансов**; identity бота доступна в
  хендлере (`bot`/`bot.id`). Опираемся на резилентность BOB-002 (изоляция).
- Текущий `infrastructure/telegram/gateway.py` — один бот за портом `ReplyStreamer`/EventBus + Authorizer-гейт.

### Затрагиваемые области
`infrastructure/telegram/*` (мульти-бот gateway + GUPPI-handlers + topic-фильтр + thread-reply),
`infrastructure/config/*` (два токена, `topic_id`, реструктуризация `telegram`-секции), `application/authz`
(перенос enforcement в мульти-бот роутер + reject-via-GUPPI; owner-команды), `app.py` (сборка двух ботов).

## Предлагаемое решение

### Мульти-бот gateway (шов)
- **`BotRegistry`** — регистрация бота: `{identity, token, handlers, scope}`. Регистрируем Боба и GUPPI.
  Добавить реплику = ещё одна регистрация (forward-compatible).
- **Один Dispatcher** поллит оба бота; **центральный роутер** получает `(update, bot_identity)`.
- **Кросс-бот дедуп:** одно групповое сообщение может прийти на оба бота (privacy off) → дедуп по
  `(chat_id, message_id)`, обрабатываем **один раз** (не зависит от того, какой бот доставил).
- **Изоляция:** падение/реконнект одного бота не валит другой.

### Маршрутизация (центральный роутер)
Для каждого входящего (после дедупа):
1. **Топик Боба + авторизован** → пайплайн Боба → ответ **ботом-Бобом** в его тред.
2. **Топик Боба + НЕ авторизован** → **GUPPI** шлёт «⛔ Пользователь не авторизован» в тот же тред; **пайплайн
   Боба не запускается**.
3. **General + owner-команда** (`/authorize`, `/status`, опц. `/deauthorize`) → обрабатывает **GUPPI** (только owner).
4. **Остальное** (другие топики, чужие чаты, DM от незнакомца) → **молча игнор** (без раскрытия).

### GUPPI-бот (минимум)
- Идентичность системного/админ-бота, живёт в General. Владеет authz (гейт + reject) и owner-командами.
  Reject — видимый в группе; на DM незнакомца — молчим (безопасность).
- Использует существующий `Authorizer` (owner/allowed_chats/allowlist) + `KvAllowlistStore` (BOB-002).
  `/authorize <user_id>` пишет в allowlist (персист).

### Topic-scope (Боб)
- Хендлер Боба обрабатывает только апдейты с `chat_id == bob.chat_id` И `message_thread_id == bob.topic_id`
  (`=32`); General и прочие топики игнорит.
- Отправка Боба (`ReplyStreamer` / rich-send) проставляет `message_thread_id = bob.topic_id` → ответы в его тред.

### Конфиг (два бота)
- `telegram.bob.token` (env `BOB_TELEGRAM__TOKEN`, как сейчас) + `telegram.guppi.token`
  (env `GUPPI_TELEGRAM__TOKEN`, уже добавлен; **нестандартный префикс — лоадер маппит явно**).
- `telegram.chat_id = -1004372947307`, `telegram.bob.topic_id = 32`, `telegram.owner_id = 27468732`,
  `telegram.allowed_chat_ids`. General — это тред без `message_thread_id` (служебный).

## Рассмотренные альтернативы
- **Два процесса/сервиса** (Боб и GUPPI отдельно) — отвергнуто: один процесс проще (общие DB/память/
  heartbeat/registry), aiogram нативно поллит несколько ботов. (Подтверждено в PRD.)
- **GUPPI как «голос» бота-Боба** (без отдельного токена) — отвергнуто: нужна отдельная идентичность.
- **Молчаливый отказ (как BOB-002)** — изменено: GUPPI отвечает «не авторизован» в группе; на DM
  незнакомца — молчим (без раскрытия). Reject видим только в разрешённой группе.
- **Полная GUPPI-консоль сразу** (спавн реплик/логи/bot-to-bot) — отвергнуто: фиксируем шов, наполняем минимально.

## Риски

| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Специфика aiogram мульти-бот поллинга | Med | Med | `BotRegistry`-абстракция; тесты на фейк-ботах; ранняя проверка API |
| Двойная обработка (оба бота видят сообщение) | Med | Med | Кросс-бот дедуп по `(chat_id, message_id)` |
| Privacy mode: боты не видят сообщения группы | Med | High | Операционно: BotFather `/setprivacy disable` ИЛИ боты-админы; задокументировать в ACTIVE/доках |
| Reject раскрывает ботов чужим | Low | Low | Reject только в разрешённой группе; DM незнакомца — молчим |
| Нестандартный env-префикс GUPPI токена | Low | Med | Явный маппинг в лоадере + тест |

## Открытые вопросы

| # | Вопрос | Решение |
|---|--------|---------|
| Q1 | aiogram мульти-бот | **Decided:** один Dispatcher + N Bot за `BotRegistry`; ранняя проверка API |
| Q2 | Дедуп между ботами | **Decided:** по `(chat_id, message_id)`, обработка один раз |
| Q3 | Видимый reject vs молчание | **Decided:** видимый «не авторизован» от GUPPI в группе; DM незнакомца — молчим |
| Q4 | Privacy mode ботов | Операционно (setprivacy disable / админ) — задокументировать, не код |
| Q5 | GUPPI токен из `GUPPI_TELEGRAM__TOKEN` | **Decided:** явный маппинг в лоадере (нестандартный префикс) |
