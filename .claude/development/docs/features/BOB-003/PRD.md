# PRD: BOB-003 — GUPPI-бот (мульти-бот gateway) + topic-scope

> **Status:** Approved
> **Created:** 2026-06-19

---

## Проблема

После BOB-002 Боб — **один бот**, отвечает в любом разрешённом чате (authz по chat-scope), а отказ
неавторизованным — **молчаливый**. Для нужной конфигурации не хватает двух вещей:

1. **Нет topic-awareness.** В supergroup с топиками Боб отвечал бы в **General** (служебный топик), а не
   в своём. Нужно: Боб живёт **только в своём топике** (`thread_id=32`), General — служебный.
2. **У GUPPI нет лица.** GUPPI — детерминированный backend без идентичности. Хотим **отдельного бота
   GUPPI**, который держит системный слой: гейт авторизации + ответ «⛔ Пользователь не авторизован»
   (Боб при этом **вообще не вызывается**), owner-команды; живёт в **General**. Это операционализирует
   GUPPI-как-control-plane и даёт **задел под Bobiverse** (GUPPI оркестрирует, реплики = боты,
   bot-to-bot).

## Влияние

GUPPI обретает идентичность (привратник/админ-консоль в General), Боб живёт в своём месте, и
закладывается **мульти-бот фундамент** для Bobiverse. Безопасность: GUPPI — явный привратник, Боб не
вызывается для чужих. Делаем **шов один раз** (как с capability), наполняем минимально, растим позже.

## Цели (измеримые)

- [ ] **Мульти-бот gateway:** процесс держит N ботов (бот-Боб + бот-GUPPI), роутит апдейты по identity к
      нужному обработчику. Стабильный шов (forward-compatible под будущих ботов-реплик).
- [ ] **GUPPI-бот (минимум):** живёт в General; владеет **authz** — гейт + ответ «⛔ Пользователь не
      авторизован» (**Боб не вызывается**); owner-команды (`/authorize`, `/status`). Перенос authz-логики
      BOB-002 под identity GUPPI.
- [ ] **Topic-scope:** Боб скоупится на свой топик (`telegram.bob.topic_id`); игнорит General и прочие
      топики; **отвечает в свой тред** (`message_thread_id` на отправке).
- [ ] **Конфиг:** два токена в `.env` (Боб + GUPPI); `chat_id`, топик Боба, General-топик GUPPI. Секреты
      только из env.

## Не-цели (вне BOB-003)

- **Богатый GUPPI-интерфейс** (спавн реплик, логи, дашборды, статусы задач) — эпик оркестрации позже.
- **Bot-to-bot** коммуникация Бобов↔GUPPI — позже (за тем же мульти-бот швом).
- **Несколько реплик/топиков Бобов** (Bill, Bender…) — Bobiverse позже; здесь только шов под это.
- Изменение персоны/навыков Боба; новые capabilities.

## Пользовательские истории

### US-1: Боб живёт в своём топике
**Как** owner, **я хочу**, чтобы Боб отвечал **только в своём топике** и писал ответы туда же,
**чтобы** General оставался служебным (под GUPPI).

**Критерии приёмки:**
- [ ] Сообщения вне топика Боба (General/другие топики) Боб **игнорирует**.
- [ ] Ответы Боба уходят в его тред (`message_thread_id`).

### US-2: GUPPI — привратник
**Как** owner, **я хочу**, чтобы неавторизованному отвечал **GUPPI** («не авторизован»), а Боб **не
вызывался**, **чтобы** доступ контролировал системный слой, а не персона.

**Критерии приёмки:**
- [ ] Неавторизованный `user_id` / запрещённый `chat_id`/топик → **GUPPI** отвечает «⛔ Пользователь не
      авторизован»; пайплайн Боба не запускается.
- [ ] (Безопасность) В приватной группе — отвечаем; на DM от незнакомца — молчим (без раскрытия).

### US-3: GUPPI — админ-консоль в General
**Как** owner, **я хочу** управлять доступом/статусом через GUPPI в General, **чтобы** служебное было
отделено от чата с Бобом.

**Критерии приёмки:**
- [ ] Owner-команды `/authorize <user_id>` (+ опц. `/deauthorize`, `/status`) обрабатывает **GUPPI** в
      General; только owner.

### US-4: Мульти-бот шов (фундамент)
**Как** разработчик, **я хочу** стабильный мульти-бот шов, **чтобы** добавить будущего бота-реплику =
зарегистрировать его, без переписывания gateway.

**Критерии приёмки:**
- [ ] Добавление бота = регистрация (identity + handlers + scope); потребители/композиция не переписываются.
- [ ] Падение/переподключение одного бота не валит остальных (изоляция, опирается на резилентность BOB-002).

## Критерии приёмки (общие)

- [ ] Мульти-бот gateway роутит по identity; Боб — в топике, GUPPI — в General.
- [ ] GUPPI отвечает «не авторизован» и не вызывает Боба; owner-команды только у GUPPI/owner.
- [ ] Боб игнорит вне-топиковые апдейты и отвечает в свой тред.
- [ ] Два токена из env; целевые id (chat/топик/owner) из config.
- [ ] Тесты ≥80%, `ruff`/`mypy --strict` чисто, `beadloom ci` зелёный; тесты на фейк-ботах (без сети).
