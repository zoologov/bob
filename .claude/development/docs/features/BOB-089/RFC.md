# RFC: BOB-089 — Боб работает под своей идентичностью, main недостижим по правам

> **Status:** Approved
> **Created:** 2026-08-05

---

## Что уже есть (разведка по коду и по факту)

- **Инфраструктура доступов готова** (руками owner'а + координатора): организация
  `bobiverse-dev`, приватный форк `bobiverse-dev/bob`, два GitHub App с ключами в
  `.secrets/*.pem` (0600, каталог в `.gitignore`), `app_id` и пути в `.env`.
- Негативный смоук координатора: токеном `Propose` попытки создать ветку / force-push в main /
  записать файл в апстрим — все три `403 Resource not accessible by integration`.
- Рабочее место сейчас создаётся в **linked worktree**: `coding_assistant.py:295`
  (`worktree.create`), `interactive/usecases/session.py:215` (эфемерный) и `:285/:394`
  (`workspace.ensure` — долгоживущий).
- Окружение спавна уже умеет дополняться: `push_guard.guarded_spawn_env(os.environ,
  active=…)` (`claude_runner.py:159`) — чистая функция, возвращает `None` при OFF, то есть
  «спавн без `env=`, байт-в-байт». Это **готовый шов** для изоляции.
- Порт `Worktree` реализуется `GitWorktree`; интерактив дополнительно знает узкий
  `PersistentWorkspace.ensure`.
- 🔴 В зависимостях **нет** PyJWT и cryptography. Координатор подписывал JWT через
  `openssl dgst -sha256 -sign` — рабочий путь без новых зависимостей.

## Решение

### 1. Рабочее место — КЛОН, а не linked worktree

Ядро беады. Linked worktree делит `.git`: refs, remotes, credentials. Значит любой барьер на
push обходится локальным `git update-ref refs/heads/main` — без сети и без кредов.

Новый адаптер рядом с `GitWorktree`, реализующий тот же порт (`create`/`remove`, и `ensure`
для долгоживущего места): вместо `git worktree add` он делает `git clone` во свой каталог.
Ключевые свойства:

- у клона **свой** `.git` — ref'ов основного репозитория в нём просто нет;
- единственный remote — **форк** Боба (апстрим не прописан вовсе: нечего пушить и нечего
  случайно перепутать);
- клонируется из **локального** пути (быстро, без сети), но remote после этого
  переписывается на форк — иначе `origin` указывал бы на рабочую копию owner'а;
- 🔴 приватность как у worktree: клон несёт только **трекнутые** файлы, поэтому `data/soul/`,
  `bob.db*`, `.env*`, `config/*`, `.secrets/` в него не попадают. Это надо доказать тестом,
  а не предположить: у `git clone` иные правила, чем у `worktree add`.

Выбор «свой адаптер под тем же портом» — чтобы use-case'ы (`CodingAssistant`,
`InteractiveSessionManager`) не знали, worktree это или клон: подмена происходит в
композиции по флагу.

### 2. Токены двух принципалов

Чистое ядро (mutation-цель): сборка JWT-claims и решение «токен ещё годен / пора обновить».
Транспорт и подпись — в адаптере.

- `work` (contents write на форк) — пуш ветки;
- `propose` (contents read + pull_requests write) — чтение апстрима, если понадобится;
- installation-токен живёт час → адаптер обновляет его **заранее** (с запасом), а не по факту
  `401`: сессия кодера бывает длиннее часа, и падение посреди работы обошлось бы дороже.
- 🔴 Токены и ключи **не логируются никогда** — ни в отладке, ни в сообщении об ошибке.
  Диагностика по типу ошибки и по `app_id`, но не по значению.

### 3. Изоляция окружения спавна

Расширяем существующий `guarded_spawn_env` (не заводим второй механизм):

- credential helper owner'а отключается (`GIT_CONFIG_GLOBAL` в контролируемый файл, пустой
  `credential.helper`), вместо него — helper с токеном Боба;
- `GIT_TERMINAL_PROMPT=0` — git не уходит в интерактивный запрос пароля, а честно падает;
- `GIT_ASKPASS` в никуда — то же для askpass-пути;
- существующий push-барьер `pushInsteadOf` **остаётся** как второй слой: он ненадёжен сам по
  себе (снимается изнутри), но в паре с отсутствием кредов делает обход бессмысленным.

### 4. Идентичность

`user.name = bob[ai]`, `user.email = <app-user-id>+bob-ai-work[bot]@users.noreply.github.com`
— 🔴 **локально в клоне** (`git -C <clone> config`), не глобально. Иначе коммиты owner'а в
основном репозитории начнут подписываться как `bob[ai]` — ровно та путаница идентичностей, от
которой уходим.

### 5. Ссылка на PR — голосом Боба

Чистая функция «ветка → URL» (`compare/main...bobiverse-dev:bob:<branch>?expand=1`) плюс
реплика в стиле соседних (`coding/session_voice.py`). Боб не притворяется, что открыл PR: он
говорит, что работа готова и лежит там, и даёт ссылку.

### 6. Флаг

`coder.isolated_clone` (default OFF). OFF → прежний linked worktree, прежний спавн,
байт-в-байт. Доказывать равенством (тип адаптера и его аргументы), не «похожестью».

## Риски

| Риск | Митигация |
|---|---|
| `git clone` тянет лишнее (гитигнорируемые данные Боба) | тест на настоящем git: перечислить содержимое клона и проверить отсутствие `data/`, `.env*`, `config/bob.yaml`, `.secrets/` |
| Клон каждой сессии дорог (репозиторий ~500 МБ в `.git`) | клонировать из локального пути + `--shared`/`--reference` или `--depth`, замерить и назвать цену; для долгоживущего места клон один |
| Токен истёк посреди длинной сессии | обновление заранее, с запасом; тест на «токен просрочен» |
| Изоляция сломает легитимный путь Боба | смоук: пуш ветки в форк работает; `commit_and_push` и открытие PR owner'ом не задеты |
| Ложное чувство защиты | 🔴 в итоге честно разделить: что невозможно СТРУКТУРНО (нет кредов, нет общего `.git`), а что осталось на доверии (модель внутри клона всё ещё делает что угодно с рабочим деревом) |

## Тестовая стратегия

- Чистые ядра (JWT-claims, годность токена, URL сравнения) — mutation ≥85% с честной оценкой
  силы гейта (§0.3 п.6: константы и enum mutmut не мутирует).
- 🔴 Негативный смоук **на настоящем git**: из клона с окружением Боба — `push` в апстрим,
  `update-ref refs/heads/main`, `remote set-url` + push. Каждая попытка падает по отсутствию
  доступа. Проверить на кусачесть: сломать изоляцию — тест обязан покраснеть.
- Позитивный смоук: пуш ветки в форк проходит.
- Тест приватности клона (см. риски).
- OFF-путь: равенство сборки.

## Порядок

1. Клон-адаптер + флаг + приватность (фундамент, проверяемо локально).
2. Токены двух принципалов.
3. Изоляция окружения + негативный смоук.
4. Идентичность + ссылка голосом Боба.

Такой порядок держит смоук как можно раньше: пока изоляция не доказана, остальное не имеет
смысла.
