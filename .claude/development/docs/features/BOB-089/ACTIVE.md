## 🔴 Волна 5, `bob-a6b.10` — ssh-дорога была ОТКРЫТА, закрыта наполовину и честно

**Дефект (воспроизведён самостоятельно, не по отчёту).** Изоляция среза C не касалась ssh
вовсе. Из ровно прод-окружения спавна: `ssh -T git@github.com` → `Hi zoologov! You've
successfully authenticated…`, `git ls-remote git@github.com:zoologov/bob.git` → `rc=0`
(`a58cbc3b4978`). То есть рядом с изолированным https жила полноправная дорога к апстриму
**ключом owner'а**: по ssh Боб предъявлял не свой installation-токен, и «нет права записи» к
этой дороге не относилось. Пример конфига вдобавок рекомендовал для `coder.fork_url` ssh.

**Закрыто (git-половина).** `GIT_SSH_COMMAND` + то же значение как `core.sshCommand` в
подменном global-конфиге (второй слой, живой после `env -u GIT_SSH_COMMAND`):
`ssh -F none -o IdentitiesOnly=yes -o IdentityAgent=none -o BatchMode=yes -o IdentityFile=<путь, которого нет>`.
Вживую: `git ls-remote` апстрима по ssh → `rc=128`, `Permission denied (publickey)`.

🔴 **Три находки на настоящем ssh 10.2 (без них мера была бы мнимой):**
1. `IdentitiesOnly=yes` **сам по себе не закрывает ничего** — «configured identity» включает
   ДЕФОЛТНЫЕ `~/.ssh/id_*`, и ssh по-прежнему здоровался как owner. Закрывает только **явно
   названный** `IdentityFile`.
2. `IdentityFile` — **многозначная** опция: ключ из `~/.ssh/config` **добавляется** к нашему
   (тот же класс ловушки, что `remote.origin.pushurl` в bob-5ao) → `-F none` несущий.
3. `HOME` подменять **бессмысленно**: `~` OpenSSH раскрывает по записи в **passwd**
   (`HOME=<пустой каталог> ssh -T git@github.com` здоровается как owner).
4. На настоящем git `core.sshCommand` оказался **сильнее** унаследованного `GIT_SSH` —
   поэтому файловый слой держит и без вычистки переменной.

🔴 **ЧТО НЕ ЗАКРЫТО (названо, а не спрятано).** Прямой вызов `ssh`/`scp` из спавна ключ
owner'а находит: он лежит на диске под тем же UID, а домашний каталог ssh переменной не
подменить. Итоговая формулировка: **сетевой путь закрыт по https и по git-over-ssh; ключ
owner'а остаётся достижим прямым `ssh`** — класс тот же, что у локального файлового пути, и
закрывает его та же мера, **раздельный UID (BOB-093)**. Ограничение зафиксировано
ИСПОЛНЯЕМО: `test_ssh_road_live_smoke.py::test_a_raw_ssh_from_the_isolated_environment_still_greets_the_owner`
утверждает, что прямой ssh ЗДОРОВАЕТСЯ, и покраснеет, когда ограничение снимут.

**Три места приведены к факту ВИДИМОЙ правкой** (прежняя формулировка цитируется и помечена
неверной): `docs/domains/identity/README.md`, докстринги `identity/spawn_isolation.py` и
`coding/push_guard.py`. Плюс `docs/domains/coding/README.md`, «честный итог» PRD и RFC §3.
`config/bob.example.yaml`: `coder.fork_url` теперь **https** (+ прямо сказано, что ssh вёл по
неизолированному транспорту и что прямой ssh всё равно открыт).

**Мутация с числами** (`identity.spawn_isolation`, 105 мутантов): 59 убито / 46 выжило сырых.
Мои функции: `controlled_ssh_command` 5/13 (все 8 выживших — мутанты ТЕКСТА отказа: `None`,
XX-обёртка, регистр), `isolation_env` 21/31 (все 10 выживших — тот же класс),
`isolation_config_pairs` 8/8. После поштучного триажа поведенческий счёт по моим функциям
**26/26 = 100%**: поведенческих выживших нет. Добить текстовые можно только ассертом на

## `pushurl` увозил ветку в апстрим

Факт ревьюера воспроизведён и закрыт, состав фикса выбран ПОПЫТКАМИ на настоящем git 2.49

**Что исполнялось в процессе Боба ДО фикса** (маркер-скрипты, а не рассуждение):
подложенные моделью `pre-commit` / `post-commit` / `pre-push`; `core.fsmonitor` (на `add`);

Боба всегда отдаёт git PIPE, не tty, а `commit` идёт с `-m`.

**Три слоя, каждый со своей причиной:**
1. **Пары в argv** — `hardened_git_argv` (`core.hooksPath=/dev/null`, `core.fsmonitor=false`,
   `commit.gpgSign=false`) на КАЖДОМ git-вызове Боба в чужом каталоге (оба адаптера рабочего

   от момента проверки. 🔴 Хуки — единственный вектор, которому конфиг вообще не нужен.
2. **Push ПО ЗНАЧЕНИЮ `fork_url`**, а не по имени remote'а. Форк не настроен → отказ по
   конфигурации, а не загадочная ошибка git.
3. **Отказ по незнакомому ключу локального конфига клона** — то, чего argv не закрывает
   вовсе: `filter.*.clean` исполняется при любых парах, `url.*.pushInsteadOf` перезаписывает
   адрес после разбора argv. 🔴 Проверка сделана ALLOW-списком, а не перечнем опасных ключей,
   потому что перечень обходится ДВУМЯ воспроизведёнными дорогами: `include.path` (ключи
   включённого файла `config --local --list` НЕ показывает, а фильтр из него исполняется) и
   `extensions.worktreeConfig` (ключи уезжают в `.git/config.worktree`).

**Честная рамка (записана в докстроке `untrusted_repo`, а не только здесь):** слой 3 — это
проверка НА МОМЕНТ (живой сеанс `claude` вправе дописать ключ между опросом и `add`), и он
применим только к КЛОНУ, где конфиг завели мы; у linked worktree локальный конфиг — конфиг
ВЛАДЕЛЬЦА (в нём законно живёт `merge.beads.driver`), и там работают только пары в argv. Это
