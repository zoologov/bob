# CONTEXT: BOB-089 — Боб работает под своей идентичностью, main недостижим по правам

> **Status:** Approved
> **Created:** 2026-08-05
> **Last updated:** 2026-08-05

---

## Цель

Неприкосновенность `main` перестаёт зависеть от суждения модели и начинает держаться на
правах: у процесса Боба нет доступа на запись в апстрим и нет общего `.git` с рабочей копией
owner'а. Работа Боба подписана его именем и доезжает до owner'а ссылкой на PR. Неизменна
после утверждения.

## Ключевые ограничения

- **Обход ограничения GitHub не ищем.** Cross-repo PR из приватного форка невозможен:
  installation-токен скоупится на одну установку. Проверено три способа — все отказывают.
  Решение owner'а: вариант A, Боб отдаёт ссылку.
- **Branch protection недоступна** на бесплатном плане (`403 Upgrade to GitHub Pro`).
  Отложена owner'ом; схема прав работает и без неё.
- **Клон, а не linked worktree.** Общий `.git` — корень проблемы: `git update-ref
  refs/heads/main` двигает main без сети и без кредов, мимо любого push-барьера.
- **Идентичность ставится ЛОКАЛЬНО** в клоне. Глобальная настройка переподписала бы коммиты
  owner'а — та самая путаница, от которой уходим.
- **Токены и приватные ключи никогда не логируются** — ни в отладке, ни в тексте ошибки.
  Диагностика по типу ошибки и `app_id`, не по значению.
- Новый механизм за флагом `coder.isolated_clone`, default OFF; OFF-путь прежний **кроме
  закалки формы git-вызовов** (волна 8, `bob-a6b.16`; ревью MAJOR-9): она действует в обоих
  адаптерах, поэтому на коммитах Боба **хуки репозитория не исполняются** (`beadloom
  install-hooks`: pre-commit lint+sync-check, pre-push `beadloom ci`) и **upstream у ветки не
  ставится** (`push -u` → явный refspec). Обмен осознанный — в общем `.git/hooks` хук
  владельца от хука модели не отличить; потерянный быстрый гейт заменяют перепроверка
  координатором и `beadloom ci` на push из основного репозитория и на PR. Полная формулировка
  — в PRD «Цели».
- **Второй механизм изоляции не заводим** — расширяем существующий `push_guard`.

## Стандарты кода

### Язык и окружение
- **Язык:** Python 3.12+ (asyncio, `str | None`)
- **Менеджер пакетов:** uv
- **Архитектура:** DDD + Clean Architecture, domain-first вертикали
- **Новых зависимостей не добавляем** (PyJWT/cryptography в проекте нет — подпись через
  `openssl`)

### Методологии

| Методология | Применение |
|---|---|
| TDD | Red → Green → Refactor, тесты первыми |
| BDD | `.feature` на поведение, ассерты через границу |
| Mutation | прицельно на чистые ядра, ≥85%, честный триаж |
| DDD | границы контекстов, `beadloom lint --strict` |
| Cohesion | у модуля одна называемая ответственность |

### Тестирование
- pytest + pytest-cov, покрытие ≥80%
- 🔴 **Здесь это правило главное:** тест на фейке доказывает контракт ФЕЙКА. Вся беада —
  про git, креды и subprocess, то есть ровно та зона, где фейк врёт (уроки BOB-084,
  BOB-087.D5c). Изоляция доказывается **на настоящем git**, иначе не доказана.
- 🔴 Негативный смоук проверяется на кусачесть: сломай изоляцию — тест обязан покраснеть.
  Зелёный тест, который не падает на сломанном коде, — не тест.
- 🔴 Отказ должен приходить **по отсутствию доступа**, а не по нашей вежливости. Проверять
  текст отказа, а не только код возврата.

### Гейты перед сдачей
```
uv run pytest · uv run ruff check src/ tests/ · uv run mypy src/ · uv run mypy tests/
rm -f .beadloom/beadloom.db && beadloom reindex && beadloom lint --strict
```
🔴 `beadloom lint` — ТОЛЬКО на чистой БД (BDL-UX #142). После mutmut чистить байткод.

## Решения, принятые до старта

| Вопрос | Решение |
|---|---|
| Учётка или App | GitHub App — короткоживущие токены, гранулярные права, свой аудит |
| Одно приложение или два | Два: права App одинаковы для всех установок, сузить нельзя |
| Кто открывает PR | Owner по ссылке от Боба (вариант A) |
| Доступ на чтение | Ко всем репозиториям owner'а — сознательно, под BOB-048 |
| Подпись коммитов | `bob[ai]`, локально в клоне |
| Branch protection | Отложена (недоступна на free-плане) |

## Состояние на старте

- Инфраструктура доступов **готова** руками owner'а: организация `bobiverse-dev`, приватный
  форк, два App, ключи в `.secrets/*.pem` (0600), `app_id` и пути в `.env`.
- Негативный смоук координатора токеном `Propose`: создание ветки / force-push в main /
  запись файла в апстрим — все три `403 Resource not accessible by integration`.
- В коде: `GitWorktree` (linked worktree), `push_guard.guarded_spawn_env` (шов изоляции,
  `None` при OFF), порт `Worktree` + узкий `PersistentWorkspace.ensure`.
- Флаги `coder.allow_bypass`, `coder.extra_dirs`, `coder.resume` выключены. Пока они
  выключены, риск теоретический — беада готовит право включить их без потери `main`.
