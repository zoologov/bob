# RFC: BOB-049 — «Семантическое решение об отклике»

> **Status:** Approved
> **Created:** 2026-06-30
> **PRD:** `.claude/development/docs/features/BOB-049/PRD.md`
> **Решения (утв.):** floor — входной сигнал · сбой → «полный Боб или GUPPI-нотис» (не тихий дефолт) ·
> эмодзи валидируется + фолбэк.

---

## Идея решения

Заменить лестницу эвристик (`classify_addressivity` → `decide_response` → `decide_expression`) **одним
смысловым суждением**: на каждое входящее Боб (Tier-0 LLM) **понимает** сообщение в контексте и решает
`reply | react | ignore` (+ эмодзи при react, + причина). Структурные сигналы (`@mention`/reply/«Боб,»/
`others_present`) и floor **становятся ВХОДАМИ-подсказками**, а не правилами. Authz (BOB-019) — отдельный
ортогональный слой: суждение решает *соц-отклик*, исполнение по-прежнему применяет гостевые ограничения.

## Доменная модель

```python
class ResponseIntent(StrEnum):
    REPLY = "reply"     # ответить словами
    REACT = "react"     # поставить реакцию-эмодзи (по смыслу)
    IGNORE = "ignore"   # промолчать (прочитал, ответа не ждут)

@frozen(slots=True)
class ResponseChoice:
    intent: ResponseIntent
    emoji: str | None      # заполнен при REACT — выбран ПО СМЫСЛУ (валидируется против
                           # разрешённого Telegram-набора реакций; иначе дефолт/REPLY)
    reason: str            # короткое «почему» (для логов/прозрачности, не пользователю)
```

Чистая валидация эмодзи против Telegram-набора free-реакций (если судья вернул невалидный — мягкий
фолбэк на дефолтный тёплый эмодзи).

## Шов суждения (port + Tier-0 реализация)

```python
class ResponseJudge(Protocol):           # инъектируемый шов (детерминизм в тестах)
    async def decide(self, ctx: ResponseContext) -> ResponseChoice: ...
```

- **`ResponseContext`** (вход суждения): текст сообщения; **отправитель как соц-контекст** (Interlocutor:
  owner/known/guest + имя/отношение BOB-014) — НЕ override; **per-person недавняя нить** (BOB-045 —
  `recent_episodes_for`); **структурные подсказки** (`mentions_bob`, `reply_to_bob`,
  `addressivity`-класс, `others_present`, floor-engagement) — как сигналы; **настроение** (mood tone).
- **Tier-0 реализация** (`LlmResponseJudge`): чистый промпт-строитель (domain) → Tier-0 вызов → парсинг в
  `ResponseChoice`. Непарсибельный ответ — НЕ тихий дефолт, а сигнал сбоя (см. «Отказоустойчивость»):
  ограниченный ретрай, затем GUPPI-нотис. Reason/intent/emoji из ответа.
- **Application use-case `DecideResponse`**: собирает `ResponseContext` из соула/нити/сигналов, зовёт
  `ResponseJudge`, возвращает `ResponseChoice`. Один Tier-0 вызов на входящее (ВСЕГДА семантика).

## Поток в `handle_message`

Заменяем блок addressivity-решения (`_decide_addressivity` → SILENT/REACT/REACT_ONLY ветки):

```
perceive(mood, interlocutor, per-person history, structural signals)
choice = await DecideResponse(...)            # семантика
match choice.intent:
  REPLY  -> compose+send (СУЩЕСТВУЮЩИЙ путь, с гостевыми ограничениями BOB-019) ; persist(reply)
  REACT  -> reactor.set(choice.emoji)         # эмодзи ПО СМЫСЛУ (заменяет mood→таблицу BOB-018)
            ; persist(user turn, bob="(реакция: <emoji>)")
  IGNORE -> ; persist(user turn, bob="(промолчал)")
advance_floor(...)                            # floor по-прежнему обновляется
```

- 🔴 **Персист во ВСЕХ ветках** — ход пользователя сохраняется и при REACT, и при IGNORE (память по нити,
  BOB-045) → follow-up имеет контекст. (Сейчас REACT/SILENT — ранний return без `_persist`.)
- **Эмодзи по смыслу:** `reactor` (BOB-018 `MessageReactor`) ставит `choice.emoji`; mood→эмодзи-таблица
  больше не решает (может остаться дефолтом-фолбэком).
- **`decide_response`/`decide_expression`** перестают рулить (их сигналы — на вход судье). Модули
  оставляем как поставщиков сигналов (полное удаление — позже).

## Authz и приватность (🔴 ортогонально)

Суждение решает **соц-отклик**, НЕ доступ. Исполнение REPLY для гостя по-прежнему идёт **гостевым путём**
(BOB-019: без owner-памяти/recall, без capabilities, гостевой ход не пишется в owner-факты). Судья может
решить «ответить Норману тепло» — но контент остаётся гостевым. Семантика и authz **не смешиваются**.

## Детерминизм и стоимость

- **Детерминизм:** `ResponseJudge` — инъектируемый шов; в тестах фейк отдаёт скриптовый `ResponseChoice`;
  ветвление+персист в `handle_message` детерминированы по выходу судьи. Промпт-строитель/парсер — чистые.
- **Стоимость:** +1 Tier-0 вызов на входящее (дёшево; реакции/болтовня редки; консистентно с нашими
  Tier-0-классификаторами intent/sentiment/project). Цена за человечность.

## 🔴 Отказоустойчивость: «полный Боб или честный GUPPI-нотис» (общий принцип)

Никаких полумер/полуответов. Пользователь получает либо **полного Боба**, либо честный системный нотис —
не деградированный отклик (полу-ответ = «уверенный бред», антипаттерн).

- **Essential-путь** (падение → отказ): семантическое **суждение** + **генерация ответа** (REPLY-compose).
- **Ретрай, потом нотис:** на сбое essential-шага — 1–2 быстрых ретрая; если всё равно падает → **GUPPI
  подсвечивает «⚠️ Проблемы со связью — Боб временно недоступен»** в топике Боба (системный голос GUPPI),
  и Боб НЕ отвечает деградированно.
- **Опциональные флейворы** (рефлексия-колбэк, fascination, alignment-нота и пр.): при сбое **тихо
  опускаются** — ядро остаётся полным Бобом; отказ НЕ объявляется.
- **REACT/IGNORE как генуинный выбор суждения — это полный Боб, не отказ.** Нотис только когда шаг УПАЛ
  (ошибка/таймаут после ретраев), а не когда Боб осмысленно выбрал реакцию/молчание.
- Канон: Боб — разум (недоступен → его нет), GUPPI — инфраструктура, честно докладывает отказ.

## Слои (DDD)

- **domain:** `ResponseIntent`/`ResponseChoice`, промпт-строитель + парсер, валидация эмодзи, `ResponseJudge`
  порт.
- **application:** `DecideResponse` (сбор контекста + вызов судьи); правка `handle_message` (ветвление +
  персист).
- **infrastructure:** `LlmResponseJudge` (Tier-0 через router); провязка в `app.py`.

## Риски и митигации

- **Судья мажет** (ответил на фон / промолчал на важное) — это человеческая нечёткость, принимаем осознанно
  (это и есть живость); Tier-0 с хорошим контекстом; систематически мажет → поднять на Tier-1 (шов это
  позволяет без переписывания). Это НЕ сбой — а вот ошибка/таймаут вызова → отказоустойчивость (GUPPI-нотис).
- **Невалидный эмодзи** → валидация против Telegram-набора + фолбэк.
- **Регрессии** addressivity/floor/гостя → шов замещает РЕШЕНИЕ, не ломая компоненты-сигналы; гостевой путь
  и floor целы; полный тест-набор зелёный.
- **Латентность** Tier-0 на каждое сообщение → приемлемо; typing-индикатор покрывает.

## Решения (утверждены)

1. **Floor (BOB-025):** остаётся **входным сигналом** судье, не жёстким порогом. Полное удаление floor —
   позже.
2. **Сбой судьи/генерации:** НЕ тихий дефолт, а **«полный Боб или GUPPI-нотис»** (раздел «Отказоустойчивость»)
   — ретрай, затем GUPPI «проблемы со связью». Общий принцип проекта.
3. **Эмодзи-набор:** валидируется против Telegram-разрешённых реакций, фолбэк на дефолтный тёплый.
