## Results

Замер dev-беады `bob-11o`, 2026-10-22, macOS (Apple silicon), Python 3.12, SQLite 3.50.4,
sqlite-vec v0.1.9. Копия прод-БД (134 МБ): `episodic_log` 27 502 строки, `semantic_memory` 45,
`memory_vec` 27 547 векторов (27 502 episodic + 45 semantic), недостающих векторов 0 в обоих
источниках.

| Что | Было | Стало |
|---|---|---|
| Поиск недостающих, `episodic` | > 120 с (прервано по пределу) | 0,163 с |
| Поиск недостающих, `semantic` | 3,703 с | 0,086 с |
| `backfill()` целиком, холодный стор | — | 0,244 с, эмбеддер не вызван |
| `SqliteMemoryRepo.initialize()` целиком | — | 0,502 с |
| Проверка «вектор уже есть» на запись | 119 мс на каждое сообщение | один проход 129 мс, дальше 0,0 мс |

Строка журнала на копии: `vector backfill: semantic 45 rows (0 missing), episodic 27502 rows
(0 missing) in 0.25 s`.

Выбор реализации — множество в Python, а не временная таблица `_vec_done` + `NOT EXISTS`: обе
платят один и тот же проход по vec0 (131 мс из 163 мс), временная таблица быстрее на 35 мс
(0,128 с), но множество заодно отвечает на проверку при записи без второго прохода. Фильтр по
ключу партиции вне KNN-запроса проход не сужает: партиция `semantic` из 45 векторов стоит 85 мс.

Синтетика теста (30 000 эпизодов, все встроены): `backfill()` 0,25 с, бюджет 1,25 с; 20 записей
с встраиванием 0,15 с, бюджет 0,75 с (≈ 5× от замера). Саботаж старым `LEFT JOIN` и старой
точечной проверкой — оба красные по бюджету (FAILED).
