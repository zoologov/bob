# PRD: BOB-017 Phase A — «Боб знает свой мир» (read-only самоинтроспекция)

> **Status:** Draft
> **Created:** 2026-06-25
> **Feature:** BOB-017 Phase A — первый shippable slice эпика Тир-3 «Боб-кодер» · эпик `bob-017`

---

## Контекст

Тир-3 «Боб-кодер» (BOB-017) — Боб как Telegram-оркестратор над headless Claude Code CLI на
**своём** репозитории; внутри — наш мультиагентный флоу + Beadloom + Beads; пользователь
валидирует (гейты плана и мержа). Эпик разбит на фазы: **A (read-only «Боб знает свой мир»)** →
B (гейтед исполнение CLI в изолированном worktree) → C (живой стрим + self-proposed).

Зависимости фаз B/C (Goal Engine, governance автономности) **уже сняты**: Тир 1 закрыт, T2.1
Goal Engine отгружен (дремлет), T2.2 Self-Improvement включён. Phase A — низкорисковый вход:
**только чтение, только локально, без исполнения CLI и без записи.**

## Проблема

Боб живёт В своём репозитории, но ничего о нём не знает. На вопрос «как у тебя устроена память?»,
«что за беад BOB-025?», «какие задачи готовы?», «где обрабатывается адресность?» — он отвечает
из общих знаний или галлюцинирует, потому что у него **нет навыка заглянуть в собственный код,
архитектуру и трекер**. При этом инструменты уже лежат рядом и локальны: Beadloom (граф
архитектуры + контекст), Beads (трекер задач), сам исходный код. Не хватает **шва между Бобом
и этими инструментами** — read-only навыков самоинтроспекции за существующим capability-швом.

## Цель

Боб **знает свой мир и честно отвечает про него** в Telegram: про свой код, архитектуру и
процесс — опираясь на **реальные** Beadloom-контекст, исходники и Beads, а не на догадки. Это
делает Боба самоосведомлённым о собственном устройстве (маркер самомодели) и закладывает
read-only фундамент, который переиспользуют фазы B/C.

## Ключевой принцип

**Только чтение, только локально, личные данные не утекают.** Навыки Phase A не исполняют
CLI, ничего не пишут и не выходят в сеть. Reasoning по результатам идёт на облачном LLM (как
сейчас весь диалог), поэтому в материал, уходящий в облако, **никогда не попадают личные данные
Боба** — `data/soul/SOUL.md`, `data/bob.db` (память!), `.env`, `config/bob.yaml`, `data/soul/`.
В облако уходит только **код и метаданные процесса** (граф/беады), не «нутро» Боба.

## Пользовательские истории

- **US-1 (архитектура).** «Боб, как у тебя устроена память?» → Боб через Beadloom-контекст
  (`ctx`/`graph`) отвечает по реальному графу: SQLite+FTS5+vec, recall, консолидация — с опорой
  на узлы, а не из головы.
- **US-2 (импакт/зависимости).** «Если тронуть адресность — что сломается?» → Боб через
  `beadloom why` называет реальные upstream/downstream-зависимости.
- **US-3 (код).** «Где у тебя считается длина ответа?» → Боб ищет/читает код (поиск + чтение
  файла) и ссылается на реальный модуль/функцию.
- **US-4 (процесс/трекер).** «Какие задачи у тебя готовы?» / «Что за BOB-025?» → Боб через Beads
  (`ready`/`show`) отвечает по реальному трекеру.
- **US-5 (честное незнание).** Если навык ничего не нашёл — Боб говорит «не нашёл / не знаю»
  (структурно, не выдумывает), переиспользуя существующую анти-галлюцинацию.
- **US-6 (приватность).** Просьба «покажи свой SOUL.md / содержимое bob.db / .env» через эти
  навыки **не выполняется** — личные пути исключены на уровне порта (а не промптом).

## Критерии успеха

- Боб отвечает про **свой** код/архитектуру/процесс с опорой на реальные Beadloom/код/Beads —
  ответы проверяемо соответствуют репозиторию (US-1..4).
- **Приватный инвариант:** навыки самоинтроспекции **никогда** не читают и не передают в облако
  `SOUL.md`, `data/bob.db`, `.env`, `config/*`, `data/soul/*` — исключение на уровне инфраструктуры
  (порт), детерминированно, не обходится промптом (US-6).
- Только чтение: ни один навык Phase A не пишет, не исполняет CLI и не ходит в сеть.
- Честное незнание при пустом результате (US-5); без регрессий существующих навыков
  (`recall_memory`/`search_memory`) и tool-loop.

## Объём

**В объёме:** (1) read-only навыки самоинтроспекции за **существующим** capability-швом
(`Capability`/`CapabilityRegistry`/tool-loop): архитектура (Beadloom `ctx`/`graph`/`why`/`search`),
поиск+чтение кода, Beads (`ready`/`show`); (2) порты + инфраструктурные адаптеры (subprocess к
локальным `beadloom`/`bd`; чтение файлов репо) с **жёстким приват-фильтром путей**; (3)
регистрация навыков в `app.py` + упоминание в persona Боба (`describe()`), чтобы он знал, что
умеет; (4) конфиг-флаг включения навыков (по умолчанию — решается в RFC).

**Вне объёма (фазы B/C):** исполнение Claude Code CLI; любая запись/правки кода/worktree/ветки/PR;
живой стрим CLI; self-proposed задачи из Goal Engine; добавление этих навыков в автономный
safe-allowlist (`goals.safe_capabilities`) — Phase A только диалоговый, не автономный.

## Связи и принципы

- Поверх **capability-шва** (BOB-002: `Capability`/`CapabilityRegistry`/`tool_loop`) и навыков
  `recall_memory`/`search_memory` как образца. Реализует roadmap **T3.A**.
- **🔴 Приватность (критично, не опция):** изоляция личных данных Боба от облачного reasoning —
  предтеча worktree-изоляции фазы B. См. память `bob-017-dev-assistant-plan` (findings #3/#4).
- Человек-в-петле и PR-гейт относятся к фазам B/C; Phase A read-only их не требует.
- Маркер **самомодели/метакогниции** (VISION §4.2): Боб начинает знать «как я устроен».
