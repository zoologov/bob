# BRIEF: BOB-059 — «Устойчивый старт при флапе сети»

> **Status:** Approved
> **Created:** 2026-07-01
> **Type:** bug · Тир-инфраструктура · старт GUPPI/поллинга устойчив к моргу сети

---

## Проблема

При рестарте в момент кратковременного обрыва сети Боб **и GUPPI молчат**: процесс жив, но **поллинг не
стартует**. Наблюдалось вживую (2026-07-01): рестарт попал в блип Telegram → фатальный трейсбек на старте.

**Точная причина** (`infrastructure/telegram/multibot.py::resolve_bot_identities`, ~стр. 338): метод
УЖЕ задуман деградировать грациозно —
```python
try:
    me = await get_me()
except (OSError, RuntimeError, TimeoutError) as exc:   # ← НЕ ловит TelegramNetworkError
    logger.warning("could not resolve Bob's bot identity (get_me): %s", exc)
    return   # «rather than blocking startup»
```
Но при обрыве aiogram поднимает **`aiogram.exceptions.TelegramNetworkError`**, которого в этом `except`
**нет** → исключение пролетает вверх (`app.startup` → `_run` → `asyncio.run`) → **старт падает целиком** →
`AgentRuntime`/поллинг не запускаются → Боб и GUPPI немые до ручного рестарта.

**Контраст:** сам поллинг (`poll_once`) к обрывам устойчив (один упавший бот логируется и пропускается) —
а вот **старт** нет. Одна сетевая осечка при запуске = немой процесс. При нестабильном канале owner это
повторяется.

## Решение

Сделать `resolve_bot_identities` устойчивым — в духе уже заложенной грациозной деградации + essential-retry
(BOB-049):

1. **Bounded retry** `get_me()` — обернуть в `call_with_retry` (`application/reliability.py`, BOB-049): 
   несколько попыток с коротким бэкоффом (инъектируемый sleep для детерминизма тестов). Транзиентный блип
   переживается, идентичность резолвится.
2. **Грациозная деградация на исчерпании** — расширить `except`, чтобы ловить **и** `TelegramNetworkError`
   (сетевые ошибки aiogram), а не только `(OSError, RuntimeError, TimeoutError)`: на устойчивом сбое —
   `logger.warning` + `return` (как задумано, «не блокировать старт»). 🔴 Старт ПРОДОЛЖАЕТСЯ → поллинг
   запускается → Боб слушает; bob-identity (для reply-to) дорезолвится позже/на следующем ходе.
3. 🔴 Не менять поведение при УСПЕХЕ (идентичность ставится как сейчас) и не глотать НЕ-сетевые баги
   (ловим конкретные сетевые типы, не голый `except Exception`).

**Итог:** моргание сети при запуске больше не оставляет немого Боба — либо идентичность резолвится по
ретраю, либо старт грациозно продолжается без неё (а не падает).

## Критерии приёмки

- Рестарт в момент блипа Telegram → старт НЕ падает; поллинг запускается; Боб/GUPPI слушают.
- Транзиентный блип → `get_me` резолвится по ретраю (идентичность есть).
- Устойчивый сбой → грациозная деградация (warn), старт продолжается без идентичности (не крах).
- НЕ-сетевые баги не проглатываются; успех — без изменений.
