# BRIEF: BOB-095 — Настоящий CI по PR (beadloom ci на pull_request)

> **Status:** Approved
> **Created:** 2026-08-18
> **Bead:** `bob-ah6` (`type: task`, P1)

---

## Проблема

CI по PR **не существовал**, хотя доки полгода утверждали обратное (найдено 5-м проходом ревью
BOB-089). На ветке Боба pre-push хук не исполняется (с BOB-089 форма git-вызовов закалена в обоих
адаптерах), поэтому на его коммитах быстрый гейт **исчез вовсе** — единственная страховка сейчас —
перепроверка координатором руками. CI по PR вернёт автоматику.

🔴 **Что изменилось и упрощает:** GitHub Actions на этом приватном репо **доказанно работают** —
деплой v1.0.0 (BOB-094) прошёл боевым прогоном. Так что вопрос «доступны ли Actions / уложимся ли
в лимит минут» наполовину снят. Рядом уже лежат `deploy-site.yml` и `deploy-bob.yml`.

## Решение

`.github/workflows/ci.yml` на `pull_request → main` (+ `push` в main для видимости, + ручной
`workflow_dispatch`):
- `uv sync --extra dev` — 🔴 **урок деплоя (Issues #57):** `ruff`/`mypy`/`pytest` в
  `[project.optional-dependencies].dev`, дефолтный `uv sync` их НЕ ставит;
- `ruff check src/ tests/`, `mypy src/`, `mypy tests/`;
- `uv run pytest -q -rs` — 🔴 **флаг `-rs` обязателен:** процессный гейт `test_process_drift_gate`
  на раннере (нет `bd`/базы трекера — Dolt-база gitignored) даёт **SKIP с причиной**, не ERROR и не
  молчаливое зелёное (устроено в BOB-098/bob-ck4.4). `-rs` печатает причину пропуска, чтобы CI не
  читался как «согласованность проверена»;
- 🔴 **`beadloom ci` на ЧИСТОМ индексе** (§0.3 п.1: инкрементальный `reindex` врёт) —
  `rm -f .beadloom/beadloom.db && beadloom reindex && beadloom ci`. Поставить `beadloom` (pip/uv) на
  раннер; если недоступен — шаг честно SKIP с причиной, а не молча пропущен.
- Кэш `uv` (`~/.cache/uv`) — уложиться в лимит минут бесплатного плана.

## 🔴 Честность (главное — не выдать желаемое за required)

Branch protection на бесплатном плане **недоступна** (`403 Upgrade to Pro`). Значит проверка —
**ИНФОРМАТИВНАЯ, а не блокирующая**: красный CI виден в PR, но технически не мешает мёржу.
- `CLAUDE.md §6` — сказать это **прямо**: CI по PR есть и виден, но НЕ required check (branch
  protection недоступна); что реально держит `main` — дисциплина + перепроверка + теперь ещё и
  видимый CI. Исправить прежние утверждения §6 видимой правкой.
- Не называть проверку «required» и «blocking» нигде.

## Границы

- Не настраивать branch protection (недоступна — команда `403`).
- Не дублировать деплой (это `deploy-bob.yml`, по тегу) — CI это ГЕЙТ на PR, не выкатка.
- Не гнать mutation в CI (дорого, не pre-commit — §0.2).

## Критерии приёмки

- [ ] `ci.yml` на `pull_request → main`; `gh run list` подтверждает запуск на живом PR
- [ ] Гоняет `uv sync --extra dev` → ruff + mypy(src,tests) + `pytest -rs` + `beadloom ci` на чистом
      индексе
- [ ] Процессный гейт на раннере даёт SKIP с причиной (видно в выводе `-rs`), не ERROR/не молчание
- [ ] `CLAUDE.md §6` честно называет проверку информативной, а не required (видимая правка)
- [ ] Уложились в лимит минут (кэш uv); прогон зелёный на чистом PR
