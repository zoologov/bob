# PRD: BOB-015 — «Автономность: Goal Engine + Planner + самонаправленность»

> **Status:** Approved
> **Created:** 2026-06-24
> **Feature:** BOB-015 (Тир 2, T2.1 + срез T2.2 — автономность-стадия B) · эпик `bob-xnz`

---

## Проблема

Боб **реактивен и проактивен в чате** (стадия A: heartbeat + «стоит ли заговорить» под
governance), но у него **нет собственных целей**. Он не может удерживать намерение во времени,
довести что-то до конца, преследовать что-то **сам** между сообщениями. Для настоящего
companion-агента (и как фундамент под Боба-кодера, Тир 3) ему нужна **подложка целей** + умение
**действовать к целям самостоятельно**, но строго безопасно — это первый шаг, где Боб начинает
делать что-то без явного «давай» на каждый шаг.

## Цель

Дать Бобу **автономность-стадию B** в рамках governance:

> **Goal Engine** (граф целей) + **Planner** (декомпозиция цели → задачи) + **самонаправленное
> исполнение** уже-**утверждённых** целей под той же proactivity-governance (quiet-hours /
> rate-limit / approval / контроль owner).

Боб удерживает цели между сессиями, разбивает их на задачи, **сам продвигает** безопасные шаги
в фоновом ритме — и при этом **никогда не действует по неутверждённой цели** и **не выходит за
границы безопасных capability** (внешняя агентность — код/инструменты/внешние API — это стадия C,
гейтед, не здесь).

## Пользовательские истории

- **US-1 (owner ставит цель).** Owner даёт Бобу цель («веди заметки по теме X», «напоминай про
  Y», «разберись с Z и расскажи»). Goal Engine хранит её: приоритет, критерии завершения, опц.
  дедлайн, состояние.
- **US-2 (Боб декомпозирует и ПРЕДЛАГАЕТ план).** Planner (LLM) разбивает цель на исполнимые
  задачи (с зависимостями) и Боб **показывает план owner на утверждение** — не начинает молча.
- **US-3 (Боб сам продвигает утверждённое).** После апрува Боб **сам**, по heartbeat в рабочие
  часы, продвигает **безопасные** задачи под governance (rate-limit/quiet-hours/«не спамит»):
  обновляет состояние цели/задач, выполняет внутренне-безопасные шаги (напоминание, заметка из
  памяти, рефлексия, подготовка), **сообщает прогресс** в чат — как живой, который занимается
  своим делом и держит owner в курсе.
- **US-4 (Боб ПРЕДЛАГАЕТ цель сам).** Из паттернов диалога/памяти Боб может **предложить** цель
  («хочешь, я буду следить за…?») — но **не берёт в работу без апрува owner**.
- **US-5 (owner у руля).** Owner видит список целей/задач, правит приоритеты, **паузит / отменяет**,
  и есть **kill-switch** («стоп, не занимайся этим») — мгновенно останавливает самонаправленность.
- **US-6 (граница стадии B — безопасность).** Боб **НЕ исполняет внешние действия** автономно
  (код, инструменты вне chat/памяти, внешние API, файловая система вне его данных). Задача,
  которой нужна внешняя агентность, **остаётся предложением** (помечается «нужен стадия-C гейт»),
  Боб не выполняет её сам — только показывает owner.

## Критерии успеха

- Боб **удерживает цели между сессиями** (персист в SQLite), декомпозирует их в задачи с
  зависимостями, **сам продвигает** безопасные задачи в фоновом ритме под governance.
- **Authz-before-autonomy соблюдён:** Боб **никогда** не действует по неутверждённой цели;
  предложенные им цели ждут апрува; **никогда** не пересекает границу внешней агентности (стадия C).
- Owner имеет **полный контроль**: list/approve/pause/cancel/kill-switch; самонаправленность
  уважает quiet-hours/rate-limit и **не спамит**.
- Прогресс/намерения Боба **прозрачны** (он сообщает, чем занят и почему).
- Не сломаны: реактив, проактив-чат (стадия A), личность (Тир 1: настроение/вкус/память/
  отношения/адресность/краткость), governance, capability-шов, authz/гость-инвариант.

## Объём

**В объёме:** (1) **Goal Engine** — граф целей в SQLite (поля/состояния/приоритеты/зависимости/
критерии завершения); (2) **Planner** — LLM-декомпозиция цели → задачи (с зависимостями) + апрув-флоу;
(3) **самонаправленный цикл** — heartbeat-driven продвижение **утверждённых** целей через **ту же
proactivity-governance**, только для **безопасных** (chat/внутренних) шагов; (4) **предложение
целей** Бобом (proposed → требует апрува); (5) **контроль owner** (list/approve/pause/cancel/
kill-switch) через чат; (6) **прозрачность прогресса**.

**Вне объёма (явные границы безопасности):**
- **Внешняя агентность (стадия C):** автономный запуск кода / Claude Code / внешних инструментов /
  Apple-приложений / файловой системы — **НЕ здесь** (гейтед, Тир 3 / стадия C).
- **Self-Improvement правилами** (анализ паттернов ошибок → новые правила/стратегии) — вторая
  половина T2.2, **отложена** (отдельный эпик).
- **Permission-tiers / зрелость capability-машинерии** (T2.3) — отложено; реюз существующего
  capability-шва как есть.

## Связи и принципы

- **Authz-before-autonomy** (ядро): цель → апрув → действие; governance (owner/allowlist/scope)
  расширяется на автономные действия. Память: `bob-post-p0-plan`, `bob-personality-simulation-philosophy`.
- Переиспользует **proactivity drive-model** (BOB-010: heartbeat / quiet-hours / rate-limit /
  «стоит ли действовать»), **capability-шов + GUPPI** (исполнитель безопасных действий),
  **память** (контекст целей), **личность Тир 1** (Боб преследует цели «как характер»).
- **Фундамент под Тир 3** (Боб-кодер): Goal Engine даёт Бобу источник самопредложенных dev-задач
  (но исполнение кода — уже стадия C/гейт).
