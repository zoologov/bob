# PRD — Форматирование для удобства восприятия (rich Telegram + таблицы)

## Проблема

Боб корректно прислал список багов из bob-issues.md, но **полотном текста**: он не структурировал
вывод (нет markdown-разметки). Причина — не рендер (палитра богатая), а промпт: brevity-система
(BOB-024) на коротких ходах велит «без списков, в 1-2 строки», на развёрнутых — «несколько абзацев»;
форматирование даётся как выбор ДЛИНЫ, но НИКОГДА как выбор СТРУКТУРЫ. Ни один режим не учит «оформи
списком/таблицей для удобства».

🔴 **Актуализация API (research 2026-08):** Telegram **Bot API 10.1** (11.06.2026) добавил
`sendRichMessage` с **нативными таблицами** (`RichBlockTable`), сворачиваемыми блоками
(`RichBlockDetails`), списками/заголовками/цитатами/кодом/математикой/медиа. aiogram 3.29 всё экспонирует.
Но наш конвертер `rich.py` (`MarkdownToRichMessage`) реализует лишь **подмножество** — таблицы/details не
эмитит. Значит markdown-таблица Боба сейчас НЕ станет нативной таблицей.

## Цель (стиль owner'а: Боб судит по контенту; охват: везде группа+личка)

Боб **понимает, как форматировать для удобства собеседника** и умеет это технически:
- структурное содержимое (списки/шаги/сравнения/баги) → списки/заголовки/**жирный**/`код`/цитаты;
- табличные данные → **нативная таблица** Telegram (не полотно);
- casual-болтовня → живой короткий текст (не форматируем ради формата — north star);
- судит по контенту (LLM-решение, не скрипт).

## Сценарии (acceptance)

**S1 — Структура вместо полотна (главный).** «дай список багов с приоритетами» → Боб оформляет
**структурно** (список/таблица с приоритетами-тегами), а не абзацем-полотном.
**S2 — Нативная таблица.** Табличные данные → markdown-таблица `| … |` → рендерится **нативной
таблицей Telegram** (`RichBlockTable`), не моноширинным полотном.
**S3 — Casual остаётся живым.** Обычная реплика/болтовня → короткий живой текст, без лишней разметки.
**S4 — Везде.** Тот же навык в группе и в личке (единая личность).

## Инварианты

- INV-1 (Судит по контенту): форматирование — по смыслу содержимого, не всегда-вкл/не всегда-выкл; casual живой.
- INV-2 (Нативные таблицы): markdown-таблица → `RichBlockTable` (не ASCII-полотно), рендерится клиентом.
- INV-3 (Не регресс): существующий subset конвертера (заголовки/списки/цитаты/код/inline) цел; brevity
  на casual-ходах сохраняет живую краткость.
- INV-4 (Везде): навык глобальный (группа+личка), не dev-only.

## Не входит в scope
- Медиа-блоки (photo/video/collage/map) в конвертере — только текст/таблицы/список/заголовки/детали.
- Переработка decide_verbosity/engagement (длина) — только добавляем ось СТРУКТУРЫ.
- Интерактив-механизм BOB-083.
