## D — четыре тупика, прежде чем рендер заработал

Каждый выглядел как решение и оказывался ложным. Записаны, чтобы следующий хост поднимался
по прямой:

| Попытка | Почему не вышло |
|---|---|
| `snap install chromium` | snap-сборка не стартует из сервисного контекста: `is not a snap cgroup for tag snap.chromium.chromium` |
| `npx puppeteer browsers install` на node 18 (из Ubuntu 24.04) | `SyntaxError: Invalid regular expression flags` — свежему puppeteer-CLI нужен node ≥ 20 |
| то же под node 22 | `All providers failed for chrome-headless-shell` — загрузка с Google-бакета с этого VPS не проходит (`storage.googleapis.com` отдаёт 403) |
| первый `npx` от имени `bob` | `EACCES: spawn sh` — унаследовал рабочий каталог `/root`, куда `bob` не пройдёт |

**Что сработало:** Node 22 (NodeSource) + `mermaid-cli` глобально + **Google Chrome из `.deb`**
(`dl.google.com` доступен, отдаёт 200) + `PUPPETEER_EXECUTABLE_PATH=/usr/bin/google-chrome` в
`.env` юнита. Плюс `mmdc_bin` в конфиге прода переведён с пути макбука на `/usr/local/bin/mmdc`.

## Решения по ходу

- **«Боб выдумал» переквалифицировано в дефект шва.** Соблазн был списать на модель. Но
  `_run_tool` отбрасывал причину в тексте и клал её только в автобиографию: Бобу сообщили
  «сломалось» без единого слова о том, почему. Он не солгал о известной причине — заполнил
  вакуум, созданный кодом. Поэтому и чиним кодом, а не промптом.
- **Каждый слой среды проверялся ОТ ЛИЦА сервисного пользователя.** Проверка под `root`
  показала бы «установлено» на всех трёх слоях, где для `bob` ничего не работало.
- **Обещаем ровно то, что держим.** Гард на молчание — детерминированный. «Больше никогда не
  сочинит» не обещаем: это поведение модели, мы убрали причину сочинять.
