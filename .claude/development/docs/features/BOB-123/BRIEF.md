# BRIEF — BOB-123: spike дублёра Tier-0 на CPU VPS — Qwen3.5-4B / 2B

> **Type:** task · **Status:** Approved (решение владельца 2026-10-22: «замер qwen3:4b», уточнено — актуальная лёгкая модель; по обзорам 2026 — Qwen3.5-4B, запасной — 2B)
> **Created:** 2026-10-22 · **Беада:** `bob-aiu`

## Проблема

На VPS (4 vCPU, GPU нет, RAM 7,9 ГБ, доступно ~5,8) дублёр Tier-0 выключен: `qwen3:8b` отклонён замером D9 BOB-116 (5,9 ГБ + `bge-m3` 1,2 ГБ не помещаются рядом — взаимное вытеснение; REFLECT 116 с холодный). Без дублёра отказ облака = немота (теперь слышная, но немота).

## Решение

Замер `qwen3.5:4b` (~3,1 ГБ Q4) и `qwen3.5:2b` (~1,5 ГБ) той же процедурой, что D9, но с `think: false` и печатью текстов: три сервисные двери (классификатор 0,5 k ток., монолог 1,5 k, рефлексия 2 k; по 2 прогона с embed `bge-m3` между ними), критерии RFC BOB-116: REFLECT ≤ 90 с, классификатор ≤ 15 с, обе модели помещаются рядом без вытеснения (RSS ≤ 6,5 ГБ); качество по-русски — тексты читает владелец. Замер **только при поднятом Бобе** (BOB-124: раньше голодал старт). Частичный замер 22.10 (прерван): 4B — 3,1 ГБ, обе модели загружены одновременно (4,3 ГБ), классификатор тёплый 3,2 с, ответ верный.

## Axes

Код не меняется — замер на VPS; `beadloom impact` неприменим, узлов в scope нет. Результат — решение: включить `tier0_fallback` в `config/bob.vps.yaml` (отдельный PR, выкатка тянет модель сама) или остаться без дублёра (B — отдельное решение владельца).
