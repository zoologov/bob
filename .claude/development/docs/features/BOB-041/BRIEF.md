# BRIEF: BOB-041 — T3.B UX/канон: задача Бобу естественным языком, голос Боба, GUPPI исполняет

> **Status:** Approved
> **Created:** 2026-06-26
> **Type:** feature · поверх BOB-039/040 (T3.B) · эпик `bob-041`

---

## Проблема (первый живой прогон T3.B, PR #48 создан ✓)

T3.B работает end-to-end, но три недочёта UX/канона:

1. **Markdown не рендерится.** Coding-сообщения шлются голым `send_message` без `parse_mode` →
   `## …`/`**`/`` ` `` уходят текстом. (Обычные ответы Боба идут rich/markdown — coding-путь нет.)
2. **Дубль в теле.** План в БД содержит `## План` дважды: claude в plan-mode эмитит план и в
   `assistant`-событии, и в `result` → `_run_plan` собирает оба → дубль.
3. **🔴 Должен делать Боб, а не GUPPI (канон).** Сейчас `/code` — команда GUPPI в General, голос
   GUPPI. По канону Бобиверса (и по решению owner): **owner общается с Бобом, ставит задачу Бобу
   естественным языком в его топике, а Боб исполняет руками GUPPI** (GUPPI — детерминированный backend,
   «руки» без личности).

## Решение

1. **Markdown.** Coding-сообщения через rich/markdown-путь (как обычные ответы Боба;
   `send_rich_message`/`parse_mode`), с безопасным фолбэком на plain.
2. **Дедуп плана.** Брать план один раз (финальный `result`-текст plan-mode, без дубля
   `assistant`+`result`); очистить служебную преамбулу («ExitPlanMode недоступен…»).
3. **Естественный язык + голос Боба + GUPPI-исполнитель:**
   - **Интент-детект в топике Боба:** на сообщение owner Боб распознаёт **запрос на dev-работу над
     репо** (Tier-0 классификатор, КОНСЕРВАТИВНО) vs обычную болтовню. По интенту — стартует
     `CodingAssistant` (фаза плана).
   - **🔴 Безопасность сохранена:** интент только **owner** (authz); даже при ошибочном распознавании
     **гейт плана защищает** — Боб лишь предлагает ПЛАН (без правок) и ждёт явного согласия; исполнения
     без апрува нет. `coder.enabled` тот же мастер-свитч.
   - **Естественный апрув/стоп:** «давай/го/апрув» → approve_plan; «стоп/отмена» → stop (в топике Боба).
   - **Голос Боба:** ключевые реплики сессии (берусь / план готов / готово-PR / ошибка) — **в персоне
     Боба** («Окей, берусь — сейчас прикину через GUPPI», «Готово, вот PR — глянь»); пер-событийный
     нарратив исполнения — фактический, **атрибутирован GUPPI** («GUPPI: правлю `docs/HELLO.md`»). Боб
     дирижирует, GUPPI пашет — канон.
   - GUPPI-команды `/code …` в General **остаются** как явная резервная поверхность (не ломаем).
