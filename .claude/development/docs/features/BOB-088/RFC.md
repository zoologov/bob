# RFC: BOB-088 — Боб ведёт эпик по многоагентному конвейеру из Telegram

> **Status:** Approved
> **Created:** 2026-08-15
> **PRD:** `.claude/development/docs/features/BOB-088/PRD.md`
> **Bead:** `bob-c3r`

---

## Что выяснила живая проба

🔴 Дизайн этой работы стоял на двух утверждениях, и **оба оказались неверны**. Проверялось
настоящим CLI, той же формой спавна, что у Боба (`scratchpad/permprobe/probe.py`), а не чтением
документации — по `CLAUDE.md` §0.3 п.4.

| # | Прогон | Результат |
|---|---|---|
| A | `--allowedTools 'Bash(echo *)'`, команда `ls -la` (вне списка) | выполнилась, запроса разрешения нет |
| C | то же, **пишущая** `touch probe-created.txt` | **файл создан**, запроса нет |
| D | **точная форма спавна Боба** (без `--allowedTools`), пишущая команда | **файл создан**, запроса нет |
| E | `--disallowedTools Bash` | Bash исчез из набора — но модель **обошла запрет через `Write`** и создала файл |
| F | `--disallowedTools 'Bash(touch *)'` | 🔴 **запрет сработал**: событие `system/permission_denied`, сессия жива, модель получила ошибку и продолжила |

**Вывод 1 — пер-действенного гейта нет.** `--permission-mode acceptEdits` в headless-режиме
пропускает произвольный Bash молча. Значит и «Bash упирается в запрос разрешения» (описание
беады), и «OFF keeps the per-action gate that actually makes it structural» (докстрока
`wiring/coding.py`) — неверны, в противоположные стороны. Заведено отдельным P0 `bob-l3t`.

**Вывод 2 — ограничивает denylist, а не allowlist.** `--allowedTools` в наблюдаемом поведении
**расширяет**, а не сужает. Сужает `--disallowedTools`, причём на уровне шаблона команды.

**Вывод 3 — у отказа есть машиночитаемое событие.** `system/permission_denied` несёт
`tool_name`, `tool_use_id`, `decision_reason_type`, `message`. Это ровно тот шов, которого не
хватало для «Боб спрашивает owner'а»: не абстрактный `control_request`, а обычное событие потока,
которое уже проходит через `events()`.

**Вывод 4 — перечислять команды бесполезно.** Проба E: запретили `Bash` — модель сделала то же
самое `Write`'ом. Значит граница не может держаться на списке команд; держать её должна
**структура** (клон, отсутствие кредов, push-барьер), а denylist — только узкая страховка от
необратимого.

## Решение

Четыре среза, первый — предусловие.

### Срез 1. Включить изоляцию BOB-089 и развязать push-барьер

`coder.isolated_clone: true` → рабочее место становится клоном, окружение спавна теряет креды
owner'а (`PURGED_SPAWN_VARS`, подменный global-конфиг, `GIT_TERMINAL_PROMPT=0`). `fork_url`
оставляем пустым: клон поднимается из локального источника, апстрим не прописывается — сеть в
этом срезе не нужна.

🔴 **И меняем условие push-барьера.** Сейчас `guard_push=allow_bypass`: страховка от нечаянного
push включается **только вместе с ослаблением**, которое её же и обесценивает. Логика обратная
здравой. Барьер должен стоять **всегда**, а `allow_bypass` — влиять только на allowlist режимов.

Проверяется живым смоуком: сессия поднимается в `.clones/…`, `git remote -v` пуст или не ведёт
к origin owner'а, попытка сетевого push умирает на несуществующем хелпере.

### Срез 2. Стартовый промпт

`InteractiveSessionManager` после `runner.open(...)` скармливает **первый кадр** — задачу плюс
указание идти по `CLAUDE.md` (для эпика — через `/coordinator`, роли субагентами). Проба
подтвердила: первый кадр в открытый stdin принимается и запускает ход.

Текст промпта — чистая функция в домене (`bob.coding`), не строка в адаптере: он влияет на
поведение конвейера и обязан быть mutation-целью и предметом теста.

Флаг: `coder.pipeline_prompt` (default OFF) — без него спавн байт-в-байт прежний.

### Срез 3. Denylist необратимого + вопрос owner'у словами

Спавн получает `--disallowedTools` с **узким** списком необратимого и наружного: сетевой push,
`push --force`, правка remotes, `reset --hard`, `rm -rf`, `gh pr merge`, `curl`/`wget`. Всё
остальное (`pytest`, `ruff`, `mypy`, `bd`, `git status/add/commit`) едет само — что и требовалось
owner'ом от гибрида.

Событие `system/permission_denied` перехватывается в перекачке событий и превращается в **живую
реплику Бобу в личку**: «Упёрся в запрет: хочу выполнить `…`. Разрешаешь?» — без кнопок, ответ
словами (`BOB-101`). На «да» команда выполняется **повторным заходом**: `--resume <session_id>` с
временно снятым из denylist пунктом. 🔴 Отказ необратим для конкретного `tool_use`, «доразрешить»
на месте нельзя — это ограничение CLI, и оно названо честно, а не обойдено `bypassPermissions`.

Голос: вопрос про разрешение — **голос Боба** (канон BOB-090.D уже так и говорит), механика
прогона — GUPPI.

### Срез 4. Живой смоук конвейера

Не тест на фейке (§0.3 п.4): реальная сессия из лички, реальный `claude`, реальные субагенты.
Проверяем по PRD: постановка живой речью → сессия с контекстом → гейты проезжают → `bd` видит
беады → `dev`/`test`/`review` стартуют → ветка и PR, `main` не тронут.

## Что НЕ делаем

- **Не** пытаемся построить полный пер-действенный гейт поверх CLI: механизма для этого нет, а
  имитация дала бы третью иллюзию защиты в одном месте. Граница — структурная (клон без кредов).
- **Не** включаем `allow_bypass`: под ним нет даже denylist'а.
- **Не** перечисляем разрешённое: проба E показала, что список команд обходится другим
  инструментом.

## Риски

| Риск | Ответ |
|---|---|
| Denylist так же обходится другим инструментом, как в пробе E | Признаётся прямо: denylist — страховка от нечаянного, граница — клон. Проверить пробой на каждом пункте списка |
| `--resume` со снятым пунктом = дыра, если состояние переживёт сессию | Снятие одноразовое, на один заход; проверить, что следующий спавн снова с полным списком |
| Субагенты в клоне не увидят `.claude/` | `.claude/` трекается целиком → в клоне есть. Но это рассуждение: проверить смоуком (срез 4) |
| Конвейер сожжёт бюджет в фоне | Потолок прогона `coder.timeout` уже есть; для эпика — назвать явный потолок волн |

## Гейты

Стандартные: `pytest`, `ruff`, `mypy --strict`, чистая БД + `beadloom lint --strict`,
`sync-check`, `beadloom ci`. Mutation — на чистом ядре среза 2 (текст стартового промпта) и
среза 3 (разбор события отказа), обе функции живут в домене, не в адаптере (§0.3 п.7).
BDD `.feature` — на сценарии PRD С-1 и С-3 (наблюдаемое поведение через границу).
