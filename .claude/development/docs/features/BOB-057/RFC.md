# RFC: BOB-057 — «Боб знает, чего не знает» (эпистемическая проверка)

> **Status:** Approved
> **Created:** 2026-07-01
> **PRD:** `.claude/development/docs/features/BOB-057/PRD.md`
> **Решения (под утв.):** Tier-0 `VolatilityJudge` (консервативный) в reply-пути · ОДИН прямой web_search
> (не через registry/tool-loop → не гейт BOB-052; internal public-verify) · находка → контекст генерации
> (факты+тон) · живая адресная интерим-реплика (Tier-0 + fallback на BOB-055) · сбой/затяжка → честный
> хедж · всё декоративно (сбой не ломает обычный ответ).

---

## Идея решения

Перед генерацией ответа Боб делает **один быстрый метакогнитивный шаг**: Tier-0 `VolatilityJudge` смотрит
на вопрос+контекст и решает — зависит ли хороший ответ от **свежего волатильного факта**, которого память
может не знать. Если да (консервативно) → Боб (а) роняет **живую адресную реплику** «погоди, проверю X»,
(б) делает **ОДИН** прямой `web_search`, (в) вплетает находку в контекст генерации → ответ и **тон**
подстраиваются в его голосе. Если нет → обычный ответ, **ноль задержки**. Всё поверх обычного пути,
декоративно.

## Поток (single-pass, в `_compose_reply`)

```
входящий ход
  → VolatilityJudge.assess(вопрос + недавний контекст)   # Tier-0, ~1–2с, консервативный
      needs_check=False → обычная генерация (0 задержки)   ← US-2 не зануда
      needs_check=True:
        1. живая интерим-реплика (US-3b): gateway.reply(chat_id, <адресная фраза про предмет>)
        2. web_search(query) ОДИН раз, tighter timeout       ← US-3 не 5 минут
             ok       → grounded-заметка «СВЕЖАЯ ПРОВЕРКА: …» в контекст
             fail/timeout → hedge-заметка «свериться не вышло; честно оговорись»  ← US-6
        3. обычная генерация ответа С этой заметкой → факты+тон  ← US-1/US-4
```

## Доменная модель (судья) — зеркалит BOB-049/052

`domain/personality/volatility_judgment.py` (стиль `response_judgment.py`):

```python
@frozen(slots=True)
class VolatilityVerdict:
    needs_check: bool     # проверять ли (консервативно False по умолчанию)
    query: str            # поисковый запрос (напр. «текущие ставки ОФЗ РФ 2026»)
    topic: str            # человекочит. предмет для живой реплики («свежие ставки»)

class VolatilityJudge(Protocol):
    async def assess(self, ctx: VolatilityContext) -> VolatilityVerdict: ...
```

Плюс чистый парсер (`parse_volatility_verdict`) — терпимый к формату Tier-0 (как `parse_response_choice`).

## Судья (infrastructure)

`infrastructure/llm/volatility_judge.py` — `LlmVolatilityJudge` (Tier-0 через `LLMRouter`, новый
`TaskType.VOLATILITY_JUDGE`; pure prompt-builder + parser; **raise-on-failure**). Промпт —
**консервативный** (US-2): проверять ТОЛЬКО если {факт реально протухаем: ставки/цены/«сейчас/актуальный/
последний»/рейтинги/версии/кто у власти/погода} И {меняет ответ}. Стабильное (история/математика/
определения/мнения/память Боба/болтовня/шутки) → `needs_check=False`. По умолчанию — НЕ проверять.

## Проверка — ОДИН прямой web_search (не tool-loop)

- Реюз `WebSearchProvider` (BOB-053 стриминг BOB-055), **инъектируется в `HandleMessage`** (optional).
  Вызов **прямой**: `await provider.search(verdict.query)` — НЕ `registry.dispatch("web_search")`.
- 🔴 **US-5 / authz:** прямой internal-вызов означает, что это НЕ per-sender привилегия BOB-052 (никто не
  просил инструмент; раскрывается только публичная веб-инфа, не внутрянка/owner-данные). Работает для всех
  (Лёша/гость). Гейт BOB-052 остаётся на пользовательских запросах инструментов; internal-verify его не
  трогает — и не может утечь приватное (поиск публичный).
- **Латентность (US-3):** отдельный, **более короткий** таймаут (`verify.timeout_seconds`, напр. 60–90с) —
  меньше глубокого пути; превышение → hedge (не ждём «5 минут»).

## Живая адресная интерим-реплика (US-3b) — апгрейд BOB-055-анонса

BOB-055 `GatewayProgressAnnouncer` шлёт seeded-фразу. Здесь Боб **знает предмет** (`verdict.topic`) и
**адресата** (имя отправителя) → генерируем **живую** реплику Tier-0 в голосе Боба: «Леш, надо кое-что
проверить, погоди…». Реализация: расширить анонсер контекстным режимом (`announce(topic, sender_name)`)
или лёгкая Tier-0-генерация в reply-пути. 🔴 **Декоративно:** сбой генерации → fallback на seeded-фразы
BOB-055 → или молчание; ход не ломается. Латентность +1–2с тонет на фоне поиска.

## Вплетение находки → факты + тон (US-1/US-4)

Находка входит в контекст Tier-1-генерации как grounded-заметка: «СВЕЖАЯ ПРОВЕРКА (веб): <ответ+ключевые
факты>. Учти актуальное; если картина изменилась — отреагируй по-своему (в т.ч. тоном)». Тон подстраивается
**сам** через генерацию (увидел «ставки тоскливые» → отшутился) — отдельно шутку не программируем. Хедж-
заметка (при сбое): «Свериться со свежими данными по <topic> не вышло — не выдавай устаревшие цифры за
точные, сделай честную оговорку».

## 🔴 Отказоустойчивость / инварианты

- **Судья декоративен:** сбой `assess` → `needs_check=False` (обычный ответ), не блокирует/не ломает ход.
- **Интерим-реплика декоративна:** сбой → seeded fallback / молчание.
- **US-6 честность:** сбой/пустой поиск → честный эпистемический хедж (не уверенная устаревшая цифра, не
  выдумка). Инвариант BOB-053 «полный Боб / честный нотис» цел.
- **US-2 не зануда:** порог судьи консервативный; тест-инвариант «болтовня/мнения/стабильные факты →
  needs_check=False».
- **Один поиск** (не петля) — глубокое расследование это BOB-056.

## Слои (DDD)

- **domain:** `VolatilityVerdict`/`VolatilityContext`/`VolatilityJudge` + парсер (чистые).
- **application:** verify-шаг в `_compose_reply` (судья → интерим → один web_search → grounded/hedge
  заметка → генерация); инъекция `VolatilityJudge` + `WebSearchProvider` в `HandleMessage`; интерим-реплика
  (расширенный анонсер).
- **infrastructure:** `LlmVolatilityJudge` (Tier-0, `TaskType.VOLATILITY_JUDGE`); интерим-генерация (Tier-0).

## Риски и митигации

- **Гипер-триггер (зануда)** → консервативный промпт + тест-набор «не проверять»; порог тюнингуется; по
  умолчанию False.
- **🔴 Латентность casual-проверки** → web_search Qwen сам по себе ~45–110с (серверный поиск). Митигации:
  живая интерим-реплика + короткий таймаут + hedge. **Реальный рычаг скорости — быстрый search-провайдер
  (Tavily, ~секунды) за тем же портом `WebSearchProvider`** — см. открытое решение №5.
- **Обход authz** (гость косвенно инициирует поиск) → безопасно: поиск публичный, приватное/внутрянка не
  раскрываются; BOB-052 на пользовательских tool-запросах цел. Ревью проверит границу.
- **Двойная генерация** → НЕ делаем draft→revise; single-pass (судья до генерации) — одна Tier-1-генерация.
- **Тон не подстроился** → grounded-заметка явно просит отреагировать в голосе Боба; тест на «ставки
  тоскливые → ироничный ответ» (семантически, не по подстроке).

## Открытые решения (под утверждение)

1. **Точка проверки:** pre-answer single-pass (судья ДО генерации, одна Tier-1-генерация с находкой) —
   **рекомендую** (дешевле draft→revise, меньше латентность).
2. **Прямой web_search (не tool-loop) → не гейт BOB-052** (internal public-verify для всех) —
   **рекомендую** (иначе кейс Лёши-гостя не работает; поиск публичный, утечки нет).
3. **Интерим-реплика:** живая Tier-0-генерация из `topic`+имя, fallback на seeded BOB-055 —
   **рекомендую** (US-3b; латентность тонет).
4. **Сбой/пусто:** честный эпистемический хедж, судья/интерим декоративны — **рекомендую**.
5. **Провайдер для verify:** v1 — реюз Qwen web_search (работает; латентность прикрыта интеримом+хеджем).
   **Открытый вопрос:** хочешь ли сразу **быстрый Tavily** (секунды, снепповее для casual-проверки, но
   новый ключ) за тем же портом — или оставить Qwen и добавить Tavily позже? **Рекомендую v1 на Qwen**,
   Tavily — как явный upgrade латентности потом.
