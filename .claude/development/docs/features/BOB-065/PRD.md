## Проблема

Аудит (сессия `13b1e49b`) нашёл два фундаментальных препятствия для чистой domain-first
реорганизации (Фаза 3, эпик BOB-062):

- **God-ports.** `src/bob/domain/ports.py` — один файл на ~1153 строки, ~49 портов и
  значений-типов из всех доменов сразу. Его импортируют **141 файл** (огромный blast radius).
  Пока все контракты свалены в один модуль, вертикальные срезы (personality/conversation/
  memory/…) нельзя выделить: любой перенос тянет за собой весь `ports.py`, а граница
  «кто чем владеет» невидима.
- **Правило слоёв не энфорсится.** Инвариант Clean Architecture
  `domain ← application ← infrastructure` только задокументирован (через `depends_on`),
  но `beadloom lint` проверяет ТОЛЬКО `domain-needs-parent`. Нарушения направления
  зависимостей невидимы → архитектура дрейфует без сигнала.

Без этих двух вещей Фаза 3 (per-module вертикали) будет резать вслепую и рискует
закрепить те же нарушения.

## Цели

- **Каждый домен владеет своими контрактами.** Порты и значения-типы разложены по
  модулям; общее инфраструктурно-нейтральное ядро (Clock, EventBus, LLMProvider,
  JsonValue…) вынесено в общий kernel.
- **Ноль регрессий и ноль «большого взрыва».** 141 импортёр продолжает работать без
  изменений на время миграции — через транзитный re-export-шим `domain/ports.py`.
- **Архитектура с зубами.** `beadloom lint` начинает проверять направление слоёв
  `domain ← application ← infrastructure`, делая дрейф видимым в CI.
- **Готовность к Фазе 3.** После этой фичи вертикальные срезы (#11–#16) можно резать
  по модулям без раскопок в God-файле.

## Не-цели

- НЕ переносить сам код доменов в domain-first дерево (это Фаза 3 / BOB-062).
- НЕ декомпозировать `handle_message.py` / `app.py` (#9/#10 — внутри Фазы 3).
- НЕ удалять re-export-шим в этой фиче (удаление — #18, после реорга).
- НЕ включать правило слоёв в «жёстком» режиме, если это потребует массового
  переписывания до реорга (стратегия строгости — предмет RFC).

## Пользовательская ценность

Пользователь здесь — сопровождающий (Владимир) и Боб-кодер. Ценность:
- смотря на дерево контрактов, сразу понятно, какому домену что принадлежит;
- изменение одного домена не тащит за собой чужие контракты (ниже связность, меньше слияний);
- CI ловит нарушение архитектурных границ до мержа, а не постфактум.

## Критерии успеха

- `domain/ports.py` больше не God-файл: контракты распределены по модулям + shared kernel;
  импорт `from bob.domain.ports import X` продолжает работать (шим) для всех 141 файла.
- `pytest`, `ruff`, `mypy --strict` зелёные; поведение не изменилось (рефактор behavior-preserving).
- `beadloom lint --strict` включает правило направления слоёв и проходит зелёным на текущем коде
  (или чётко перечисляет предсуществующие нарушения как явный список к устранению).
- BOB-Issues #7 закрыт; #8 введён (жёсткое включение «зубов» — по плану после реорга).
