# PRD: BOB-094 — переезд Боба на VPS (не спать с ноутом + раздельный UID)

> **Status:** Approved
> **Created:** 2026-08-18
> **Bead:** `bob-jgm` (`type: feature`, P1)
> **Закрывает:** BOB-093 (`bob-r9l`) — раздельный UID тем же переездом

---

## Цель owner'а

Боб не должен жить на ноутбуке. Повод не теория: ноут лежал в рюкзаке в режиме сна с 6 по 12
августа — процесс формально «работал» (тики шли, 124 рефлексии в `episodic_log`), а снаружи был
глух: входящих ноль за шесть дней, лечится только ручным перезапуском. Компаньон, который «есть»
только когда открыт ноут, — не компаньон.

## Два драйвера, сходящиеся в одном решении

1. **Доступность.** VPS не спит. Плюс автозапуск при перезагрузке, авторестарт при падении,
   наблюдаемость «я оглох» (сейчас о немоте узнаёт только owner — по молчанию).
2. 🔴 **Безопасность (BOB-093).** Под UID owner'а не закрыть две дороги, найденные в BOB-089:
   - **локальная файловая** — путь к репозиторию owner'а читается из reflog клона, локальному
     транспорту креды не нужны (пять шагов до сдвига ствола, воспроизведено);
   - **прямой ssh** — OpenSSH раскрывает `~` по `passwd`, а не по `HOME`, окружением не отрезать.
   Отдельный системный пользователь на отдельной машине закрывает обе разом — структурно.

## Решения owner'а (2026-08-18)

- **VPS есть, доступ по SSH есть.** Хостер owner'а (Индия), vCore x4 / 8 ГБ ECC / 90 ГБ NVMe.
  Проверено ранее, что claude code оттуда работает.
- 🔴 **Локальный дублёр на VPS без GPU — НЕ ставим.** `qwen3:8b` крутится на GPU M1 Max; на CPU-VPS
  он медленный/невозможный. Решение: **vision-и-речь — облачная способность**, при отвале Tier-1
  Боб честно молчит / говорит «сейчас не могу», а не галлюцинирует слабой моделью. Тот же принцип,
  что принят для мультимодальности (BOB-104). Это МЕНЯЕТ поведение на VPS осознанно и называется
  прямо, а не замалчивается.

## Что делает эта работа автономно (провайдер-независимо)

- **systemd-юнит** под отдельным системным пользователем `bob` (не owner): `Restart=on-failure`,
  `WantedBy=multi-user.target` (автозапуск), окружение из защищённого файла, рабочий каталог —
  домашний Боба, НЕ репозиторий owner'а.
- **Скрипт бутстрапа**: создать пользователя `bob`, развернуть venv (`uv sync`), поставить `bd`,
  разложить конфиг и каталоги, поставить юнит. Идемпотентный.
- **Наблюдаемость «я оглох»**: N подряд неудачных поллингов — это **состояние-диагноз**, а не
  строка в логе. Стыкуется с BOB-103 (там уже считается `consecutive_failures` на bot) — поднять
  этот счётчик до наблюдаемого сигнала (порог → пометка «оглох», сброс на первом успехе), доступного
  owner'у (лог/статус). 🔴 Без ложной тревоги: единичный блип — не «оглох».
- **Бэкап `data/`**: периодический дамп SQLite (`bob.db` — душа, память, отношения) в отдельное
  место; ротация бэкапов. Восстановление проверить.
- **Логи**: ротация уже есть (BOB-103, RotatingFileHandler); на VPS доступ owner'а к ним (путь,
  права чтения).
- **Runbook переноса**: пошагово — что owner делает руками (см. ниже), в каком порядке, как
  откатиться.

## Секреты и автодеплой (решение owner'а 2026-08-18)

🔴 **Секреты — в GitHub Environment `bob-vps`.** Ключи Tier-1/Tier-0 и токены ботов — в Secrets;
несекретные `*_APP_ID`/`*_REPO` — в Variables (открытые); значения через меня не печатаются.
🔴 _Исправлено по факту 2026-08-18: `.env` **НЕ** пересобирается из секретов каждый деплой — он лежит
на VPS постоянно (`/opt/bob/.env`, 600, gitignored, переживает `git checkout`). Секреты в GitHub —
запись/бэкап и вход для будущей материализации, не рантайм-источник._

🔴 **Автодеплой + рестарт.** Тег `v*` → GitHub Actions по **SSH-ключу** выкатывает на VPS
(`git checkout <tag>` → `uv sync` → `systemctl restart bob`; `.env` уже на месте). Никакого ручного
cutover-кода после первичной установки.

🔴 **Боб по-человечески предупреждает о перезапуске.** Перед остановкой (SIGTERM от `systemctl
restart`) Боб в СВОЁМ голосе говорит, что обновляется и скоро вернётся; после старта — что вернулся.
Не строка из деплой-скрипта, выдающая себя за Боба, а **его собственный голос** (канон BOB-090.D,
как `rule_voice` в BOB-096 — без скриптованности). Это и есть «предупреждение о перезапуске».

## Что всё равно требует owner'а (я не могу и не должен)

- 🔴 **Значения секретов** — owner кладёт в GitHub Secrets и переносит `data/bob.db`; я к значениям
  не прикасаюсь и не печатаю. Deploy-workflow и runbook дают форму, значения — owner.
- **Первичная установка**: SSH-доступ, запуск `bootstrap.sh`, `systemctl enable bob`, регистрация
  VPS-хоста и его SSH-ключа как GitHub Secret для деплоя.
- **Первый перенос `data/bob.db`** (душа Боба) — руками owner'а по runbook (остановить ноут →
  перенести → поднять на VPS).
- **Провайдер-специфика**: firewall (Боб только исходящие + входящий SSH для деплоя).

## Связь с BOB-095 (CI)

Автодеплой — это CD (выкатка на мёрж). CI по PR (BOB-095, `beadloom ci` на pull_request) — ГЕЙТ
перед мёржем. Идеально: деплой идёт только на зелёном `main`. BOB-095 пока нет; на переходный период
`main` держится дисциплиной, деплой-workflow МОЖЕТ прогнать быстрый гейт до выкатки (назвать явно,
чтобы «задеплоил сломанное» не стало новым классом).

## Инварианты

- **И-1.** Боб на VPS под **отдельным** системным пользователем, не под owner'ом.
- **И-2.** Переживает перезагрузку (автозапуск) и падение (авторестарт).
- **И-3.** «Оглох» виден как **диагноз**, а не как тишина.
- **И-4.** Секреты owner'а не проходят через меня; перенос — его руками по runbook.
- **И-5.** Одна живая душа: `data/bob.db` переносится целиком — память, отношения, self-model не
  теряются. Не «новый Боб», а тот же, на новом хосте.
- **И-6.** При отвале Tier-1 на VPS Боб честно молчит, а не галлюцинирует (нет локального дублёра).

## Границы

- **Не** контейнеризация (Docker/k8s) — один процесс, systemd достаточно; лишний слой не нужен.
- **Не** миграция БД на сервер (Postgres) — SQLite остаётся, переносится файлом.
- **Не** мультирепо/оркестрация (BOB-048/BOB-097) — отдельные линии.
- **Не** автоматический cutover — секреты и запуск за owner'ом.
