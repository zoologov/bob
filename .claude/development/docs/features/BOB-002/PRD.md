# PRD: BOB-002 — Ближний батч: Rich/стриминг + Authz + Резилентность + Capability-шов

> **Status:** Approved
> **Created:** 2026-06-19

---

## Проблема

P0 (BOB-001) живой в `main`: личность + память + Tier 1. Но перед тем, как делать Боба **живым**
(проактивность, поиск по памяти, Bobiverse), нужно закрыть фундамент:

- **Форматирование/стриминг хрупкие.** Боб стримит через хак на `editMessageText`-loop (батч/троттл),
  без форматирования — markdown от модели приходит литералами. Telegram в 2026 дал нативное:
  `sendMessageDraft` (стрим) + **Rich Messages** (`sendRichMessage`/`sendRichMessageDraft`,
  document-grade, под ИИ) + блок `RichBlockThinking`.
- **Нет авторизации.** Боб отвечает **кому угодно**, кто пишет. До автономности/расширения это
  недопустимо.
- **Тики падают на сетевых сбоях.** Live-тест показал: idle-heartbeat словил `Server disconnected`
  (пойман, но это сигнал — петля должна быть устойчивой; это фундамент автономной петли).
- **Нет слоя навыков.** Боб не осознаёт, что умеет, и не может вызывать инструменты. Нужен стабильный
  **Capability-шов** (фундамент для `search_memory`, `send_proactive`).

## Влияние

Это **подготовка почвы под «живого» Боба** и **предпосылка безопасности** (authz — до любой автономии).
Один батч закрывает: правильный UX сообщений, защиту доступа, надёжность 24/7-петли и слой
возможностей, на котором поедут «Память» и «Автономность». GUPPI обретает роль исполнителя capabilities
(по канону книги).

## Цели (измеримые)

- [ ] **Нативный стриминг** через `sendMessageDraft` заменяет `editMessageText`-хак (плавный токен-стрим).
- [ ] **Rich Messages**: ответы Боба форматируются (заголовки/списки/код/цитаты) через
      `sendRichMessage`/`sendRichMessageDraft` (структурное дерево `RichMessage`, **не** markdown), с
      конвертером **markdown→RichMessage**, вызовом через **сырой Bot API** (пока PTB не поддержит 10.1),
      и **fallback на plain** при ошибке. Не использовать edit+rich (известный баг).
- [ ] **`RichBlockThinking`** заложен под монолог/размышления Боба (опциональный «думающий» блок).
- [ ] **Авторизация:** только **owner + allowlist** Telegram `user_id`/`chat_id`; чужие игнорируются;
      **scope по чату** (только приватная supergroup); owner может авторизовать других.
- [ ] **Резилентность тиков:** heartbeat переживает транзиентные сбои (retry/backoff), петля не падает.
- [ ] **Capability-шов:** контракт `Capability` (имя/описание/JSON-схема/`async execute`/permission) +
      `CapabilityRegistry` + **tool-use петля** (Боб эмитит tool-call → реестр диспатчит = «GUPPI
      исполняет» → результат → ответ) + **манифест возможностей в контексте** (Боб знает, что умеет).
      Forward-compatible с будущей полной плагин-системой.

## Не-цели (вне BOB-002)

- Полная **плагин-система** (авто-дискавери, hot-reload, sandbox, permission-tiers, **self-creation**) —
  отдельный эпик под самораширение, за тем же швом.
- **Проактивный чат** (#5-A), **Goal Engine**, агентность вне чата — следующие шаги.
- **`search_memory`**, **векторный/гибридный recall** (эмбеддинги) — эпик «Память».
- Перевод rich-вызовов на нативные методы PTB — когда выйдет поддержка 10.1 (сейчас сырой API).
- Мульти-пользовательские роли сверх owner/authorized, биллинг/коммерция.

## Пользовательские истории

### US-1: Красивые, плавно стримящиеся ответы
**Как** пользователь, **я хочу** видеть ответы Боба с нормальным форматированием (заголовки, списки,
код, цитаты) и плавным стримингом, **чтобы** общение ощущалось как с современным ИИ, а не как «стена
текста».

**Критерии приёмки:**
- [ ] Стрим идёт через `sendMessageDraft` (без `editMessageText`-хака).
- [ ] Форматированный ответ через Rich Messages; при ошибке — корректный fallback на plain.
- [ ] Опционально: размышления Боба выводятся в `RichBlockThinking`.

### US-2: Доступ только для своих
**Как** owner, **я хочу**, чтобы с Бобом могли общаться только я и авторизованные мной пользователи,
**чтобы** Бобом/Bobiverse не пользовался кто попало.

**Критерии приёмки:**
- [ ] Сообщения от не-allowlist `user_id` и из не-разрешённых `chat_id` **игнорируются**.
- [ ] Owner (я) задан в конфиге; owner может авторизовать других (`/authorize <user_id>`).
- [ ] Даже при утечке токена в чужих чатах Боб не отвечает (scope по чату).

### US-3: Боб не умирает от сетевых сбоев
**Как** owner, **я хочу**, чтобы Боб переживал транзиентные сетевые ошибки, **чтобы** он был надёжно
живым 24/7.

**Критерии приёмки:**
- [ ] Тик/вызов с транзиентной ошибкой ретраится с backoff; петля продолжает работать.
- [ ] Сбой одного тика не валит процесс и не глушит остальные тики.

### US-4: Боб знает, что умеет (фундамент)
**Как** пользователь, **я хочу**, чтобы Боб осознавал свои возможности и мог их применять (подкидывать
задачи GUPPI), **чтобы** он рос в сторону «живого» агента, а не bot'а вопрос-ответ.

**Критерии приёмки:**
- [ ] Манифест capabilities попадает в контекст Боба (он перечисляет, что умеет).
- [ ] Tool-use петля работает: модель эмитит tool-call → реестр исполняет → результат возвращается.
- [ ] Шов forward-compatible (добавить навык = зарегистрировать объект; потребители не меняются).

## Критерии приёмки (общие)

- [ ] Стриминг на `sendMessageDraft`; Rich Messages через сырой API с fallback; `RichBlockThinking` заложен.
- [ ] Authz: allowlist + scope по чату работают; чужие отсечены; owner может авторизовать.
- [ ] Heartbeat-тики устойчивы к транзиентным сбоям (retry/backoff), петля не падает.
- [ ] Capability-шов: контракт + реестр + tool-loop + манифест; forward-compatible.
- [ ] Тесты ≥80%, `ruff`/`mypy --strict` чисто, `beadloom ci` зелёный. Где трогаем LLM — тесты на
      реалистичный формат reasoning-моделей.
