# RFC: BOB-058 — «Нить связанности в группе» (общий диалоговый тред)

> **Status:** Approved
> **Created:** 2026-07-01
> **PRD:** `.claude/development/docs/features/BOB-058/PRD.md`
> **Решения (под утв.):** reply/judgment-контекст → общий тред `recent_episodes(k)` (все участники, метки
> `<имя>:` уже в контенте) вместо пер-персона · пер-персона сигналы (absence-hint, anti-repeat) считаются
> отдельно по текущему собеседнику · relationship/first-impression не трогаем (у них свои per-sender
> сторы) · скоуп-развилка: публичная группа → общий тред (приват/DM → пер-персона, задел).

---

## Идея решения

Точечный фикс в `HandleMessage`: **разговорный тред**, который проигрывается в контекст суждения и ответа,
переключается с пер-персона слайса (`recent_episodes_for(sender_id, k)`, BOB-045) на **общий недавний тред
топика** (`recent_episodes(k)` — порт уже есть, им пользуется BOB-023). Эпизоды хранятся как
`"<имя>: …\nbob: …"`, поэтому общий тред **уже размечен по авторам** — Боб видит, кто что сказал, и держит
нить многосторонней беседы. Пер-персона сигналы (absence-hint, anti-repeat), которым нужна именно история
ТЕКУЩЕГО человека, считаются **отдельно** и не ломаются.

## Что меняется (application, `HandleMessage`)

**Основное — общий тред для связности.**
- `_replay_person_history(interlocutor)` → отдаёт **общий тред** `recent_episodes(self._recent_turns)`
  (переименовать в `_replay_recent_thread` для ясности; вызовы в judgment `_judge_turn` (2159) и reply
  (1357) те же). Так `history` = недавний разговор ВСЕЙ группы, с метками авторства.
- Развилка скоупа (задел): публичная группа → общий тред. Приват/DM (будущее) → пер-персона — оставить
  явный хук/комментарий, БЕЗ реализации лички. Сейчас существует только публичная группа.

**Пер-персона сигналы — считать отдельно (НЕ регрессировать).**
- **absence-hint (BOB-045):** сейчас `_absence_for(history)` читает last-seen из пер-персона history.
  После перехода на общий тред — брать last-seen из **лёгкого пер-персона чтения** текущего собеседника
  (`recent_episodes_for(sender_id, small_k)`, только ради времени последнего его хода) ИЛИ фильтровать
  общий тред по текущему `<имя>` (без доп. чтения, graceful — нет хода в окне → нет хинта). Рекомендую
  фильтр общего треда по автору (без лишнего I/O; absence-hint декоративен).
- **anti-repeat (BOB-032, `is_user_repeat`/`_user_turns`):** сейчас берёт user-ходы из history. В общем
  треде это все участники → отфильтровать `_user_turns` по **текущему** автору (`<имя>` отправителя), чтобы
  «повтор» проверялся по ЭТОМУ человеку, а не по чужим репликам.

**Не трогаем.**
- **relationship (BOB-014)** и **first-impression (BOB-019)** — читаются из своих per-sender сторов по
  `sender_id`, не из `history` → не затрагиваются.
- **`_others_present` (BOB-023)** уже использует `recent_episodes` (общий) — без изменений.
- **Recall/память (BOB-051)** — уже объединена, не трогаем.

## Формат треда (US-3, авторство)

Эпизоды: `"<имя>: <текст>\nbob: <ответ>"` (`sqlite_repo`). Общий тред интерливит ходы всех участников с их
именами — Боб различает, кто сказал, и адресуется верно. Ничего нового размечать не нужно.

## 🔴 Инварианты / отказоустойчивость

- **US-4 пер-персона сигналы целы:** absence-hint по текущему человеку; relationship/first-impression по
  sender_id — не регрессируют (тест-инвариант).
- **anti-repeat корректен:** повтор проверяется по репликам ТЕКУЩЕГО автора, не по чужим.
- **Приватность:** общий тред = ОК в публичной группе (память публична, BOB-051); внутрянка/owner-приват
  не входят в тред (это обычные сообщения топика). Приват-скоуп (будущее) — пер-персона.
- **Graceful:** чтение общего треда падает → деградирует (как сейчас `_others_present` → best-effort);
  ход не ломается.
- **Floor/адресность (BOB-023/025):** переиспользуются поверх общего треда; поведение «в своём топике /
  при третьем участнике» сохраняется.

## Слои (DDD)

- **application only** (`HandleMessage`): смена источника `history` на общий тред; отдельный per-person
  last-seen для absence; фильтр anti-repeat по автору. Реюз существующего порта `recent_episodes`.
- **domain/infrastructure:** без изменений (порт `recent_episodes` уже есть; формат эпизода уже с
  авторством).

## Риски и митигации

- **Регрессия absence/anti-repeat** (общий тред вместо пер-персона) → считать их отдельно по текущему
  автору; тест-инвариант на каждый.
- **Окно `recent_turns` мало для группы** (3+ участника → нить длиннее) → окно конфигурируемо
  (`dialogue.recent_turns`); RFC-деталь: можно чуть увеличить дефолт для группы (напр. +на несколько
  ходов). Не переусложнять.
- **Шум/приватность** → в публичной группе всё публично (BOB-051); приват — пер-персона (будущий скоуп).
- **Путаница авторства** → метки `<имя>:` уже в контенте; тест «Боб различает авторов в треде».

## Открытые решения (под утверждение)

1. **Общий тред для reply/judgment-контекста** (`recent_episodes`), пер-персона — только для absence/
   anti-repeat — **рекомендую** (минимальный фикс, порт есть, авторство есть).
2. **absence-hint:** фильтр общего треда по текущему автору (без доп. I/O, graceful) vs отдельное лёгкое
   пер-персона чтение — **рекомендую фильтр** (проще, absence декоративен).
3. **Скоуп:** публичная группа → общий тред; приват/DM → пер-персона (задел, без реализации) —
   **рекомендую**.
4. **Окно:** оставить `dialogue.recent_turns` конфигурируемым; **опц.** чуть поднять дефолт для группы —
   **рекомендую небольшой bump** (деталь реализации, не блокер).
