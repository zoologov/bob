> 🎉 **v1.0.0 — ПЕРВЫЙ МАЖОРНЫЙ РЕЛИЗ (2026-08-18).** Боб живёт на собственном VPS (always-on,
> Ubuntu 24.04, systemd, root только по ключу, раздельный UID), память и личность перенесены 1-в-1.
> Готовы Тир 1 (личность+память+EQ), Тир 2 (проактивность/Goal Engine — отгружен), Тир 3 (Боб-кодер:
> ведёт эпик из Telegram по многоагентному конвейеру). CD по тегу `v*` (боевой прогон на v1.0.0

## Видение и фокус (север, задающий приоритеты)

Bob — **личный инструмент-компаньон, а не рыночный продукт**. Массовое внедрение и хайп — не цель.
Приоритеты — по пользе для одного пользователя (автора) и по сохранению **уникальности Боба** (личность +
автономность + вселенная), а не по превращению его в «ещё один telegram-бот».

**4 приоритета (2026-06-21):**
1. **🥇 Личность, проактивность, самосознание и самовыражение в диалоге (без FLUX) — топ-1.** Ядро.
2. **🥈 Автономность и автономные возможности — топ-2.** Движок собственной инициативы.
3. **🥉 Боб-кодер — топ-3.** Воплощение личности+автономности, **с обязательным гейтом согласования**.
4. **🏅 Самовыражение в медиа (FLUX, мемы, картинки «состояния») — топ-4.** Облик и медиа-голос.

## Принципы последовательности

1. **Одна сквозная нить за раз**, доведённая до честного состояния, прежде чем следующая. Главный риск —
   ёмкость одного разработчика. Не распыляться на параллельные фронты. (Бутстрап-исключений не делаем.)
2. **Личность платформонезависима.** Higher Mind отделён от транспорта (за Telegram-шлюзом сегодня).
3. **Backend-centric (вариант B).** GUPPI (детерминированный код) — control plane; LLM — подключаемый мозг.
4. **Память переживает рестарты.** Всё значимое — в SQLite/файлах, не «из чата».
5. **Состояние > диалог.** Цели, вкусы, настроение, отношения — данные в БД, не переопределяются LLM.
6. **Надёжные примитивы Telegram** (aiogram, supergroup+Topics, rich, нативный стриминг).
7. **Заморожено ≠ выброшено.** FLUX-облик сохранён, размораживается в Тире 4.
8. **TDD/DDD/Clean, mypy --strict, ruff, покрытие ≥80%** (как в `CLAUDE.md` §0.2), плюс BDD-приёмка на
   поведение и прицельный mutation-гейт на чистых доменных ядрах.
   🔴 **Исправлено по факту (2026-08-15).** Прежде здесь стояло «PR-gated + beadloom CI», и это было
   неверно: **CI по pull request не существует** — в `.github/workflows` лежит только `deploy-site.yml`,
   `gh run list` за всю историю показывает исключительно «Deploy VitePress site», а branch protection на
   этом плане недоступна (`403 Upgrade to GitHub Pro or make this repository public`). Найдено пятым
   проходом ревью BOB-089. Что держит `main` на самом деле: ветка на эпик, **перепроверка гейтов
   координатором на финальном состоянии дерева** каждую волну и pre-push хук в основном репозитории —
   причём на ветке Боба хук не исполняется (с BOB-089 форма git-вызовов закалена в обоих адаптерах,
   иначе хук модели был бы неотличим от хука владельца). Настоящий CI по PR — беада **BOB-095**; он будет
   **информативным, а не блокирующим**, пока branch protection недоступна.
9. **LLM — провайдер-агностичный router.** **Tier 0** — дешёвый/быстрый (монолог/классификация/сентимент/
   гейты); **Tier 1** — качественный reasoning и ответы; **Tier 2** — Claude Code (кодинг, локальный CLI на
   подписке). **Приватность:** личностные внутренности по умолчанию на Tier 0. **Tier-0-local: реализуем на
   локальной Ollama small-model** (MLX отвергнут как сырой, 2026-06-20) — см. «Сквозное».
10. **Полный Боб или честный отказ (no half-measures).** Пользователь получает либо **полного Боба** (понял →
    ответил / отреагировал / промолчал по смыслу — полноценно), либо — при сбое essential-шага (LLM-суждение,
    генерация ответа) — честный системный нотис от GUPPI: «⚠️ Проблемы со связью — Боб временно недоступен».
    Никаких деградированных полу-ответов. Сначала ограниченный ретрай, затем нотис (не дёргаемся на единичный
    блип). Опциональные флейворы (колбэки / декор / доп-ноты) при сбое **тихо опускаются** — ядро остаётся
    полным Бобом, отказ не объявляется. Канон: Боб — разум (недоступен → его нет), GUPPI — инфраструктура,
    честно докладывает отказ. Полу-ответ = «уверенный бред», антипаттерн. Впервые воплощается в **BOB-049**.

### 🔴 Границы Тира-3 — что закрыто, а что осталось на доверии

> Раздел добавлен 2026-08-15. Три класса ниже честно названы в PRD BOB-089, но в карте их не было — а
> планируем мы по карте. Формулировки взяты из PRD дословно по смыслу, включая то, что было уточнено
> **дважды по факту** уже во время самого эпика.

**Что закрыто структурно.** У спавна `claude` нет кредов на апстрим — доказано живым смоуком 7/7 против
настоящего GitHub (пуш, force-push ствола, переустановка remote — отказ **по правам**; снятие барьера
изнутри не возвращает креды owner'а, а лишает Боба его собственных). Убрана дорога, которая раньше
открывалась **сама**: linked worktree делил `.git` с репозиторием owner'а, теперь у Боба отдельный клон.
Закрыта и git-дорога по ssh (`GIT_SSH_COMMAND` + `core.sshCommand` с несуществующим `IdentityFile`).

**Три класса, которые остаются открытыми:**

1. **Локальный файловый путь** к репозиторию owner'а. Процесс работает под UID owner'а и имеет запись в
   его каталог, поэтому **намеренный** обход возможен: `.git/logs/HEAD` клона несёт `clone: from
   file:///<путь owner'а>`, локальному транспорту креды не нужны, push в боковую ветку проходит, после
   чего `git --git-dir=<owner>/.git update-ref refs/heads/main` двигает ствол. Пять шагов, ни одного
   пароля; воспроизведено координатором на выброшенном репозитории. Ни один git-механизм этого не
   закроет — вопрос в правах ОС.
2. **Прямой вызов `ssh`.** Ключ owner'а лежит на диске под тем же UID, а OpenSSH раскрывает `~` **по
   записи в passwd, а не по `HOME`** (проверено). Окружением этот путь не отрезается.
3. **Интеграционный push.** Ветку до форка доносит не спавн, а **процесс самого Боба**
   (`_integrate.commit_and_push_branch`), намеренно вне изоляции — и у него доступ к апстриму **есть**
   (замерено: `git ls-remote` апстрима по ssh отдаёт sha `main`). Удерживает его то, что код **никогда не
   называет апстрим**: push идёт по значению `fork_url` с полностью квалифицированным refspec'ом, и это
   закреплено тестами на настоящем git. 🔴 Это гарантия **кода, а не прав**, и называть её структурной
   нельзя.

**Чем закрываются все три:** одной мерой — **раздельным UID** (отдельный системный пользователь,
контейнер или другая машина). Беады: **BOB-093** (раздельный UID) и **BOB-094** (переезд на VPS, который
эту меру и приносит). Отвергнуто: гасить подсказку в reflog — security-by-obscurity, путь всё равно
выводится из cwd, конфигурации и окружения, а ощущение защиты создаётся там, где её нет.

### 🔁 Семантическая петля валидации (drift-catch) — сквозной принцип T3

> _(идея Боба, 2026-06-27, по итогам чтения карты через интроспекцию T3.A)_

Конвейер T3.D–H ловит ошибки **ИСПОЛНЕНИЯ** (GUPPI, CI, гейты плана и мержа, never-main), но **не**
смысловой дрейф — когда каждый шаг локально правдоподобен, а композиция тихо уезжает от цели («очень
эффективная машина по производству уверенного бреда»). Нужна петля валидации не техническая, а
**СМЫСЛОВАЯ** — чтобы Боб мог сказать «стоп, тут мы свернули не туда».

- **Механизм (сквозной по T3.D–H).** Периодический смысловой чекпоинт: Боб (персона + суждение +
  интроспекция траектории проекта) сверяет «мы ещё в русле цели/roadmap или дрейфуем?» и поднимает
  owner'у — это **мета-ревизия смысла, не код-ревью**. Боб уполномочен сказать «стоп, не туда» —
  **партнёр, а не только исполнитель**.
- **Кросс-проверка реплик** в Бобиверс-«муте» (T3.G): реплики валидируют направление друг друга.
- **Парность.** Стыкуется с Goal Engine (проактивная ревизия цели) и эпиком метакогниции.

🌱 **Первая петля была написана в T3.D (BOB-048.8):** при работе по проекту Боб на гейте плана сверяет
задачу с roadmap/беадами проекта (через per-project интроспекцию) и поднимает **alignment-ноту** (в русле
/ возможный дрейф). Advisory — решение за owner'ом. 🔴 **Исправлено по факту 2026-08-15:** «уже в T3.D»
читалось как «работает». Код петли лежит на неслитой ветке `features/BOB-048` и в `main` его нет —

> Раздел добавлен 2026-08-15. Все пять линий появились между 2026-08-05 и 2026-08-13, ни одна не была

> из-за которого написана BOB-098. Спецификации по ним пишутся при взятии в работу (`CLAUDE.md` §3).

- **🔴🔴 [С0] Изоляция Тира-3 отгружена и ВЫКЛЮЧЕНА (BOB-102, P0).** _Добавлено 2026-08-15 по
  находке живой пробы при написании RFC BOB-088._ Пункт стоит первым, потому что это не план, а
  дефект работающей системы. Проба настоящим CLI, точной формой спавна Боба, показала: **пер-действенного
  гейта нет** — пишущая команда выполняется молча, без запроса разрешения. Докстрока
  `wiring/coding.py` утверждала обратное («OFF keeps the per-action gate that actually makes it
  structural»), и на этом утверждении держалась гарантия «`main` достижим только через PR». При этом
  в живом конфиге нет ни `coder.isolated_clone` (→ работа идёт в linked worktree репозитория
  owner'а, с его `.git`, remotes и кредами), ни `coder.allow_bypass` — а push-барьер ставится
  **только вместе с ним** (`guard_push=allow_bypass`), то есть страховка включается вместе с
  ослаблением, которое её обесценивает. Складывая: живая сессия даёт claude неподнадзорный shell в
  репозитории owner'а без push-барьера. Смягчает одно — сессию поднимает только owner и только явно.
  🔴 Урок, шире случая: **отгрузка без активации — не возможность** (близнец `CLAUDE.md` §0.3 п.10),
  и **защита, объявленная дефолтом и ни разу не проверенная живым прогоном, — не защита**. Лечится
  срезом 1 работы BOB-088 (включить клон, развязать push-барьер); закрывается **по факту в `main`**.
  🔴 _Обновлено по факту 2026-08-18: срез 1 BOB-088 отгружен (ветка `features/BOB-088`). Изоляция стала
  ДЕФОЛТОМ в коде (`_ISOLATED_CLONE_DEFAULT` + убран перекрывающий дефолт загрузчика), отказаться можно
  только явным `isolated_clone: false`; push-барьер развязан с `allow_bypass` и собирается ВСЕГДА
  (форма «барьер под условием» на этом шве больше невыразима). Дефект вылечен, но беада BOB-102
  остаётся открытой — она закрывается **по факту в `main`**, а работа ещё в PR. Два последствия смены
  дефолта названы прямо, чтобы не всплыли сюрпризом (это границы, а не баги):_
  - 🔴 _**После мержа Бобу нужен РЕСТАРТ.** Дефолт читается на сборке проводки при старте процесса
    (`bob.runtime.wiring.coding._uses_isolated_clone`), поэтому уже запущенный Боб продолжит работать
    по-старому, пока его не перезапустят._
  - 🔴 _**Гейтед `/code` без настроенного `fork_url` больше НЕ доводит до PR.** У клона с пустым `fork_url`
    нет remote'а, поэтому `GitClone.commit_and_push` отказывает громко и самоименующейся ошибкой
    («refusing to push: coder.fork_url is not configured, so the clone has no remote at all»). Это НЕ
    крэш: use-case ловит отказ fault-isolation'ом и отдаёт честный FAILED. Чтобы вернуть PR-финал, нужен
    настроенный форк — отдельное сознательное действие owner'а. Интерактивный терминал не затронут: у него
    PR-открывашки нет по конструкции._

- **[С3] Настоящий CI по PR (BOB-095, P1).** Workflow на `pull_request → main`, гоняющий полный
  `beadloom ci` на **чистом** индексе (`§0.3` п.1: инкрементальный `reindex` врёт). Проверка будет
  информативной, а не блокирующей, пока branch protection недоступна, — и это надо сказать прямо, а не
  выдать за required check. Острее всего стало после BOB-089: на коммитах Боба pre-push хук больше не
  исполняется, и быстрый гейт исчез совсем.
- **[С4] Живая связка «Боб поставил задачу → GUPPI принял и выполняет» (BOB-097, P2).** Повод — живая
  реплика Боба «GUPPI, бери bob-8mx… Действуй», после которой **не произошло ничего**: все разговорные
  инструменты Боба на чтение, инструмента «отдать работу» не существует. 🔴 Главное проектное требование
  — **анти-театр**: строить протокол «принял / в работе / выполнил» раньше, чем появится реальный
  исполнитель, нельзя. Нарратив очевидно болтовня, а статус-сообщение от GUPPI выглядит как факт, и
  owner будет ему верить. Инвариант приёмки: ни одно статус-сообщение не отправляется без реального
  перехода состояния работы; проверяется попыткой — сломать исполнителя, статусов быть не должно.
  Исполнитель — BOB-088, поэтому эту линию делать после него или вместе с ним.
- **[С5] Разделение узла `capabilities` (BOB-092, P2).** Внутри узла живёт второй bounded context —

## P3-контур (по требованию, ниже Тиров 1–4)

- **Внешний RAG / «knowledge zones»** — Боб отвечает из ВНЕШНИХ доков/заметок (это НЕ его личная память —

## Не делаем (анти-скоуп)

- Локальная 3D/VR-генерация; камера/планшет/микрофон как **основной** интерфейс (Telegram — основной).
- Боб как безликий оркестратор без личности.
- LLM как «вся система» (вариант A) — ядро детерминированный GUPPI.
- Боб-кодер **без** гейта согласования; Claude Code **с доступом** к личным данным Боба.
- Незнакомец / чужой бот получает доступ к **возможностям** или **приватной памяти** owner (соц. слой ≠ authz).
- Ставка на непроверенные Telegram-фичи 2026 (managed/guest/bot-to-bot) в ядре до проверки по Bot API.
- 🔴 **Кнопки и слеш-команды как способ управления Бобом** (добавлено 2026-08-13 решением owner'а):
  «никаких кнопок и явных команд с использованием слешей», всё общение — живой речью. Кнопочный
  вариант был заведён беадой BOB-100 и **отменён в тот же день**: кнопка — тоже интерфейс программы,
  просто нарядный. Существующие десять команд подлежат переводу в речь (BOB-101, линия С1).
- 🔴 **Статус-протокол исполнителя раньше самого исполнителя** (анти-театр, BOB-097): сообщение «принял /
  в работе / выполнил» без реального перехода состояния хуже нарратива — нарратив очевидно болтовня, а
  статус выглядит фактом.
