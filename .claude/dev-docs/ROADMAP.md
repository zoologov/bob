## Видение и фокус (север, задающий приоритеты)

Bob — **личный инструмент-компаньон, а не рыночный продукт**. Массовое внедрение и хайп — явно не цель.
Приоритеты ранжируются по пользе для одного пользователя (автора) и по тому, насколько они сохраняют
**уникальность Боба** (личность + облик + вселенная), а не превращают его в «ещё один telegram-бот».

- **Личность — ядро (P0).** Без живого характера Боб не отличается от тысяч ассистентов.
- **Облик — усилитель (P1).** «Аквариум вселенной» под рукой: Боб шлёт картинки себя.
- **Bobiverse / реплики — масштаб личности (P2).** Оркестрация как часть вселенной, а не как платформа.
- **Бытовая польза (P3).** Apple-приложения, голос, n8n, RAG — по мере появления реальной нужды.

**Правило приоритизации:** каждый пункт P0/P1 должен либо строить личность, либо давать ей «тело»/«облик».
Пункты, которые лишь добавляют бытовых интеграций, осознанно понижены до P3.

## Принципы последовательности

1. **Одна сквозная нить за раз, доведённая до честного состояния, прежде чем следующая.** Главный риск —
   ёмкость одного разработчика. Не распыляться на параллельные фронты.
2. **Личность платформонезависима.** Higher Mind отделён от транспорта: за Telegram-шлюзом сегодня, за
   чем угодно завтра. Не вшивать Telegram в логику характера.
3. **Backend-centric (вариант B).** GUPPI (детерминированный код) — control plane; LLM — подключаемый
   мозг, а не операционная система. Что можно сделать кодом — делать кодом.
4. **Память переживает рестарты.** Никакой «памяти из чата»: всё значимое — в SQLite/файлах.
5. **Состояние > диалог.** Цели, вкусы, настроение — это данные в БД, а не переопределяются LLM на
   каждом цикле.
6. **Надёжные примитивы Telegram.** Строить на supergroup+Topics, rich media, стриминг-редактировании.
   Фичи 2026 (managed/guest/bot-to-bot) — проверять по актуальному Bot API, не закладываться на пересказы.
7. **Заморожено ≠ выброшено.** Железо и FLUX-облик сохранены и размораживаются по плану (см. ниже).
8. **TDD/DDD/Clean Architecture, mypy --strict, ruff, покрытие ≥80%** (как в `CLAUDE.md`).
9. **LLM — трёхслойный провайдер-агностичный router** (зафикс. 2026-06-18): Tier 0 локальный MLX
   small-model (приватно, 24/7) · Tier 1 Qwen API (тяжёлый reasoning) · Tier 2 Claude Code (кодинг).
   Личность/память по умолчанию на Tier 0; эскалация в API — только с редакцией контекста. См. VISION §7.1.

## P0 — Личность в Telegram (текстовый MVP) — ✅ SHIPPED 2026-06-19 (BOB-001 / PR #1)

> Цель среза: живой Боб с характером в текст-чате, переживающий рестарты. Без оркестрации и без картинок.
> Идёт зависимостно-упорядоченными слайсами, не параллельными фронтами. Точный DAG — в `/task-init`.

- **[P0] Telegram Gateway.** Приватная supergroup; General = чат с Бобом. Приём апдейтов (long-polling
  или webhook), отправка с **стримингом через `editMessageText`**, дедупликация апдейтов, базовые
  команды. Транспортный слой строго отделён от Higher Mind. _Источник: VISION §7._
- **[P0] GUPPI core (control plane).** Детерминированный каркас: event loop (asyncio), EventBus,
  ConfigLoader (defaults→YAML→env), graceful start/stop, единый процесс. Без LLM-логики. _VISION §5/§7._
- **[P0] LLMRouter (провайдер-агностичный) + Tier 0/1.** Маршрутизация по типу задачи поверх
  OpenAI-совместимого клиента (`base_url+model+key`). P0 задействует: **Tier 0** — локальный MLX
  small-model (Qwen3-1.7B/4B на `mlx-lm`) для монолога/классификации/сентимента; **Tier 1** — **Qwen API**
  (Qwen3.7-Plus) для тяжёлого reasoning и ответов Боба. Приватность: личность/память по умолчанию на
  Tier 0, эскалация в Tier 1 только с редакцией контекста. Tier 2 (Claude Code) — в P2. _VISION §7.1._
- **[P0] Память (без RAG/эмбеддингов).** Память ≠ RAG. На срезе P0: SQLite (структурированное
  состояние — настроение/вкусы/цели/отношения, ядро личности), эпизодический дневник по свежести
  (`ORDER BY`), recall фактов через **SQLite FTS5** (ключевые слова). Переживает рестарт,
  консолидация/дедуп. **Заложить чистый шов `MemoryRecall`**, чтобы позже заменить keyword→vector
  drop-in. FAISS/эмбеддинги — НЕ в P0 (бюджет памяти M4 + сложность); вводить при промахах
  recency+keyword (P1.5/P2). Внешний RAG над доками/заметками — P3 (knowledge zones). _Архив RFC §3.4;
  переписка §RAG._
- **[P0] Higher Mind — ядро личности.** Mood System, Taste Engine, Negotiation Engine, Inner Monologue,
  Reflection. Кормятся **текстовыми** сигналами (частота/сентимент сообщений, presence, время суток)
  вместо камеры/просодии. Влияют на тон и содержание каждого ответа. _VISION §4._
- **[P0] Genesis (текстовый).** Первый запуск = «пробуждение» в Telegram: осознание себя, генерация
  личности/настроения/вкусов/фантомных предпочтений из `bob-soul/`, запись SOUL. Без генерации
  ассетов/материализации. _Архив PRD Genesis Mode (переосмыслен)._
- **[P0] Самосознание + фантомные предпочтения.** Боб знает о книге, шутит, «помнит» кофе/закаты/книги.
  _Архив PRD._

> **SHIPPED (2026-06-19):** 23 беада, Gate зелёный, PR #1 в `main`. Сверх исходного P0 пришлось добить
> память: **recall по всему архиву переписки** (FTS5 над `episodic_log` + бэкфилл) + **извлечение
> фактов** (Tier 0) + обработка reasoning-моделей (timeout/disable_thinking/устойчивый парсинг). Урок:
> фейк-модели в тестах скрыли поведение reasoning-моделей — тестировать на реалистичных формах вывода.

## P0.5 — После P0: capability-слой, авторизация, проактивность (зафикс. 2026-06-19)

**Архитектурные решения (обсуждение 2026-06-19):**
- **Навыки = Capability/Tool-слой, GUPPI = исполнитель.** Полную SkillDomain-плагин-систему сразу НЕ
  строим (преждевременная абстракция при нуле реальных навыков). Фиксируем **стабильный шов один раз**:
  контракт `Capability` (имя/описание/JSON-схема/`async execute`/permission), `CapabilityRegistry`,
  **tool-use петля** (Боб эмитит tool-call → реестр диспатчит = «GUPPI исполняет» → результат → ответ),
  **манифест возможностей в контексте** (Боб знает, что умеет; ссылается на GUPPI в персоне). Тяжёлую
  машинерию (авто-дискавери, hot-reload, sandbox, permission-tiers, **self-creation**) — отдельным
  эпиком ближе к самораширяющемуся Бобу, **за тем же швом, без переписывания потребителей**.
- **Авторизация — до автономности.** Owner + allowlist Telegram `user_id`/`chat_id`; гейтвей отсекает
  чужих; scope по чатам (только приватная supergroup); роли owner/authorized — фундамент для Bobiverse.
- **Автономность стадиями:** A проактивный чат (heartbeat + дешёвый Tier 0 гейт «стоит ли сказать?» +
  quiet-hours/rate-limit/контроль юзера) → B Goal Engine + самонаправленная активность → C агентность
  вне чата (инструменты / Claude Code / Apple-apps под approval). Возвращает отложенную машинерию
  исходного PRD (Goal Engine, Reflection, Approval).

**Порядок:**
1. **Ближний батч (мелкие, быстро):** резилентность heartbeat-тиков (retry/backoff) · **Rich Messages
   + нативный стриминг** (Bot API 10.1, зафикс. 2026-06-19): стрим через **`sendMessageDraft`**
   (заменяет текущий хак на `editMessageText`-loop; PTB уже поддерживает) + форматирование через
   **`sendRichMessage`/`sendRichMessageDraft`** — это **структурное дерево `RichMessage`, НЕ markdown**
   (без экранирования) + конвертер **markdown→RichMessage**, вызываемое через **сырой Bot API**, пока
   PTB не поддержит 10.1; заложить **`RichBlockThinking`** под монолог/размышления Боба; НЕ использовать
   edit+rich (известный баг). · **Authz** (owner/allowlist/scope) · **Capability-шов** (контракт +
   реестр + tool-loop + манифест, forward-compatible).
2. **#5-A — проактивный чат** (ранний вкус живости).
3. **Эпик «Память Боба»** — `search_memory` (первая capability, агентный поиск по всему архиву) +
   векторный/гибридный recall (эмбеддинги за швом `MemoryRecall`) + реплей старого.
4. **#5 B/C — Автономность** (Goal Engine + агентность) + полная плагин-машинерия (sandbox/дискавери/
   self-creation) под самораширение.

## P1 — Облик возвращается (визуальное присутствие)

> Размораживаем FLUX-трек. Здесь Taste/Negotiation получают и свою «визуальную» поверхность (комната,
> внешний вид) в дополнение к влиянию на текст.

- **[P1] FLUX-навык: «Боб шлёт картинку себя».** Адаптер генерации изображения Боба под текущее
  настроение/сцену/занятие → отправка в чат. Переиспользует замороженный `bob_identity.safetensors` +
  `validate_bob.py`. _Заморожено в `godot/`; VISION §3/§6._
- **[P1] ModelManager: загрузка/выгрузка FLUX по требованию.** Tier 1 reasoning ушёл в API, поэтому
  локально тяжёлый только FLUX. FLUX (~6-19 ГБ) не уживается с dev-тулчейном на 24 ГБ → профили
  загрузки/выгрузки (как в архив RFC §1.2), Боб уведомляет о «творческом режиме». _VISION §7.1._
- **[P1] Вкусы/переговоры на визуальной поверхности.** Облик/«комната» как объект, которым Taste и
  Negotiation управляют (их исходная сильная сторона), теперь поверх Telegram-медиа. _VISION §4._
- **[P1, опц.] Стикеры/кастом-эмодзи** как «визуальный голос» настроения. _Telegram 2026 UX._

## P2 — Bobiverse / оркестрация (реплики)

> Оркестрация как часть вселенной, а не платформа. Сначала логические субагенты внутри одного бэкенда,
> только потом — отдельные сущности. Начинать после того, как личность уже живёт.

- **[P2] Реплики в темах.** `/new_agent` → реплика (Билл, Бендер…) как форк SOUL со своим
  system-prompt'ом и темой Telegram; мини-Genesis при спавне. _VISION §5._
- **[P2] GUPPI-реестр и lifecycle.** Registry реплик, состояния, TTL, локи (один активный запрос в
  сессию), watchdog, восстановление после рестарта. _Переписка вариант B._
- **[P2] Replicative drift.** Дрейф характера копий; поколение/глубина форка. _VISION §5._
- **[P2] Мооты.** Координационная тема: Prime сводит выводы реплик. _VISION §5._
- **[P2] Claude Code как навык реплики-кодера.** Bridge Telegram-тема ↔ CLI-сессия, очередь, resume,
  rate-limit. Опциональный исполнитель с fallback. _Архив RFC §4.2; переписка._

- **Железо:** OBSBOT, ReSpeaker, Android-планшет, ADB, реалтайм Godot-рендерер. Док — `archive/` (PRD/RFC).
- **Облик (FLUX):** ядро сохранено в `godot/` (адаптер `bob_identity.safetensors` 93M, датасет,
  `validate_bob.py`, `style_guide.yaml`). **~30 ГБ промежуточных чекпойнтов `bob_identity_training/` —
  кандидат на удаление** (регенерируемы; финальный адаптер уже извлечён).

- **3D/VR:** оставлено окончательно (невозможно локально на Apple Silicon).

## Не делаем (анти-скоуп)

- Локальная генерация 3D-сцен / VR.
- Камера-гимбал, планшет и микрофонный массив как **основной** интерфейс (Telegram — основной).
- Боб как безликий оркестратор агентов без личности.
- Ставка на непроверенные Telegram-фичи 2026 в ядре архитектуры (managed/guest/bot-to-bot) до проверки
  по актуальному Bot API.
- LLM как «вся система» (вариант A); ядро — детерминированный бэкенд (GUPPI).
